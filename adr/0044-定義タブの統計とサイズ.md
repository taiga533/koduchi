# ADR 0044: 定義タブの見出しに表の統計とサイズを出す

- ステータス: 承認
- 日付: 2026-09-28

## 状況

issue #66 の要望は 3 つある。

> 表を開く前に「全件 `SELECT` してよい大きさか」「統計が古くて実行計画が狂っていないか」を知りたい。あとコメントも見れないのが地味に困る。
>
> コメントをカラムの型情報より右に出す（はみ出し注意）

定義タブ（[[0019-テーブル定義ビューとddlの取得]]・[[0022-テーブル定義タブ]]）は列・制約・索引・DDL を出すが、表の大きさも統計も出していない。コメントは [[0033-定義タブのコメント表示]] で出すようになった。列のコメントは列の内訳の 5 つめの欄（`#` / 列 / 型 / NULL の右）にあり、型より右という位置は既に満たしている。

決めるべきことは 5 つある。

1. 統計とサイズを `object_definition` に相乗りさせるか、別のコマンドにするか
2. 他人の表のセグメントサイズをどう測るか。測れないことをどう出すか
3. パーティション表・索引構成表・LOB・一時表・クラスタ化表・外部表・ネストした表・ビューをどう扱うか
4. `NUM_ROWS` を今の行数と読ませない表記
5. 列のコメントの「はみ出し」をどう扱うか

Oracle 側の事情を確かめた（23ai Free で実測）。

- **`ALL_SEGMENTS` は存在しない。** 他人の表のセグメントを読めるのは `DBA_SEGMENTS` だけで、`SELECT_CATALOG_ROLE` などを要する。自分の表なら `USER_SEGMENTS` が権限なしで読める。
- `ALL_TABLES.NUM_ROWS` / `LAST_ANALYZED` と `ALL_TAB_STATISTICS.STALE_STATS` は PUBLIC の辞書ビューであり、表が見えれば読める。統計を採っていない表では `NULL` になる。
- `ALL_TAB_STATISTICS` はパーティションの行も持つ。表全体の行は `OBJECT_TYPE = 'TABLE'` の 1 行である。ただし一時表でセッション統計を採ると、`SCOPE` が `SHARED` と `SESSION` の 2 行になる。
- パーティション表はセグメントをパーティションの数だけ持つ（`TABLE PARTITION`）。
- 索引構成表は表のセグメントを持たない。行の本体は主キーの索引（`ALL_INDEXES.INDEX_TYPE` が `IOT - TOP`）のセグメントにある。
- **LOB の索引（`SYS_IL…`）は `ALL_INDEXES` に出ない。** `ALL_LOBS.INDEX_NAME` から引く必要がある。
- 遅延セグメント作成（既定で有効）のため、行を 1 度も入れていない表はセグメントを持たない。
- 一時表は永続のセグメントを持たない。
- **クラスタ化表**（`ALL_TABLES.CLUSTER_NAME` が入る）は表のセグメントを持たない。行はクラスタのセグメントに、同じクラスタの他の表と一緒に入る。**外部表**（`ALL_TABLES.EXTERNAL` が `YES`）は行がデータベースの外のファイルにあり、セグメントを持たない。どちらも行があってもセグメントは 0 個に見える。
- overflow 付きの索引構成表は、主キーの索引に入らない列を `SYS_IOT_OVER_*` という**表と別の名前**のセグメント（`ALL_TABLES` で `IOT_TYPE = 'IOT_OVERFLOW'`、`IOT_NAME` が元の表）に置く。ネストした表は入れ子の行を格納表（`ALL_NESTED_TABLES`）の、区分 `NESTED TABLE` のセグメントに置く。
- 表と索引は名前空間が別であり、表と同じ名前の索引がありうる。

## 決定

### 統計とサイズは別のコマンド `object_stats` で取り、開いた時点で定義と並べて走らせる

`object_definition` に相乗りさせない。[[0019-テーブル定義ビューとddlの取得]] が `object_ddl` を分けた理由は「GET_DDL の権限が無いというだけで列も制約も見られなくなってはいけない」だった。**セグメントサイズにも同じ理由が当てはまる。**他人の表では `DBA_SEGMENTS` を要し、しかも `DBA_SEGMENTS` は大きなデータベースで遅いことで知られる。[[0033-定義タブのコメント表示]] がコメントを相乗りさせたのは「落ちうるものが増えない」からであり、ここでは増える。

ただし DDL と違い、**開いた時点で取る。**見出しは内訳を切り替えなくても常に見えており、DDL のように「開くまで要らない」ものではない。定義の往復を待たずに並べて走らせ、ストアでは状態（`stats` / `statsStatus` / `statsError`）を定義と別に持つ。統計が失敗しても見出しに一言が出るだけで、内訳はそのまま見られる。定義が失敗しても統計は出る。

### セグメントの権限不足はエラーではなく値で返す

`SegmentSize` は 5 つの形を持つ。

| 形                 | 意味                                        | 画面               |
| ------------------ | ------------------------------------------- | ------------------ |
| `measured`         | 測れた。表・索引・LOB の 3 つとセグメント数 | `表 64 KB · 索引 128 KB` |
| `permissionDenied` | `DBA_SEGMENTS` を読む権限が無い             | 権限が無く測れません |
| `temporary`        | 一時表                                      | 一時表のため持ちません |
| `external`         | 外部表                                      | 外部表のため持ちません |
| `clustered`        | クラスタ化表。クラスタの名前を添える        | クラスタ C に含まれ、測れません |

**権限不足を 0 バイトにしない。**[[0017-セッションとロックの確認]] の「見えない」と「居ない」を混同させないのと同じである。そしてこれを**コマンド全体の失敗にもしない。**統計（`ALL_TABLES`）は権限なしで読めており、大きさが測れないというだけで行数まで隠す理由が無い。

権限不足の判定は `errors.rs` の `map_permission_error` を通す（[[0030-接続が切れていることの気付き方と繋ぎ直し]]）。接続断は権限不足より先に見分けられ、エラーのまま返る。**権限不足以外の失敗は握り潰さない。**

### 測っても表の大きさにならない表は、測る前に見分ける

一時表・外部表・クラスタ化表は、セグメントを測れば 0 個になる。そのまま `measured` で返すと、行の入っている表に「セグメントが無い」と言うことになる。**統計の問い合わせで `TEMPORARY` / `EXTERNAL` / `CLUSTER_NAME` を一緒に取り、`unmeasurable_size`（純粋な関数）で見分けて、セグメントの問い合わせにも行かない。**

クラスタ化表を「クラスタ全体の大きさ」で代わりに出すことはしない。同じクラスタの他の表のぶんが混ざり、この表の大きさとしては嘘になる。「測れない」と言い、どのクラスタにあるかを添える。

`measured` でもセグメント数が 0 のときは「未割り当て」と出す。上の 3 つを除いた後で 0 個になるのは、遅延セグメント作成でまだセグメントが作られていない表か、`TRUNCATE … DROP ALL STORAGE` で解放された表である。**注記で行の有無は言わない**（後者は行が入ったことがある）。「0 B」と書くより事実に近い。

### 自分の表は `USER_SEGMENTS`、他人の表は `DBA_SEGMENTS` で測る

判定は `segment_view`（`db/stats.rs` の純粋な関数）で、所有者と接続している利用者（`USER`）を比べる。`USER` は統計の問い合わせに同じ 1 本で混ぜて返させ、往復を足さない。

**自分の表では権限があっても `USER_SEGMENTS` を使う。**権限の有無で同じ表の数字が変わらないようにするためである。割り切りとして、自分の表に**他人のスキーマで**張られた索引は数えない（稀であり、数えるには権限の要るビューを引くことになる）。

### 大きさは表・索引・LOB の 3 つに分けて足し上げる

問い合わせは 3 つを `union all` で繋ぎ、区分を付けて返す。足し上げは `summarize_segments`（純粋な関数）が行う。

- **表**: 表と同じ名前で、`SEGMENT_TYPE` が `TABLE` / `TABLE PARTITION` / `TABLE SUBPARTITION` のもの。種別でも絞るのは、表と同じ名前の索引がありうるためである。パーティションは足し上げる。**表と別の名前で行を持つセグメントも表に数える。**索引構成表の overflow（`SYS_IOT_OVER_*`）と、ネストした表の格納表（区分 `NESTED TABLE`）である。取りこぼすと大きさが小さく出る。
- **索引**: `ALL_INDEXES` の索引のセグメント。**索引構成表の主キーの索引（`IOT - TOP`）は表に数える。**行の本体そのものであり、索引に数えると「表 0 B」になって「全件 SELECT してよいか」に誤って答える。
- **LOB**: `ALL_LOBS` の LOB セグメントと LOB の索引。LOB の索引は `ALL_INDEXES` に出ないため `ALL_LOBS.INDEX_NAME` から引き、索引の側では `INDEX_TYPE <> 'LOB'` で除いて二重に数えない。

**割り切り**: overflow と格納表に付いた索引と LOB は数えない。格納表がさらに入れ子を持つ場合も 1 段目までしか辿らない。どちらも稀であり、辿るには問い合わせが再帰になる。この割り切りで出る誤りは「小さめに出る」方向だけで、「測れないものを測れたと言う」ことはない。

分けるのは、答えたい問いが違うからである。全件 `SELECT` の重さは表と LOB で決まり、索引は効かない。合計 1 つだけを出すと、索引の大きな表を重く見せる。

### 表とマテリアライズドビュー以外では問い合わせにも行かない

判定は `ObjectKind::has_table_details()`（制約と索引を引く種別）をそのまま使う。**`has_stats()` は作らない。**統計とセグメントを持つのは表とマテリアライズドビュー（の実体の表）であり、集合が完全に一致する（[[0033-定義タブのコメント表示]] が `has_comments()` を作らなかったのと同じ理由）。ビューやシーケンスでは Rust 側が往復せずに `None` を返し、画面は何も出さない。種別の集合をフロントエンドに写さずに済む。

### `NUM_ROWS` は「行数（統計時点）」「約 1,234 行」と書く

見出しに**統計時点**、値に**約**を添える。そのすぐ右に統計を採った日時と経った日数を並べる（`2026-09-08 22:00（20 日前）`）。`NUM_ROWS` は採った後に入った行も消えた行も数えておらず、標本から推し量った値であることも多い。補足（「今の行数ではありません」）は `title` に回し、値だけで取り違えない形にする。

統計が無い表は行数を「不明」、統計を「未取得」と書く。**0 と書かない。**

古さ（`STALE_STATS`）は `ALL_TAB_STATISTICS` の **`SCOPE = 'SHARED'` の行**から取る。行数を読む `ALL_TABLES` が持つのは共有の統計であり、それと揃える。絞らないと、一時表でセッション統計を採ったときに 2 行が当たり、どちらを拾うかが約束されない。

経った日数は Oracle の `SYSDATE - LAST_ANALYZED` で引く。`LAST_ANALYZED` はデータベースの時計で書かれており、手元の時計と引くとタイムゾーンの差が混ざる。

### 統計が古いかはデータベースの `STALE_STATS` だけで決める

`YES` のときだけ「古い」の印を警告の色で付ける。**日数のしきい値は持たない。**更新の少ない表は 1 年前の統計でも正しく、データベースは変更の割合（既定 10%）で判定している。実行計画が狂うかに近いのはそちらである。

### 並びは行数 → 統計 → サイズ → 作り

「全件 SELECT してよいか」に答える行数を先頭に、その値がいつのものかをすぐ隣に置く。パーティション表と索引構成表は最後に「作り」として添える。表のコメント（[[0033-定義タブのコメント表示]]）の下に 1 行で並べ、狭ければ折り返す。

**コピーには含めない。**見出しであって内訳の中身ではない（表のコメントと同じ扱い）。

### 列のコメントの欄の位置は変えず、列名を折り返さない

「型より右」は [[0033-定義タブのコメント表示]] で既に満たしている。欄の順（`#` / 列 / 型 / NULL / コメント）は変えない。長さの揃わないコメントを最後の欄に置けば、残りの幅をまるごと使って折り返せる。途中の欄にすると、短い `NULL` の欄が行ごとに押される。

「はみ出し」の原因は**列名の押し潰し**と見た。表の幅（`table-layout: auto`）は各欄の中身の長さに応じて配られる。列名の欄は `break-all` で最小幅がほぼ 1 文字だったため、長いコメントがあると列名の欄が細くされ、`SHIPMENT_ID` が途中で折れうる。列名は `whitespace-nowrap` にし、コメントの欄に最低幅（200px）を置く。**最低幅は `<td>` ではなく中の `<div>` に付ける。**`<td>` の `min-width` は CSS 2.1 で未定義であり、中身の箱の最低幅なら表の自動配置が最小幅として必ず汲む。狭い窓では表ごと横へスクロールする（本文の器は既に `overflow-auto` である）。

欄の順を変えないため、コピー（`definitionCopy.ts`）の列順にも手は要らない。

スキーマツリーにコメントを出す話は別の変更で扱う（この ADR の範囲外）。

## 理由

- **別のコマンドにした**のが最も効いている判断である。セグメントは権限と重さの両方で落ちうる。相乗りさせれば、`DBA_SEGMENTS` の遅さがそのまま定義タブの開く遅さになり、権限の無い接続では列も見られなくなる。
- **権限不足を値にした**のは、統計と大きさの権限が違うからである。エラーにすれば、読めている行数まで道連れになる。
- **自分の表で `USER_SEGMENTS` を使う**のは、権限の要らない道があるなら使うべきであり、しかも数字が権限で変わらないからである。
- **表・索引・LOB に分けた**のは、「全件 SELECT してよいか」に答えられるのが表と LOB の大きさだけだからである。

## 却下した案

**統計とサイズを `object_definition` に相乗りさせる**: 往復の数え方は単純になる。しかし `DBA_SEGMENTS` の遅さと権限不足が定義タブ全体へ波及する。[[0019-テーブル定義ビューとddlの取得]] が GET_DDL を分けた理由がそのまま当てはまる。

**統計だけ相乗りさせ、サイズだけ別にする**: 統計は PUBLIC のビューで落ちない。しかし見出しの 1 行のために状態を 2 つに割ることになり、「行数は出たがサイズはまだ」の中途半端な見出しが生まれる。1 本のコマンドの中で権限不足を値にすれば、統計が道連れになることもない。

**DDL と同じく、開いたときではなく求められたときに取る**: 見出しは常に見えており、「開くまで要らない」ものではない。

**`DBA_SEGMENTS` を先に試し、権限で落ちたら `USER_SEGMENTS` へ退く**: 権限があれば他人のスキーマの索引まで数えられる。しかし同じ自分の表の数字が権限の有無で変わり、権限の無い接続では往復が 2 本になる。

**`ALL_TABLES.BLOCKS` × ブロックサイズで推し量る**: 権限なしで他人の表も測れる。しかし `BLOCKS` も統計時点の値であり、統計の無い表では出ない。ブロックサイズを知るにも `V$PARAMETER` か `DBA_TABLESPACES` の権限が要る。索引と LOB も測れない。「測れない」と正直に言うほうがよい。

**大きさを合計 1 つで出す**: 1 語で済む。しかし索引の大きな表を重く見せ、LOB が本体の何倍もある表を軽く見せる。

**権限が無いときは空欄にする**: 「0」と取り違えはしないが、「読み込み中」や「無い」と見分けが付かない。空欄は理由を言わない。

**統計の日数にしきい値（30 日など）を置いて古いと言う**: 分かりやすいが、更新の無い表を誤って責め、大量に更新された昨日の統計を見逃す。データベースの判定を借りる。

**`NUM_ROWS` をそのまま「1,234 行」と書き、注記を `title` に置く**: 画面が静かになる。しかし `title` はマウスを止めないと出ない。今の行数と読ませない表記は値の側に要る。

**列のコメントの欄を型のすぐ右（NULL の左）へ動かす**: 「型より右」を字義どおりに強める。しかし伸び縮みする欄が途中に来て、短い `NULL` の欄が行ごとに押される。はみ出しの原因は欄の位置ではなく列名の折り返しである。

**列名も折り返させたまま、コメントに `…` を付けて省く**: 桁は揃う。しかし [[0033-定義タブのコメント表示]] が退けた「読みにくるために開いた欄が読めなくなる」に戻る。

## 結果

- Rust に `object_stats` コマンドと `Driver::object_stats` が増えた。型は `db/stats.rs`（`ObjectStats` / `SegmentSize` と純粋な関数 `segment_view` / `summarize_segments` / `parse_stale`）、問い合わせは `db/oracle/stats.rs` にある。
- フロントエンドは `definition` ストアが開いた時点で定義と並べて取り、見出しの 1 行（`StatsLine`）に出す。文言は `src/components/definition/definitionStats.ts` の純粋な関数が作る。
- 開発用データベースに `dev/oracle/initdb/009_table_stats.sql` を足した。統計を採ってロックした表（索引と LOB 付き）・統計の無い表・パーティション表・索引構成表・一時表・クラスタ化表・外部表・overflow 付きの索引構成表・ネストした表と、`SELECT_CATALOG_ROLE` を持たない利用者 `koduchi_stats_viewer` を揃えてある。**統計はロックしてあり、自動統計収集で値が動かない。**ネストした表の格納表に Oracle が作る `SYS_FK…` の索引（`GENERATED = N`）は、スキーマツリーの見本（ADR 0014）と食い違うため落としてある。既にボリュームを持っている開発者はこのスクリプトを手で流す。
- 定義タブを開くたびの往復が増える。表では統計の 1 本とセグメントの 1 本、それ以外の種別では 0 本である。
- PostgreSQL を足すときは `pg_class.reltuples` / `pg_stat_user_tables.last_analyze` / `pg_total_relation_size()` が同じ形を満たす。権限の分かれ方は Oracle と違い、`SegmentSize` の `permissionDenied` を使わずに済む見込みである。
