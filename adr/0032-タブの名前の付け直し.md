# ADR 0032: タブの名前の付け直し

- ステータス: 承認
- 日付: 2026-09-11

## 状況

[Issue #38] は「タブのリネームができない。タブ名でダブルクリックでリネームできるようにしたい」である。作る前に、**今のタブ名が何から出ているか**を読んだ。出どころは 3 つしかない。

| 出どころ           | 名前                 | 付ける場所                      |
| ------------------ | -------------------- | ------------------------------- |
| `⌘T` / 新しいタブ  | `無題-1.sql` の連番  | `tab.ts` の `createTab`         |
| `⌘O` / `⌘S`        | ファイル名           | `tab.ts` の `openFile` / `markSaved` |
| 定義タブ           | オブジェクト名       | `tabKinds.ts` の `definitionTabName`（[[0022-テーブル定義タブ]]） |

**取りこぼしているのはここである。**小槌でタブが増える道は上の 3 つだけではない。

- 保存済みクエリの一覧から「使う」を押す（[[0018-保存済みクエリとコマンドパレット]]）
- 履歴から SQL を引く（[[0005-クエリ履歴とセッション復元のsqlite]]）
- ツリーの右クリックで `SELECT` を開く（[[0020-スキーマツリーからの操作]]）
- コマンドパレットから保存済みクエリを選ぶ

**これらはどれも名前を持っているのに、タブへは SQL だけが入り、名前は捨てられる。**`App.tsx` の `useHistorySql` / `openSqlInNewTab` は `updateContent` しか呼んでいない。

そして小槌は**データベースのクライアントである**。`.sql` ファイルを開いて回る道具ではない。日常の使い方は「繋いで、打って、結果を見て、また打つ」であり、**ファイルに触らないまま 5 枚も 6 枚もタブが開く**。その 5 枚は全部 `無題-1.sql` … `無題-6.sql` である。並べ替えられる（[[0023-タブの並べ替えと閉じる]]）ようにはなったが、**並べ替えても見分けは付かない。**

利用者が「リネームしたい」と言っているのは、**タブに名前を付ける道が「ファイルへ保存する」しか無い**からである。

決めるべきことは 7 つある。

1. ダブルクリックと、[[0023-タブの並べ替えと閉じる]] が入れた掴みが食い合わないか
2. 名前をどこに持つか。付け直しを取り消せるべきか
3. セッションに保存するか。保存するなら古いファイルをどうするか
4. 定義タブの名前も変えられるべきか
5. 編集中の作法（空文字・IME・`esc`・焦点が外れたとき・`⌘W`・幅）
6. キーボードからの入口は要るか
7. 保存済クエリから開いたタブの名前を変えたとき、保存済みクエリの名前も変わるべきか

## 決定

### ダブルクリックで編集に入る。掴みとは初めから食い合っていない

**しきい値が既にあるからである。**[[0023-タブの並べ替えと閉じる]] は「4px 動かすまでは掴んだと見なさず、ただの押し下げとして扱う」と決め、`tabOrder.ts` の `DRAG_THRESHOLD` と `DragState.held` がそれを持っている。ダブルクリックは**動かない打鍵**なので `held` に一度も届かない。`pointerdown` で `drag.current` が置かれ、`pointerup` で捨てられるだけである。その裏で `dblclick` は普通に発火する。

`CLAUDE.md` はスキーマツリーと結果テーブルについて「`event.detail` を見て打ち消す細工は入れない」と決めているが、**ここは打ち消しの話ですらない。**打ち消すべきものが起きていない。`onDoubleClick` を 1 つ足すだけで済む。

**しきい値を動かさない。**4px は掴みの手触りを決める値であり、付け直しの都合で触る理由が無い。

塞いだ穴は 2 つある。どちらも [[0023-タブの並べ替えと閉じる]] が置いた `data-tab-action` の仕組みをそのまま使う。

- **閉じるボタンの上で始まったダブルクリックでは編集に入らない。**押した場所が `[data-tab-action]` の中かを見るだけで、掴みの判定と同じ形である。
- **編集中のタブは掴まない。**入力欄の中で文字を選ぼうと押したまま動かすと、しきい値を越えて並びが動いてしまう。入力欄そのものにも `data-tab-action="rename"` を付けてあるが、**関所は「そのタブが編集中か」の 1 つで足りる**（タブの余白から始めた動きも止まる）。

### 名前は `customName` として別に持つ。自動の名前は残す

`SqlTab` に `customName: string | null` を足す。**`name` は書き換えない。**画面に出すのは `tabNaming.ts` の `tabDisplayName(tab)` が選ぶ（`customName ?? name`）。

**2 つを 1 つの欄に混ぜないのは、付け直しを取り消せるようにするためである。**混ぜてしまうと元の名前がどこにも残らず、「自動の名前へ戻す」ための入口を別に作ることになる。分けてあれば**空の名前を確定したときに `customName` を捨てるだけ**で戻る。取り消しのボタンも、右クリックのメニューも要らない。

**空白だけの名前も同じく戻す。**空白だけのタブ名は名前ではない。判定は `normalizeTabName` という純粋な関数 1 つである。

**ファイルへ保存し直しても利用者の名前は消えない。**`markSaved` は `name`（自動の名前）だけを書き換える。「明示的に付けた名前のほうが強い」という 1 つの決まりで済み、保存のたびに名前が飛ぶ驚きが無い。隠れた自動の名前は器の `title` に `売上集計（users.sql）` の形で出るので、**どのファイルだったのかは辿れる。**

タブの名前を既定値として使っている場所は、すべて表示名を通す（`tabNaming.ts` の `tabBaseName` / `tabFileName`）。

| 場所                                | 使う名前                                        |
| ----------------------------------- | ----------------------------------------------- |
| `⇧⌘S` の保存済みクエリの名前        | 表示名から `.sql` を落としたもの                |
| `⌥⌘S` の CSV のファイル名           | 同上 + `.csv`                                    |
| `⌘S` の保存ダイアログの既定         | 表示名 + `.sql`（パスの区切りだけ落とす）        |
| 閉じるときの確認・実行中の見出し    | 表示名                                           |

名前を付けたタブから書き出した CSV が `無題-3.csv` になるのでは、付けた意味が無い。

### 保存済みクエリの名前は変わらない

**タブの付け直しは保存済みクエリへ書き戻さない。**理由は 3 つある。

1. **持ち物が違う。**保存済みクエリは `history.sqlite3` に置かれた**全接続を横断する記録**である（[[0018-保存済みクエリとコマンドパレット]]）。タブは**今そのウィンドウで開いている作業面**である。同じ保存済みクエリを 2 枚のタブへ引き出して別々に付け直したら、記録はどちらの名前になるのか答えが無い。
2. **取り返しが付かない。**タブの付け直しは軽い操作で、その場の目印のために気軽に打つ。そこから記録が書き換わると、**閉じたあとで気づいても戻せない。**小槌には取り消しが無い。
3. **既に入口がある。**保存済みクエリの名前は一覧の鉛筆で変えられる（`SavedQueryList.tsx`）。同じことをする道を 2 つ持つ理由が無い。

**そもそもタブは保存済みクエリを覚えていない。**「使う」は SQL を `updateContent` で流し込むだけで、どの記録から来たかは残らない。書き戻すにはその紐付けから作ることになり、上の 3 つに照らして作るべきではない。

### セッションに保存する。列は無ければ足す

**付けた名前が再起動で消えるなら、付ける値打ちが無い。**`session_tab` に `custom_name text` を足す。

足し方は `history/mod.rs` が既に持っている作法にそのまま乗る。`migrate_session_state` は「`create table if not exists` は既にあるテーブルへ列を足さない」ことへの手当てとして、`pragma_table_info` で今ある列を読み、無いものだけ `alter table … add column` する形だった。**これを `add_missing_columns(connection, table, columns)` に一般化して、`session_state` と `session_tab` の両方から呼ぶ。**表が 2 つになったので関数のほうを表に依らない形へ広げたのであって、新しい作法を持ち込んではいない。

`SessionTab.custom_name` には `#[serde(default)]` を付ける（`CLAUDE.md` の決まり）。**列が無い古い `history.sqlite3` も、項目が無い古い JSON も、どちらも `None` で読める。**

`position` のときと違い列が 1 つ増えるので、**「古いファイルをそのまま開ける」ことをテストで見張る**（`付け直した名前の列が無い古いファイルでも開ける`）。

### 定義タブの名前は変えられない

ダブルクリックしても `F2` を押しても**何も起きない**。判定は `tabNaming.ts` の `canRenameTab` 1 つである。

**定義タブの名前はオブジェクトの名前そのものである**（[[0022-テーブル定義タブ]]）。`SHIPMENTS` の定義タブを `出荷` と名付けられると、タブ帯から「どのオブジェクトの定義か」が読めなくなる。定義タブは**読むだけの画面**であり、内容は `target` が決めている。名前と内容がずれる余地を作る意味が無い。

加えて**定義タブはセッションに保存しない**（[[0022-テーブル定義タブ]]）。付けた名前は再起動で必ず消える。保存する道を開くと、今度は「接続を復元しないのに定義タブだけ復元するのか」という別の決定を蒸し返すことになる。

**何も起きないことに手当ては足さない。**今までも定義タブのダブルクリックでは何も起きていなかった。断りのメッセージを出すのは、押した人より押さない人のほうがずっと多い操作に対して重い。

### 編集中の作法

- **`⏎` で確定、`esc` で取り消す。**
- **焦点が外れたら確定する。**打ち込んだ文字を、うっかり別の場所を押しただけで捨てるのは失うものが大きい。取り消したいときは `esc` がその場にある。確定を 2 度走らせない（`⏎` で確定すると、外れる焦点が `blur` も呼ぶ）ための札を 1 つ持つ。
- **変換中の打鍵は何も起こさない**（[[0025-入力欄における変換中の打鍵]]）。ハンドラの先頭で `isComposingKey(event)` を見る。**これは日本語で名前を付ける欄である。**「うりあげ」を変換確定した `⏎` で名前が確定してしまうのは、ADR 0025 が `SavedQueryList` で直したのとまったく同じ穴である。`<form>` にはしていないので、関所はハンドラの先頭 1 か所で足りる。ADR 0025 の監査の表に 2 行足した。
- **編集中はタブ帯の打鍵を一切効かせない。**入力欄はタブの器の**中**に描かれるため、打った打鍵はそのまま器の `keydown` へ上がる。**macOS では `⌥←` / `⌥→` は入力欄の単語単位のカーソル移動である。**名前の途中で単語の頭へ戻ろうとした `⌥←` で、カーソルは動かず**タブが左隣と入れ替わる**のでは話にならない。関所は器の `onKeyDown` の先頭に置き、`onPointerDown` の `editing` の関所と**1 対 1 で並べる**。掴む側だけ塞いで打鍵側を忘れると片肺になる。
- **編集中の `⌘W` はタブを閉じる。**`App.tsx` の `keydown` は `⌘` を必須にしており、変換とも食い合わない（[[0025-入力欄における変換中の打鍵]]）。閉じれば付け直しも一緒に消えるが、**閉じたタブに名前だけ残しても置き場所が無い。**判定を足さない。
- **タブは編集中も広がらない。**入力欄は名前の場所にそのまま重ね、`●` 印も閉じるボタンも出したままにする。`tabSizing.ts` が数えている固定部分の内訳は 1 つも変わらないので、**`TAB_MIN_WIDTH` はそのままでよい**。縮みきったタブでは入力欄も `TAB_NAME_MIN_WIDTH`（25px）まで縮むが、そこは元から名前が `…` で省かれている幅であり、打っている文字は末尾が見える。**幅を広げて隣を押しのけるほうが、掴んでいる位置と並びをずらすぶん悪い。**

### `F2` を足す。他のキーは足さない

タブ帯の中でしか意味を持たないため、`⌥←` / `⌥→`（[[0023-タブの並べ替えと閉じる]]）と同じく `TabBar` の `keydown` に置く（`CLAUDE.md` の「キーバインドの置き場所」）。

`F2` は**名前を変えるキーとしてどの環境でも通っている**。**修飾キーが 1 つでも付いていたら効かせない**（`⇧F2` も含む）。`⌥←` / `⌥→` の側が修飾を厳しく見ているのに `F2` だけ緩いと、修飾の付いた打鍵が何になるかの読み方が 2 通りになる。修飾キーを伴わないため [[0025-入力欄における変換中の打鍵]] の決まりに従って先頭で変換中を見るが、`F2` は文字を生まないキーなので実害はない。それでも見るのは、**「修飾の付かない打鍵を扱うハンドラは必ず見る」ほうが守りやすい**からである（ADR 0025 が `ConnectionPicker` の `<form>` に関所を置いたのと同じ理由）。

**`⌘` 側には足さない。**`⌘T` / `⌘W` / `⌘K` / `⌘O` / `⌘S` は埋まっており、`⌘I` は予約済みである（[[0018-保存済みクエリとコマンドパレット]]）。**コマンドパレットにも足さない。**パレットは「今どのタブか」を選ぶ前に開くものであり、対象の曖昧な操作を並べる場所ではない。

## 理由

- **「リネームできない」の正体は「タブに名前を付ける道がファイル保存しか無い」ことである。**小槌はファイルを開いて回る道具ではないので、その道はほとんどの利用者が通らない。付け直しはその穴を最も小さく塞ぐ。
- **掴みとの両立に何も足さなかった**のは、[[0023-タブの並べ替えと閉じる]] のしきい値が既にその仕事をしていたからである。**まず読んでから作った。**打ち消しの細工を入れていたら、4px のしきい値と二重に効く判定が並ぶところだった。
- **自動の名前と利用者の名前を分けた**のは、取り消しの入口を作らずに済ませるためである。空の名前が「戻す」になるのは、分けてあるからこそ成り立つ。
- **保存済みクエリへ書き戻さない**のは、軽い操作から取り返しの付かない書き換えが起きてはならないからである。
- **判定を純粋な関数へ寄せた**のは、`closing.ts` / `tabOrder.ts` / `definitionSearch.ts` と同じ理由である。名前の決め方（どちらを出すか・空をどう扱うか・ファイル名にどう直すか）は描画抜きで確かめられる。

## 却下した案

**保存済みクエリや履歴からタブを開いたとき、その名前をタブへ自動で乗せる**: 取りこぼしの正面から見えるが、実際には筋が悪い。`useHistorySql` は**今開いているタブの内容を差し替える**作りであり（新しいタブを開くのは定義タブを選んでいるときだけ）、名前まで乗せると**利用者が付けた名前を勝手に消す**ことになる。履歴の項目にそもそも名前が無いという穴も残る。付け直しが入ったあとなら重ねられる決定であり、入れるならそのときに「新しいタブへ開くのか」から決め直せばよい。

**`name` を直接書き換える（`customName` を持たない）**: 欄が 1 つ増えないぶん軽いが、**元の名前が消える。**自動の名前へ戻す道を別に作るか、戻れないままにするかの二択になる。`markSaved` がファイル名で上書きする筋も残り、「保存したら付けた名前が飛ぶ」挙動になる。

**名前を変えるダイアログを出す**（`SaveQueryDialog` と同じ形）: 幅の心配が無くなり、入力欄も広く取れる。しかし利用者が求めたのは**タブ名でダブルクリックしてその場で直す**ことである。`SavedQueryList` も「そのためだけにダイアログを増やすほどの操作ではない」として行の中で直す形を採っており（[[0018-保存済みクエリとコマンドパレット]]）、揃えるべきはそちらである。

**右クリックのメニューから「名前を変える」を出す**: スキーマツリー（[[0020-スキーマツリーからの操作]]）と揃うが、タブ帯にはまだ右クリックのメニューが無い。1 項目のためにメニューの仕組みを丸ごと持ち込むことになり、持ち込めば次は「閉じる」「他を閉じる」「右側を閉じる」をどうするかが付いてくる。**入口を増やすのではなく、メニューを作るかどうかは別に決める。**

**掴みのしきい値を上げる / `event.detail` で 2 回目の押し下げを打ち消す**: どちらも要らなかった。4px のしきい値が既に効いており、ダブルクリックは動かないので掴みは成立しない。`CLAUDE.md` が結果テーブルとスキーマツリーで断っている細工を、必要も無いのに持ち込むところだった。

**焦点が外れたら取り消す**: 誤って確定してしまう事故は防げるが、**打ち込んだ文字が消える**という失い方のほうが痛い。名前は数文字〜十数文字で、打ち直す手間は「押した場所を戻す」手間より大きい。`esc` という取り消しの道が同じ場所にある。

**編集中は `⌘W` を効かなくする**: 付け直しの途中でタブが消える驚きは無くなるが、`App.tsx` の `keydown` に「タブ帯が編集中か」を見せることになる。`App.tsx` は 4 本の枝が同時に触る場所であり、タブ帯の内側の状態をそこへ漏らしたくない。**閉じたタブに名前だけ残しても置き場所が無い**ため、得るものも無い。

**編集中はタブを広げて入力欄を確保する**: 打っている文字は読みやすくなるが、**隣のタブが押しのけられる**。縮みきって帯がスクロールしている状態（[[0023-タブの並べ替えと閉じる]] の 3 段目）では、広げた時点で帯ごと送られて指の下のタブが動く。名前は `title` で読めるという [[0023-タブの並べ替えと閉じる]] の答えがここでも効く。

**定義タブにも名前を付けられるようにする**: タブ帯の扱いが 1 つに揃うが、名前と中身がずれる。しかも定義タブはセッションに保存しない（[[0022-テーブル定義タブ]]）ので、付けた名前は再起動で必ず消える。**「保存されない名前を付けられる」ほうが、「付けられない」より分かりにくい。**

**タブ名に色や印を付けられるようにする**: 見分けという目的には効くが、接続の色分け（[[0015-接続の色分けとグループ分け]]）と意味が重なる。あちらは「今どの接続か」を色で示しており、タブにも色が載ると 2 つの色の意味を読み分けることになる。

## 結果

- `src/components/editor/tabNaming.ts` が増えた。`normalizeTabName` / `tabDisplayName` / `tabTitle` / `canRenameTab` / `tabBaseName` / `tabFileName` の 6 つの純粋な関数である。**タブの名前の決め方はここが持ち主である。**
- `SqlTab` に `customName` が増えた。`tab` ストアに `renameTab(id, name)` が増え、`null` で自動の名前へ戻る。**定義タブでは何も起きない。**
- `TabBar` がダブルクリックと `F2` で編集に入るようになった。入力欄は名前の場所に重なり、`●` 印と閉じるボタンは出たままである。**`tabSizing.ts` は 1 行も変わっていない。**
- `App.tsx` は表示名を通すようになった（5 か所）。足したのは `import` 1 行と式の差し替えだけである。
- Rust 側は `session_tab` に `custom_name` 列が増えた。`migrate_session_state` は `add_missing_columns(connection, table, columns)` へ一般化し、`session_state` と `session_tab` の両方から呼ぶ。**古い `history.sqlite3` はそのまま開ける。**
