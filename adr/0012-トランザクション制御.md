# ADR 0012: トランザクション制御

- ステータス: 承認
- 日付: 2026-09-07

## 状況

`Connection::commit()` を呼ぶ経路が Oracle 側に一つも無かった。`oracle` crate（rust-oracle）は autocommit が既定でオフであるため、読み取り専用でない接続で `INSERT` すると「3 行に影響しました」と表示されたあと、切断時にデータベース側で暗黙にロールバックされて消える。

**利用者からは成功に見えるのに、データが入っていない。** 実行できるのに確定できないという穴であり、他のどの未実装よりも害が大きい。

未コミットの状態を UI に出すには、「今トランザクションが開いているか」を知る必要がある。

## 決定

### 自動コミットは接続設定の項目にし、既定はオフ（手動コミット）

`SavedConnection` / `ConnectionParams` に `autoCommit` を足し、`connections.toml` に保存する。接続フォームの「読み取り専用」チェックの隣に置く。読み取り専用が真のときは、書き込みがそもそも起きないため自動コミットの項目を無効にする。

自動コミットが真のときは、接続直後に `Connection::set_autocommit(true)` を呼ぶ。`set_autocommit` は `&mut Connection` を要するため、`Arc` に包む前の一点で呼ぶ（[[0002-接続ごとのアクタースレッドと中止]]）。読み取り専用トランザクションとは併用しない。

### 未コミットかどうかはデータベースに聞く

実行のたびに `select dbms_transaction.local_transaction_id from dual` を読み、非 NULL なら未コミットとする。`ExecuteOutcome` の両方の枝に `inTransaction: bool` を載せて返す。1 往復増えるが、`DBMS_OUTPUT` の取得と同じ扱いでよい。

読み取り専用と自動コミットの接続では、往復せずに偽を返す。コミットすべき変更がそもそも生じないためである。読み取り専用は `SET TRANSACTION READ ONLY` 自体がトランザクションを開くため、聞けば必ず真になってしまう。

### `Driver` trait に `commit()` と `rollback()` を足す

[[0002-接続ごとのアクタースレッドと中止]] の「実装済みの操作だけを載せる」に従い、実装と同時に足す。アクターへは `Commit` / `Rollback` の命令として送る。

コミットとロールバックは**プールの全接続へ配る**（[[0003-結果セットのカーソル保持と接続プール]]）。DML はカーソルを残さないため実行の直後に割り当てが外れ、どの接続で走ったかを割り当ての表から辿れない。未コミットの変更が無い接続でコミットしても害は無いため、取りこぼさないほうを採る。

読み取り専用の接続でコミット / ロールバックした場合は、その場で読み取り専用トランザクションを張り直す。[[0004-認証情報と接続設定の保存先]] の保証はトランザクションが続く間だけ効くためである。

### キーバインドは `⌥⌘C` = コミット、`⌥⌘R` = ロールバック

`⌘K` と `⌘I` は将来のための予約であり、使わない。

### 未コミットを可視化する

ステータスバーの「読み取り専用」の並びに「未コミット」を出す（`--warn` トークンを `tokens.css` に足した）。コミット / ロールバックのボタンも同じ並びに置く。どちらも**手動コミットの接続のときだけ**出す。読み取り専用の接続と自動コミットの接続では、未コミットの状態がそもそも生じない。

コミット / ロールバックの結果はメッセージタブのログへ 1 行として残す。

### 未コミットのまま閉じさせない

未コミットの状態で**接続を手放す操作** — ウィンドウを閉じる・アプリを終了する・切断する（切り替えを含む）— をしようとしたら、`@tauri-apps/plugin-dialog` の確認を出し、「コミット / 破棄 / やめる」を選ばせる。同プラグインの確認は 2 択しか出せないため、「進むか / やめるか」「コミットするか / 破棄するか」の 2 段に分ける。「やめる」を選んだ時点で 2 段目は尋ねない。3 つの経路はすべて `App.tsx` の `resolvePendingTransaction` という 1 つの関所を通り、問いかけと肯定側のラベルだけを操作ごとに差し替える。

アプリの終了は Rust 側で `RunEvent::ExitRequested` を捕まえ、直接落とさずに各ウィンドウへ閉じる要求を送る。これによりウィンドウを閉じる場合と同じ関所を通る。ウィンドウが残っていない場合は割り込まず、そのまま終了させる。

## 理由

- **既定をオフにする**のは Oracle クライアントの慣習に合わせるためである。SQL\*Plus も SQL Developer も既定は手動コミットであり、その前提で書かれた手順が世の中に多い。加えて、誤って `DELETE` を撃ったときに取り返せる側を既定にしておきたい。
- **未コミットの判定をデータベースに聞く**のは、クライアント側で数えると必ずすり抜けるからである。`WITH ... INSERT`、無名 PL/SQL ブロック、関数の中の DML — 先頭キーワードでは判定できない形がいくらでもある。[[0004-認証情報と接続設定の保存先]] が読み取り専用をデータベース側のトランザクションで保証しているのと同じ理由であり、同じ判断を繰り返している。
- 「未コミット」と表示しながら実は確定済み、あるいはその逆は、**表示が嘘になる**という点で読み取り専用の表示を偽ることと同じ害を持つ。

## 却下した案

**クライアント側で DML を数える**: 実行した SQL の先頭キーワードを見て未コミットの数を増減させる。往復が増えないのは利点だが、`WITH ... INSERT` や無名 PL/SQL ブロックをすり抜ける。「未コミットはありません」と表示しながら変更が残っている状態を作る。

**自動コミットを既定オンにする**: データが黙って消える今の穴は塞がるが、`DELETE` の誤爆が取り返せなくなる。消えるほうと戻せないほうを比べれば、警告を出して止められる前者のほうが軽い。

**自動コミットをアプリ全体の設定にする**: 接続ごとに性格が違う（本番は手動、手元は自動）ため、接続の項目にした。

**未コミットの判定を実行の直後ではなく定期的に行う**: ポーリングは接続を無駄に使ううえ、表示が実行と非同期にずれる。

**トランザクションを保持している接続を割り当ての表で追う**: 実行の直後に割り当てが外れる（[[0003-結果セットのカーソル保持と接続プール]]）ため、追える情報が無い。表の作りを変えるより、全接続へ配るほうが単純で確実である。

## 結果

- 接続プールの本数だけコミットの往復が増える。往復 1 回はミリ秒の単位であり、コミットは頻繁な操作ではないため許容する。
- ウィンドウを閉じる割り込みには `core:window:allow-close` と `core:window:allow-destroy` の許可が要る。`capabilities/default.json` に足した。
- `lib.rs` は `run()` の代わりに `build()` + `run(クロージャ)` を使う形になった。終了に割り込む必要があるためである。
- 接続を手放す経路が増えたら、必ず `resolvePendingTransaction` を通すこと。データベース側の暗黙のロールバックは、どの経路から手放しても等しく起きる。
- 確認そのものは `src/transaction/pendingChanges.ts` の差し替えられる境界の裏にある。ネイティブのダイアログは jsdom で開けないため、テストはこの境界を差し替えて確かめる（[[0010-テストとリンタの構成]] の「`src/api/` 層の差し替え」と同じ考え方）。
