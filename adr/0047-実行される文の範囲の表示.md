# ADR 0047: 実行される文の範囲の表示

- ステータス: 承認
- 日付: 2026-09-28

## 状況

`⌘⏎` はカーソル位置の文を実行する（ADR README「SQL の実行単位」）。どこからどこまでが 1 文かは `splitStatements` が決めるが、画面には何も出ていなかった。PL/SQL のブロックや、`;` を書き忘れた文の続きでは、流れる範囲が利用者の見立てとずれる。流した後にメッセージタブを見て初めて気づく（issue #73）。

issue の希望は 2 つである。

- 文の範囲を**行番号の横の縦線で常に示す**。
- **実行した瞬間だけその範囲を一瞬光らせる。**

## 決定

### 範囲の決め方を 1 つにする

実行の対象を決める関数を `src/sql/runTarget.ts` の `runTargetOf(scope, 本文, カーソル)` 1 つにした。仲介者の実行（`mediator/execution.ts`）もエディタの表示（`components/editor/statementRange.ts`）もここを通る。**表示が自分で範囲を決め直すと、光った範囲と流れた文がずれ、表示が嘘をつく。**

| 単位        | キー    | 対象                                                   |
| ----------- | ------- | ------------------------------------------------------ |
| `statement` | `⌘⏎`    | カーソル（選択の `head`）位置の文。**選択は見ない**    |
| `selection` | `⇧⌘⏎`   | 選択範囲の中の文。選択が無ければ無い                   |
| `script`    | `⌥⌘⏎`   | 選択範囲の中の文。選択が無ければ本文全体の文           |

実行計画（`⌘E` / `⇧⌘E`）は選択があれば `selection`、無ければ `statement` の最初の 1 文を取る（ADR 0039 のまま）。

- **縦線**は `pickStatementAt` で選ぶ。`statementAt` から「切り出し済みの一覧から選ぶ」部分を抜き出したもので、`statementAt` 自身もこれを呼ぶ。縦線は本文が変わったときだけ切り出し直し、カーソルが動いたときは選び直すだけにするためである。どの位置でも `runTargetOf('statement', …)` と同じ文を選ぶことをテストで見張る。
- **光らせる範囲**は仲介者から受け取る。仲介者が「これを流す」と決めた `RunTarget` を `RunScreen.highlight` へ渡し、`App.tsx` が `SqlEditorHandle.flashRunTarget` へ繋ぐ。keymap の中で光らせないのは、実行の入口がキー・`RunControls` のボタン・パレット・メニューバーの 4 つあり、どこから流しても光らせるためである。パレットとメニューはコマンドの表を通るので、`CommandScreen.highlightRun` も同じ口へ繋ぐ。

`RunTarget` の文の位置は、選択から切り出したときは選択の先頭から数える（`origin: 'selection'`）。仲介者は選択の位置を知らない（`EditorCursor` は選んだ文字列しか持たない）ため、本文の位置へ直すのは選択を持っているエディタの側で行う。`EditorCursor` に位置を足す手は、仲介者の形を変えるわりに得るものが無いので取らなかった。

### 縦線は `⌘⏎` の対象だけを示す

縦線は**選択の有無にかかわらず `⌘⏎` で流れる文**を示す。選択があるときに選択範囲を示す案は退けた。`⌘⏎` は選択を見ないので、選択を示すと `⌘⏎` の範囲について嘘をつく。選択範囲は選択の地そのものが見えている。

文が 1 つも無い本文（空・コメントだけ）では引かない。カーソルが文と文の間の空行にあるときは、`⌘⏎` が流す直前の文に引く。

### 描き方

- **縦線**は CodeMirror の `gutter` を行番号の直後に 1 本足し、`lineMarker` で見える行の分だけ印を作る。印の集合を状態として持つと、長い PL/SQL の中でカーソルを動かすたびに数千行ぶんを組み直すことになる。溝の幅（3px）は常に取り、そのぶん行番号の右の余白を 12px から 9px へ詰めた。溝が出たり消えたりすると本文が横へずれる。文の最初と最後の行だけ縦線を 3px 内側へ縮め、隣り合う文の縦線が 1 本に繋がって見えないようにした。
- **光らせる**のは行の飾り（`Decoration.line`）で、文が占める行をまるごと塗る。文字だけを塗る飾り（`Decoration.mark`）は行の高さ 1.7 の余りを塗らず、行と行の間にすき間が出る（issue #54 と同じ）。1 行に 2 つの文が載っているときは、片方を流しても行ごと光る。縦線と同じ行の粒度に揃えたものとして受け入れる。
- 光は 600ms で消す。消えていく動きは CSS のアニメーションで描き、時間が来たら飾りそのものを外す。続けて同じ文を流したときにアニメーションを頭から走らせるため、飾りの class を 2 つ（`cm-runFlash-a` / `-b`）交互に使い、別の名前のアニメーションを当てる。同じ class を付け直すだけではブラウザは走らせ直さない。
- **`prefers-reduced-motion: reduce` では消えていく動きを止め、光らせている 600ms の間だけ地を敷く。**何が流れたかを示すこと自体は動きではないため、やめはしない。
- 色は `--ac` から取る（縦線はそのまま不透明度 0.6、光は `color-mix(in srgb, var(--ac) 24%, transparent)`）。新しいトークンは足さない。「今流れるもの」を示す色はアクセントそのものであり、ライトとダークの値は `--ac` が既に持っている（ADR 0008）。
- 寸法は `&` に書かない（ADR 0031）。足した選択子はどれも溝と行の中を指す。

### 長い本文では打鍵の間だけ縦線を消す

切り出しは 1 文字あたりおよそ 150ns かかる（36 万文字・約 1 万行で 53ms を実測）。打鍵のたびに走らせると 1 フレームに収まらない。

本文が 50,000 文字（`SYNC_SPLIT_LIMIT`）以下なら打鍵のたびに切り出し直す。それより長ければ打鍵の間は縦線を消し、打鍵が 200ms 止んでから切り出し直して引く。

**古い結果の位置を変更に合わせてずらして使い回す案は退けた。**`'` を 1 つ打っただけで、その後ろの文の切れ目は全部変わりうる。ずらした範囲は実行される文と食い違う。範囲を示せない間は、嘘の範囲を示すより何も示さないほうがよい。変わった所より前だけを切り出し直す差分の切り出しも退けた。後ろは結局全部読み直すことになり、文頭の近くを打つときには何も得られない。

光らせる範囲は仲介者が実行の時点で切り出すので、本文の長さに関わらず正しい（実行の時点での切り出しはこの ADR より前からある）。

## 影響

- 実行の 3 つの裁定（`runStatement` / `runSelection` / `runScript`）と `runPlan` は、どれも `runTargetOf` を通すようになった。Oracle へ渡す本文は `splitStatements` の `text` のままで、ADR 0039 の決定は変わらない。
- エディタが描かれていない画面（定義タブ）では `highlight` は何もしない。仲介者は `highlight` を省いてもよい作りにしてあり、既存の単体テストは手を入れずに通る。
- 縦線はタブの本文（CodeMirror の文書）から、実行は `tab` ストアの本文から切り出す。両者は変換中（IME）だけ食い違いうる（`SqlEditor` は変換中に `onChange` を呼ばない）。変換中に `⌘⏎` を押す場面は無いため手当てしない。
