# ADR 0048: 結果テーブルの列の固定と表示調整

- ステータス: 承認
- 日付: 2026-09-28

## 状況

利用者から結果テーブルについて 2 つの要望が出ている。

1. 横スクロールしても左の列（主キーなど）を見えたままにしたい（#78）。入口は列の右クリックメニューの「この列まで固定」。
2. 結果ペインのヘッダー右端に表示調整の入口がほしい（#79）。アイコンは `sliders-horizontal`。押すとヘッダーが広がり、数値を 3 桁で区切るかなどを選べる。同じ調整を設定画面で既定としても決めたい。

ADR README の「結果テーブル」節は、列のソートを「手元の一部を並べたものが全体を並べたように見える」ために退け、同じ理由で列の並べ替えと非表示も退けている。

決めることは次のとおり。

1. 列の固定がこの決定に触れるか
2. 固定の持ち方と寿命、仮想スクロールとの両立、解除の入口
3. 表示調整に何を入れるか
4. 表示を変えたときに、コピー・検索・CSV・列幅の見積りが何を使うか
5. 表示調整の単位と保存、既定との関係
6. 広がったヘッダーのキーボード操作と `esc`

## 決定

### 列の固定は README の決定に触れない

ソートが退けられたのは、並びを偽るからである。並べ替えと非表示も同じで、前者は列の順を、後者は列の有無を画面と結果セットとで食い違わせる。固定は列の順も有無も変えない。横に流れる列の上に左の列が留まるだけで、表の中身については何も偽らない。したがって README の決定は蒸し返さない。

### 固定は見出しの右クリックから入れ、列名と位置で覚える

入口は見出しの右クリックメニュー（[[0038-右クリックメニューの追加]]）の「この列まで固定」と「列の固定を解除」の 2 つだけにする。既にその列までを固定しているときは前者を、何も固定していないときは後者を出さない。キーもマウス操作の割り振りも足さない。固定は結果を開いたときに 1 度決めれば済む操作であり、見出しの操作（ドラッグで幅、ダブルクリックで幅合わせ）と食い合わせる理由がない。

固定の境目は `ui` ストアの `resultFrozenColumns`（タブ ID → `{ name, index }`）に置く。寿命は列幅と同じにする。再実行をまたいで残し、タブを閉じたら捨て、保存はしない。同じクエリを流し直すたびに固定し直させないためである。位置も持つのは、`SELECT a.id, b.id` のように同じ名前の列が並ぶ結果で 2 つめの `ID` まで固定したときに、1 つめまでに縮まないようにするためである。覚えた位置に同じ名前の列が無ければ、同じ名前の最初の列まで固定する。どこにも無ければ固定しない（`resolveFrozenCount`）。

固定した列があるときは行番号の列も固定する。行番号を流すと、固定した列の左に隙間が空く。

### 固定は `position: sticky` で行い、固定した列の幅は決め打ちにする

仮想スクロールは縦だけであり、固定は横の話なので、行の描き方には手を入れない。固定する列と行番号の列のセルに `position: sticky` と `left` を付ける。見出しと本文は別々のスクロール領域だが、それぞれの中で同じ `left` に貼り付くため桁は揃ったままになる。

`left` は左の列の幅を足し上げて決める（`frozenOffsets`）。そのため固定した文字列の列は `minmax(160px, 1fr)` で伸縮させず、幅を覚えていればその幅、覚えていなければ下限の幅で決め打ちにする。伸縮させると描かれてみないと幅が分からず、固定した列どうしが重なる。

固定したセルは地を不透明な色で塗る（塗らないと下を流れる列が透ける）。境目の罫線は `--line` で引く。罫線を消す設定（`data-grid-lines='off'`）でも境目は見える。

選択・コピー・詳細パネル・検索は列の番号で動いており、固定しても番号は変わらないため手を入れない。選択が固定した列の陰に隠れたときに横へ送る処理は入れない。固定の前から横方向の追従は無い。

### 表示調整は「数値の 3 桁区切り」と「空白・タブ・改行の可視化」の 2 つに限る

| 候補                     | 採否 | 理由                                                                                                                                                                                                                                     |
| ------------------------ | ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数値の 3 桁区切り        | 採る | 桁の多い金額や件数が読めない。値を文字列のまま区切れるので精度を壊さない                                                                                                                                                                 |
| 前後の空白・タブ・改行   | 採る | 1 行に収めて描くセルでは、`CHAR(n)` の詰め物・取り込みで混ざった空白・改行が見えず、`WHERE` で当たらない理由が分からない                                                                                                              |
| 小数の桁数を揃える・丸め | 採らない | 丸めた値は値ではない。README がソートを退けた「画面と実体の食い違い」をこちらから作ることになる                                                                                                                                  |
| 日付の書式               | 採らない | 日時はセッションの NLS 書式で文字列になって届く。手元で読み直すと NLS ごとの解釈が要り、読み違えると日付を偽る。書式を変えたいときは `TO_CHAR` か `ALTER SESSION` が筋である                                                    |
| NULL の表記              | 採らない | `NULL` の表記は空文字列と見分けるための決定である（[[0008-デザイントークンとテーマ実装方式]]）。空にできる選択肢を置くと見分けが消える                                                                                                   |
| 文字の大きさ・折り返し   | 採らない | 行の高さは固定で、列幅の見積りも固定の文字の大きさに依る（CLAUDE.md「デザイントークンとテーマ」）                                                                                                                              |

3 桁区切りは `-12345.678` / `1234` の形だけを区切り、指数表記や見知らぬ形には手を付けない（`groupThousands`）。`Intl.NumberFormat` は `number` を経由し、38 桁の `NUMBER` の精度を壊すため使わない。

空白の可視化で置き換えるのは、前後の半角空白（`·`）と、どこにあってもタブ（`→`）と改行（`↵`）である。途中の半角空白は読めており、置き換えると文が読めなくなる。記号は値に含まれうる文字と取り違えないよう、色を落として描く。3 桁区切りは数値の列、空白の可視化は文字列の列にだけ効き、NULL と 2 進値の要約には当てない。

### 表示調整は描く文字だけを変え、写すものは値のままにする

| 用途                           | 使う文字                 |
| ------------------------------ | ------------------------ |
| セルの描画                     | 描く文字                 |
| 列幅の内容合わせ               | 描く文字                 |
| 検索                           | 描く文字と値の両方に当てる |
| コピー（`⌘C` / `⇧⌘C` / メニュー） | 値（`displayText`）     |
| CSV                            | 値（Rust 側。手を入れない） |
| 詳細パネル・セルの `title`     | 値                       |

写すものを値に寄せるのは、写す先が SQL と表計算だからである。`1,234` を `WHERE id = ` の後ろへ貼ると `ORA-00933` になる。CSV では区切りの `,` と混ざる。`·` や `↵` が混ざった文字列は、元の値と一致しない。

画面と写すものの食い違いには 2 つの手当てを置く。広がった欄と設定画面に「見た目だけ。コピーと CSV は元の値のまま」と書く。既定から外れた表示になっているあいだは、ヘッダーのボタンを `--ac` の色で描き、開かなくても分かるようにする。

検索（[[0027-結果テーブルの検索]]）の当て先は「画面に見えている文字列」であり、この規則は保つ。描く文字だけに当てると、貼り付けてきた値（`1234567`）で探せない。値だけに当てると、見えている文字（`1,234,567`）で探せない。どちらも当てる。

列幅の内容合わせは描く文字で測る。値で測ると、区切りを入れた列で末尾が `…` で欠ける。

### 既定は設定画面で決めて保存し、ヘッダーではそのタブだけを上書きする

既定は設定画面の「結果の表示の既定」で決め、`settings.toml` の `[resultDisplay]` に保存する。Rust 側の項目は `#[serde(default)]` に加えて型の合わない値を既定へ落として読む（`lenient`）。真偽値の欄に `"yes"` と手で書かれただけで表ごと読めなくなり、テーマもキーの割り当ても既定へ戻る事態を避ける。

ヘッダーの欄で切り替えたものは、その結果タブだけの上書きになる。上書きは `ui` ストアの `resultDisplayOverrides` に**既定と違う項目だけ**を持ち、寿命は列幅と同じにする（保存しない）。差分だけを持つのは、後から既定を変えたときに、そのタブで触っていない項目は新しい既定へ追随させるためである。既定をタブの上書きと同じ値へ変えたら、その上書きは消える。欄の「既定に戻す」はそのタブの上書きを捨てる。

タブ単位にするのは、「この結果だけ区切って読みたい」が一時的な用事だからである。全体を変えたいなら既定を変えればよい。ヘッダーから既定を書き換える入口は作らない。ヘッダーでの軽い操作が全タブの見え方と設定ファイルを変えることになる。

タブを閉じる関所（`closeTabAndRelease`）は、列幅・表示調整・固定の 3 つを `forgetResultView` でまとめて捨てる。3 つは寿命が同じであり、入口を 1 つにしておけば関所が捨て忘れない。

### 広がる欄は重ねずに押し下げ、`esc` は `useEscapeKey` で受ける

ボタンは結果の表を描いているとき（結果タブ・成功・列あり）だけ出す。表の無いところで押せても、変えた結果を確かめる先が無い。

押すとヘッダーの下に欄が 1 行ぶん広がり、表を押し下げる。オーバーレイにしないのは、切り替えた結果を表で確かめながら触るものだからである。重ねると、変えた表示が欄の下に隠れる。

ボタンは `aria-expanded` と `aria-controls` を持ち、欄の中身はネイティブのチェックボックスなので、`Tab` と `Space` で操作できる。開いたら最初の項目へ焦点を移す。

`esc` は `useEscapeKey` で受ける（[[0031-オーバーレイのescとdocumentのスクロール]]）。欄はオーバーレイではないが、`esc` の受け手を 2 種類にしないためである。後から開いた詳細パネルやメニューが先に閉じる順序も、積みがそのまま守る。閉じたときに焦点が欄の中にあればボタンへ戻す。表やエディタに焦点を置いたまま閉じたときは、そこから奪わない。

## 却下した案

- **固定を列の数（「左から N 列」）で持つ**: 実行し直して列の並びが変わると、別の列が固定される。列名で覚える列幅と振る舞いが揃わない。
- **固定する列を見出しのピンのボタンで選ぶ**: 見出しに押す場所が増え、幅のつまみやダブルクリックと食い合う。入口はメニューで足りる。
- **表示調整をコピーにも効かせる**: 上の「写すものは値のまま」の理由による。区切りを付けて写したい用途は見当たらない。
- **表示調整を全タブ共通の 1 つにし、ヘッダーから既定を書き換える**: ヘッダーでの一時的な操作が他のタブと `settings.toml` に及ぶ。
- **欄をポップオーバーにする**: 表を覆い、変えた結果が見えない。

## 影響

- `src/components/results/resultDisplay.ts`（表示調整の純粋な関数）と `ResultDisplayBar.tsx`（広がる欄）を足した。
- `columnSizing.ts` に `resolveFrozenCount` / `frozenOffsets` を足し、`gridTemplate` が固定した列の幅を決め打ちにする。
- `resultSearch.ts` の `SearchOptions` が表示調整を受け、描く文字と値の両方に当てる。表示調整が変われば前の結果へ継ぎ足さず数え直す。
- `ui` ストアの `clearResultColumnWidths` を `forgetResultView` に置き換えた。
- `settings.toml` に `[resultDisplay]`（`thousandsSeparator` / `showWhitespace`）が増える。項目を持たない古いファイルはそのまま読める。
- 選択範囲を表の外へ渡す callback（並行作業）は `ResultTable` の props に足せばよく、固定と表示調整の props とは独立している。
