# ADR 0029: ライセンスと商用利用の扱い

- ステータス: 承認
- 日付: 2026-09-10

## 状況

リポジトリを public にする。ここまで `LICENSE` は 1 つも置いていない。法的には全権利留保だが、[[0011-cicdとリリース配布]] のとおり dmg を配っており、[[0028-配布物の署名と公証]] で署名と公証まで済ませている。**利用者は「使ってよい」と読める状態のものを受け取っているのに、条文が無い。**

加えて第三者のソフトウェアの著作権表示（MIT / Apache-2.0 / BSD / OFL）を配布物に同梱していない。これは条文の有無とは別に、**現時点で義務を満たしていない**。

決めるべきことは 5 つある。

1. どのライセンスを土台にするか
2. 開発版の扱いをどう書くか
3. 公開の順序をどうするか
4. プルリクエストを受けるか、受けるなら貢献の権利をどう扱うか
5. 第三者の著作権表示をどう作るか

## 決定

### 1. PolyForm Noncommercial License 1.0.0 を土台にする

**OSI 準拠のオープンソースにはできない。**利用の分野で条件を変えることは OSD 6（利用分野による差別の禁止）に反する。名乗らなければよいだけなので、source-available として扱う。

自前で条文を書かず、既製の PolyForm Noncommercial License 1.0.0 を**全文そのまま** `LICENSE` に載せる。無保証・責任制限・特許許諾・是正期間 32 日・サブライセンスの禁止が最初から揃っており、この 5 つを自分で書き直す理由が無い。

条件は追加許諾（Additional Grants）として条文の下に足す。**本体には手を入れない。**既製の条文を改変すると、既製である利点（読み手が既に知っている、法務が通しやすい）がそのまま消える。

**正文は英語**とし、日本語は `LICENSE.ja.md` に参考訳として置く。効力は英語側にあると両方に明記する。

### 2. 開発版の扱いは「バージョン番号」で切り、「実行と使用」に限る

追加許諾の第 1 条で、**バージョン番号が 1.0.0 未満のリリース**を商用・非商用問わず無償とする。

**日付では切らない。**既に配ったバイナリの許諾は後から取り消せず、日付で切ると「いつ入手したか」の証明が要る。バージョンなら利用者は手元の版を見るだけで判断できる。

**この追加許諾は実行と使用に限り、配布を含まない。**含めると、最後の 0.x をフォークして配り続ける道が開く。なお PolyForm の定義する `Use` は「許諾を必要とする行為すべて」であり**配布を含む**ため、日本語の「利用」の語感に任せず条文で明示的に外す。

第 2 条で、1.0.0 以降は有償を含む別の条件になりうることを**予告する**。同時に、**既に公開した 1.0.0 未満のリリースについて第 1 条を撤回しない**ことも書く。撤回しうると読めるものを仕事道具にする者はいない。書いても 1.0.0 以降の自由は失われない。

### 3. 公開前にライセンスを確定する

**公開後に締めることはできず、緩めることはいつでもできる。**緩いライセンスで一度出せば、そのコミットは永久に緩いままで、誰でもフォークして続けられる。したがって**制限の強い側で公開し、後から開放する**順序を採る。

1.0.0 のときの条件は**まだ決めない**。第 2 条の予告があるため、そのときに決めれば足りる。

### 4. プルリクエストは受ける。貢献には再ライセンス権を伴わせる

**Issue も PR も受ける。**そのうえで `CONTRIBUTING.md` に貢献のライセンス条件を置き、PR を送ることをもって同意とし、証跡として全コミットに `Signed-off-by` を求める。

条件の要は、ライセンサーに対する**「任意の条件（有償の商用条件を含む）で再ライセンスして配布する権利」**である。**DCO だけでは足りない。**DCO は「元のライセンスで提供した」ことの表明にすぎず、貢献を含んだ版を別の条件で提供する権利を与えない。これが無いまま PR を 1 本でも取り込むと、決定 2 の第 2 条で予告した道が塞がる。

正文は英語とし、日本語は参考訳とする（`LICENSE` と揃える）。

### 5. 第三者の著作権表示は生成する

`bun run notices` が `THIRD-PARTY-NOTICES.md` を作る。npm は `package.json` の `dependencies` から**本番依存の閉包**を辿り（開発用の依存は配布物に入らない）、Rust は `cargo tree -e normal` が示す実際にリンクされるクレートを拾う。書体のように依存関係の外で同梱しているものは生成スクリプトの `ASSETS` に手で並べる。

**全文が拾えなかったものは黙って落とさず、拾えなかったことを本文に書く**（[[0021-オブジェクトのソース検索]] の「黙って切り詰めない」と同じ考えである）。

`LICENSE` と `THIRD-PARTY-NOTICES.md` は `tauri.conf.json` の `bundle.resources` で **`.app` の中へ同梱する**。この指定が外れても手元の `bun run tauri dev` は何も変わらず、**配ってからでないと気づけない**ため、[[0028-配布物の署名と公証]] のエンタイトルメントと同じ理由で `src-tauri/tests/notices.rs` が見張る。

## 理由

既製の条文を土台に置き、変えたい点だけを追加許諾に寄せる形は、**後から条件を変えるときの費用が最も安い**。本体を触らないので、読み手が既に知っている前提が壊れない。追加許諾は独立した節として足し引きできる。

順序については、**公開後にライセンスを締めることはできず、緩めることはいつでもできる**（決定 3）。1.0.0 の条件を決めていない段階では、制限の強い側から始めるほかない。逆の順序は選び直せない。

## 却下した案

**独自の条文を書く。** 無保証・責任制限・特許・是正期間をすべて自分で書くことになる。既製の条文を使えば読み手も法務も既に知っている。

**PolyForm Small Business 1.0.0 をそのまま使う。** 「従業員 100 人未満**かつ**前課税年度の売上 100 万 USD 未満」という AND 条件だが、日本の一人あたり売上高（2,000〜3,000 万円程度）で換算すると売上条件は従業員 5〜10 人規模に相当し、**100 人の条件が事実上の死に条項になる**。名前から受ける印象と実際の範囲がずれる。閾値を変えるには条文の改変が要り、既製である利点が消える。

**MIT や Apache-2.0 で公開する。** 一度緩く公開すると締められない（決定 3）。1.0.0 の条件を決めていない段階では選べない。

**Business Source License 1.1 を使う。** 追加許諾を自由に書ける点は合うが、変更日（最長 4 年）と変更ライセンス（GPL 互換）の指定が必須で、**すべてのリリースが 4 年後にオープンソースになる**約束を今する必要がある。1.0.0 の条件すら決めていない段階で負う約束としては重い。

**PR を受けず Issue だけにする。** 貢献の権利の問題は消えるが、公開する意味が薄い。CLA 相当の条項を `CONTRIBUTING.md` に置けば済む（決定 4）。

**試用期間で切る。** データベースクライアントで期限を過ぎたときに締め出すと、**利用者は保存した接続とクエリに触れなくなる**。仕事道具としての性質に合わない。

**`LICENSE` を置かずに公開する。** 何も無い状態は全権利留保であり、利用者は何もできない。加えて決定 2 の第 2 条（将来の条件変更の予告）は**今しか書けない**。予告せずに配り続けてから条件を変えると、既に導入した利用者との間で揉める。

## 結果

- `LICENSE` — PolyForm Noncommercial License 1.0.0 の全文と追加許諾 6 条（開発版 / 将来の条件 / 名称と標識 / 準拠法と管轄 / 責任の上限 / 貢献）
- `LICENSE.ja.md` — 参考訳。効力が無いことを明記する
- `CONTRIBUTING.md` — 貢献のライセンス条件と `Signed-off-by`。`.github/PULL_REQUEST_TEMPLATE.md` に確認欄を置く
- `THIRD-PARTY-NOTICES.md` — `bun run notices` の生成物。手で編集しない
- `scripts/thirdPartyNotices.ts` — 閉包の探索・ライセンスファイルの選別・Markdown の組み立て（純粋な関数）
- `scripts/generate-third-party-notices.ts` — ファイルの読み取りと `cargo` の実行
- `src-tauri/tests/notices.rs` — `bundle.resources` の指定と実在の見張り

準拠法は日本法、第一審の専属的合意管轄は**横浜地方裁判所小田原支部**とする。責任の上限は、免責の全部が有効とならない範囲（消費者契約法 8 条の適用がある場合を含む）について、**受領した対価の額**とする。

条件を変えるときは、`LICENSE` の追加許諾第 4 条・第 5 条と `CONTRIBUTING.md` の貢献条項について、一度は専門家の確認を取ること。
