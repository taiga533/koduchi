# ADR 0018: 保存済みクエリとコマンドパレット

- ステータス: 承認
- 日付: 2026-09-08

## 状況

サイドバーの「保存済み」セグメントと、タイトルバー中央の `⌘K` 検索ボックスは、どちらも器だけの状態で置かれていた。保存済みは「保存したクエリがここに並びます」という空状態を出すだけで保存する道が無く、検索欄はそのセグメントのときだけ `disabled` になっていた。検索ボックスはただの `span` で、`⌘K` と `⌘I` は「将来のための予約」として割り当てられていなかった（[[0009-ウィンドウモデルとタイトルバー]]）。

この 2 つは別々の機能に見えるが、パレットの探し先に保存済みクエリが含まれる以上、片方だけを先に作っても中途半端になる。まとめて決める。

決めるべきことは 4 つある。

1. 保存済みクエリをどこへ置き、接続をまたいで共有するか
2. 保存と取り出しの導線、および足すキーバインド
3. パレットが何を探し、どう絞り、どう並べるか
4. スキーマがまだ読み込み中のとき（[[0007-スキーマ取得の段階的ロード]]）に何を出すか

## 決定

### 保存済みクエリは `history.sqlite3` の 1 つの表に置く

[[0005-クエリ履歴とセッション復元のsqlite]] の保管庫へ `saved_query` を足す。持つのは ID・名前・SQL 全文・接続名・作成日時・更新日時である。既にあるファイルを開いても落ちないよう、`create table if not exists` を `SCHEMA` へ並べる（`session_state` の列追加と同じ作法）。

**フォルダとタグは持たせない。** 名前と本文に効く検索があれば、数十件から数百件の規模では十分に手繰れる。階層を持たせると、移動・改名・空フォルダの始末という UI が芋づるで要る。必要になった時点で列を 1 つ足せばよく、先に作る理由が無い。

**バインド変数の値は保存しない。** 保存するのは SQL 本体だけである。[[0005-クエリ履歴とセッション復元のsqlite]] が履歴とセッションに対して置いた判断をそのまま引き継ぐ。SQL 本文が平文で SQLite に残る点も履歴と同じ扱いとし、代わりに 1 件ごとの削除を用意する。

### 保管庫は全接続で 1 つ、スコープ切替を持ち、既定は「全接続」

履歴と同じく接続名を添えて 1 つの表に入れ、サイドバーで「この接続のみ / 全接続」を切り替えられるようにする。**ただし既定は履歴と逆で「全接続」にする。** 履歴は「いつ何を実行したか」の記録であり、今つないでいる先のものを見るのが自然である。保存済みクエリは使い回す道具であり、開発と本番のように同じスキーマを持つ接続をまたいで使う。窓ごとに道具箱が分かれていては保存する意味が薄い。

コマンドパレットも同じ理由で、保存済みクエリは全接続ぶんを、履歴は現ウィンドウの接続ぶんを探す。

### 保存は `⇧⌘S`、取り出しはサイドバーとパレットから

- `⇧⌘S` で今のタブ（選択範囲があればその中）に名前を付けて保存する。置き場所は `App.tsx` の `keydown` である（CLAUDE.md の「キーバインドの置き場所」）。`⌘S` はファイルへの保存、`⌥⌘S` は CSV の保存であり、`⇧⌘S` は空いていた。名前を尋ねるダイアログは `SaveQueryDialog.tsx` で、作りはバインド変数ダイアログに揃える（`⏎` で保存、`esc` で取り消す。キーバインドは足さない）。
- サイドバーの一覧から押せばエディタへ入る。鉛筆で名前を変え、✕ で消える。**名前の変更は行の中で行う。** そのためだけにダイアログを増やすほどの操作ではない。
- 保存済みセグメントの検索欄の `disabled` を外し、名前と SQL の両方に部分一致で当てる。名前を思い出せなくても中身から辿れる。
- 名前の重複は弾かない。名前は目印であって鍵ではない。

### `⌘K` はコマンドパレットに割り当てる。`⌘I` は予約のまま

[[0009-ウィンドウモデルとタイトルバー]] が予約していた 2 つのうち、`⌘K` だけを使う。`⌘I`（Ask AI）は機能スコープの対象外であり、タイトルバーの Ask AI ボタンも器のまま残す。

タイトルバー中央の検索ボックスは `span` から `button` に変え、押してもパレットが開くようにする。接続していないときは押せない。

### パレットが探すのは 4 種、見出しの順は固定

現ウィンドウの接続の中を探す。並べるのは次の 4 種である。

| 見出し         | 中身                                                    |
| -------------- | ------------------------------------------------------- |
| コマンド       | 既存のキーバインドで呼べる動作                          |
| スキーマ       | 取得済みのスキーマ名とそのオブジェクト                  |
| 保存済みクエリ | 全接続ぶんの保存済みクエリ（名前で当てる）              |
| 履歴           | 現接続の履歴（SQL の 1 行に畳んだものに当てる）         |

**見出しの並びは固定である。** 当たりの強い種別を上へ持ち上げると、1 文字打つたびに見出しの位置が入れ替わって目が迷う。種別ごとの件数には上限を置く（コマンド 20、他は各 8）。Oracle のスキーマはオブジェクトが数千に達しうるため、全部並べても読めない。

**列は候補にしない。** 数万件になりうるうえ、表を先に決めればエディタの補完で辿れる（[[0013-補完の候補生成と識別子の出力スタイル]]）。

### 絞り込みは大文字小文字を区別しない部分一致、並びは当たりの強さ順

当たり判定と並べ替えは `src/components/palette/paletteSearch.ts` の純粋な関数に寄せる（`src/components/results/selection.ts` と同じ考え方）。

- 拾い方は**部分一致**（大小の区別なし）。
- 強さは 3 段階。前方一致 3 / 語の切れ目の直後 2 / 語の途中 1。`ORDERS` は `order` に対して 3、`SALES_ORDER` は 2、`REORDERED` は 1 になる。
- 同じ強さなら、当たりの早いもの → 短いもの → 渡された順の順に並べる。

突き合わせるのは表示名だけで、右に添える補足（接続名・キー表記・スキーマ名）は対象にしない。接続名で候補が釣れると邪魔になる。

**あいまい一致（綴りを飛ばして拾うサブシーケンス照合）は採らない。** データベースの識別子は `ORDER_ITEM_DETAIL_HISTORY` のように長く、語彙も似通う。飛ばして拾うと当たりが爆発し、上位に出てくるものが信用できなくなる。打つ側も「この綴りが入っているものを出す」という単純な規則のほうが結果を予測できる。

### 保存済みクエリと履歴は開いた時点で 1 度だけ読む

パレットを開いたときに各 200 件を読み、あとは手元で絞る。打鍵のたびに SQLite へ往復すると入力が目に見えて詰まる。スキーマは既に `schema` ストアの中にあるものをそのまま使う。

### スキーマの読み込み中は、取れている範囲だけを出してその旨を添える

[[0007-スキーマ取得の段階的ロード]] の段階 1（スキーマ名とオブジェクト名）が終わるまでスキーマの候補は出ない。この間はコマンド・保存済みクエリ・履歴だけが並び、パレットの下端に「スキーマを読み込んでいます…」を出す。**空のまま黙らない。** 候補が出ないのが読み込み中のためなのか、当てはまるものが無いためなのかを、利用者が見分けられなければならない。

### 決めたときの動き

- コマンド … その動作を走らせる
- 保存済みクエリ / 履歴 … SQL を今のタブへ入れる（サイドバーから押したときと同じ）
- スキーマ … サイドバーをスキーマへ切り替え、そのスキーマを開いて絞り込み語に名前を入れる

最後の 1 つは、ツリーへ「ここへ移れ」と伝える仕組みを新たに足さず、既にある絞り込みと開閉だけで済ませる形である。名前を検索欄へ入れればその 1 件だけが残るため、位置を追う仕掛けは要らない。

### キーボードだけで完結する

↑↓ で移動（端では回り込む）、`⏎` で決定、`esc` で閉じる。マウスを乗せた行はそのまま選択になる。

### `savedQuery` ストアを足す

zustand のストアは 6 つから 7 つになる。履歴ストアへ相乗りさせることも考えたが、スコープの既定値も、持つ操作（保存・改名）も違う。`history` は「実行の記録を読んで消す」、`savedQuery` は「道具を作って直して消す」であり、責務が別である。

## 理由

- **保管庫を分けない**のは [[0005-クエリ履歴とセッション復元のsqlite]] が履歴について置いた理由がそのまま当てはまるためである。接続横断のスコープ切替がある以上、保管庫は 1 つでなければならない。テーブルが 1 つ増えるだけで済む。
- **既定を「全接続」にする**のは、保存済みクエリが記録ではなく道具だからである。1 接続 = 1 ウィンドウ（[[0009-ウィンドウモデルとタイトルバー]]）である以上、接続ごとに分けると窓を開き直すたびに道具箱が空になる。
- **絞り込みを純粋な関数に切り出す**のは、パレットの見え方が打鍵のたびに変わり、目で確かめても取りこぼすためである。当たり判定と順序だけを取り出せば、境界の場合を並べて書ける。
- **見出しの順を固定する**のは、位置が動かないことが速さに直結するためである。パレットは目で読む道具ではなく、覚えた位置へ手を伸ばす道具である。

## 却下した案

**保存済みクエリを `connections.toml` や別ファイルへ置く**: パスワード以外の接続設定はそこにあるが（[[0004-認証情報と接続設定の保存先]]）、保存済みクエリは接続の属性ではない。検索も要るため、SQLite のほうが素直である。

**保存済みクエリを接続ごとに完全に分ける**: 隣のウィンドウで保存したものが見えなくなる。同じスキーマの開発・本番を並べて見るという [[0009-ウィンドウモデルとタイトルバー]] の実利と噛み合わない。接続名は添えてあるので、絞りたい人はスコープを切り替えればよい。

**フォルダとタグを持たせる**: 移動・改名・空フォルダの始末という UI が要る。名前と本文の検索で足りる規模から始め、必要になったら足す。

**名前を一意にして、同名の保存は上書きにする**: 「保存したつもりが上書きだった」という取り返しのつかない事故を作る。名前は目印であって鍵ではない。

**保存のキーを `⌘⇧K` や新しい修飾に割り当てる**: `⇧⌘S` が空いており、「保存」の並びとしても素直である。修飾の組み合わせを増やす理由が無い。

**`⌘I` も同時に割り当てる**: Ask AI は機能スコープの対象外である。器を器のまま残す。

**あいまい一致（サブシーケンス照合）で拾う**: 上に書いたとおり、識別子の語彙では当たりが爆発する。

**当たりの強い種別から順に見出しを並べる**: 1 文字打つたびに見出しが入れ替わり、位置を覚えられない。

**打鍵のたびに SQLite へ問い合わせて絞る**: 絞り込みが Rust 側の `like` と揃うのは利点だが、入力の応答が往復に縛られる。開いた時点の写しで足りる。

**列もパレットの候補にする**: 数万件になり、表の名前が列に埋もれる。列は補完の領分である（[[0013-補完の候補生成と識別子の出力スタイル]]）。

**スキーマの読み込みが終わるまでパレットを開かせない**: 接続直後こそコマンドと保存済みクエリを使いたい。開けたうえで、出ていないものがあることを告げるほうがよい。

## 結果

- [[0009-ウィンドウモデルとタイトルバー]] の「タイトルバー中央の `⌘K` 検索ボックスは表示するが操作できない」は本 ADR で覆る。`⌘I` の予約は残る。`trafficLightPosition` と `geometry.ts` には手を触れていない。
- `adr/README.md` の「機能スコープ」表から、保存済みクエリと `⌘K` の「器だけ」の記述が外れる。テーブル定義ビューは器のままである。
- zustand のストアは 7 つになる（`connection` / `tab` / `execution` / `history` / `savedQuery` / `schema` / `ui`）。
- `src/components/palette/` が増える。絞り込みの純粋な関数と、パレットの部品を置く。
- jsdom は `Element.scrollIntoView` を持たないため、`src/test/setup.ts` で何もしないものを補った。`ResizeObserver` などと同じ扱いである（[[0010-テストとリンタの構成]]）。
- 保存済みクエリの SQL は平文で SQLite に残る。履歴と同じ扱いとし、1 件ごとの削除で始末を付けられるようにしてある。設定画面の一括削除は履歴だけを対象とする（保存済みクエリは利用者が意図して作ったものであり、まとめて消す操作は事故のほうが大きい）。
