# ADR 0049: 選んだセルの集計

- ステータス: 承認
- 日付: 2026-09-28

## 状況

利用者は、結果テーブルで選んだセルの件数・合計・平均・最小・最大をフッターに出したいと言っている（issue #77）。合計・平均・最小・最大はフッターの「接続中」の表示と同じ形で切り替え、結果セットを読み切っていないときは値の横に注意の印を出し、値は写せる（選べる）ようにしてほしい、という。

既存の決定と噛み合わせる点が 4 つある。

1. **セル選択は `ResultTable` の中に閉じてある**（CLAUDE.md「結果テーブルのコピー」）。`ui` ストアへ出すと打鍵ごとにアプリ全体が描き直る。
2. **結果は 1,000 行ずつの分割取得である**（[[0003-結果セットのカーソル保持と接続プール]]）。`⌘A` も見出しからの列選択も、読み込み済みの行の範囲しか選ばない。
3. **手元の一部を全体に見せない**（`adr/README.md` の「列のソートは実装しない」、[[0027-結果テーブルの検索]]）。
4. **`NUMBER` は最大 38 桁の 10 進で、文字列で届く**（`Cell` の型）。`number` へ通すと 16 桁目より先が化ける。

決めることは次のとおり。

1. 選択をステータスバーへ届ける経路
2. 何を数値とみなすか、精度をどう守るか、日時の最小・最大をどう扱うか
3. 「読み切っていない」をいつ言うか
4. 集計の種類の切り替えを保存するか

## 決定

### 届けるのは集計の材料だけ。専用の小さなストアを通す

`ResultTable` は選択の状態（`anchor` / `focus`・ドラッグ中か）を外へ出さない。`useSelectionStatsPublisher`（`src/components/results/`）が**集計の材料**（読み込み済みの行・正規化した範囲・カーソルが尽きたか）だけを `src/stores/selectionStats.ts` へ置く。購読するのはステータスバーの `SelectionStatsView` だけである。`ResultTable.tsx` への変更はこのフックを呼ぶ 1 行に留める。

### 集計は表の描画から切り離し、細切れに走らせる

**集計は `ResultTable` の中では走らせない。**全範囲を一度に数える所要時間は、38 桁の `NUMBER` だけの選択で次のとおりだった（bun = JavaScriptCore、WKWebView と同じ処理系）。

| セル数 | 一度に数える | 1 かたまり（1 万セル） |
| --- | --- | --- |
| 2 万 | 約 10ms | 約 3ms |
| 20 万 | 約 80ms | 約 3ms |
| 100 万 | 約 310ms | 約 3ms |

表の描画の中でこれを走らせると、5 万行以上を読んだ後の `⌘A` や列選択、範囲を広げたままのドラッグや `⇧` + 矢印で、動かすたびに表が止まる。`useDeferredValue` では集計そのものは細切れにならず、遅れた値のために表がもう 1 度描き直される。

そのため、公開のフックは状態を持たず材料を置くだけにし、数えるのはステータスバー側の `useSelectionStats` にする。

- **1 万セル（`SLICE_CELLS`）以下の選択はその場で数える。**3ms ほどで終わり、後回しにすると選ぶたびに「集計中」が一瞬出てちらつく。
- **それを超える選択は 1 万セルずつ `setTimeout` で細切れに数える**（`startSlicedStats`）。かたまりの間に描画と打鍵が通るため、**100 万セルでも 1 回に止まるのは約 3ms**で、1 フレーム（16ms）に収まる。選択が変わったら途中で捨てて数え直す。数え終えるまでは件数と注意の印だけを出し、値の欄は「集計中…」にする。前の選択の値を出し続けると別の範囲の値に見える。件数と印は範囲の広さから決まり、値を読まない。
- 見張りは `slicedStats.test.ts` にある。1 回の処理で数えるセルの数が `SLICE_CELLS` を超えないこと、途中で止めたら結果を届けないこと、分けて数えても一度に数えたときと結果が一致することを見る。**所要時間はテストで見張らない**（壁時計の閾値は実行環境の速さで緑と赤が入れ替わる）。上の実測値は手元で測ったものである。

Web Worker は使わない。行を渡すたびに構造化複製が走り、100 万セルの複製そのものが集計より重い。

**選んだセルが 1 つのときは何も出さない。**その値はセルに見えており、単クリックのたびにフッターが動くのは雑音である。結果テーブルが消えたら（タブの切り替え・定義タブ）集計も消す。

### 数値は `bigint` の 10 進で勘定する

数値とみなすのは `kind` が `number` で、文字列が `-?\d+(\.\d+)?` の形のセルだけである（Rust 側は指数表記で送らない。Oracle から実測した）。**読めない文字列は 0 として足さず「数値でない」側へ数える。**

- **合計は丸めない。**38 桁同士を足しても 1 桁も落ちない。`0.1 + 0.2` は `0.3` になる。
- **平均だけは丸める。**選んだ値の小数の桁数に 10 桁を足した桁で、0 から遠い側へ丸める（`1 / 3` で表示が際限なく伸びないため）。
- `BINARY_DOUBLE` / `BINARY_FLOAT` は `inf` / `-inf` / `NaN` の文字列でも届く。非有限の値の扱いは IEEE 754 の足し算に（`inf` と `-inf` が両方あれば `NaN`）、最小と最大は Oracle の並び（`-inf` < 有限 < `inf` < `NaN`）に従う。**有限の値は、画面に出ている最短表現の 10 進を正確に足す。**そのため `BINARY_DOUBLE` の `0.1 + 0.2` は `0.3` になり、Oracle の `SUM`（2 進の浮動小数点で足すため `0.30000000000000004`）とは一致しない。足しているのは利用者が見ている値であり、ずれは 2 進の丸め誤差の側にある。最小と最大は SQL の `MIN` / `MAX` と同じ値を指す。
- **NULL はどの集計にも入れない**（SQL の集計関数と同じ）。数値でないセル（文字列など）も入れない。どちらも件数には入れ、値の `title` に「数値 8 件の合計（NULL 1 件・数値でない 2 件は含みません）」と外した内訳を添える。

**件数は選んだセルの数である。**NULL も文字列も数える。「数値の件数」はツールチップの内訳で言う。

### 日時は最小と最大だけ。数値が無いときに限る

数値が 1 つでもあれば、最小と最大は数値を比べる。数値が無く日時だけなら日時を比べ、**表示はセルの文字列そのまま**にする。合計と平均は出さない。

- 時間帯付きの値（`2024-01-02 03:04:05.000000000 +09:00`）は UTC に直して比べる。
- **時間帯の有る値と無い値が混ざったら出さない。**無いほうの時間帯を小槌は知らず、どちらが先かを決められない。
- `INTERVAL` も `kind` は `datetime` で届くが、時点ではないため比べられない。混ざったら出さない。

**文字列の最小・最大は出さない。**Oracle の照合順序（`NLS_SORT`）と JavaScript の比較は一致せず、`ORDER BY` と違う答えを出すことになる。

### 「読み切っていない」は、選択が最後の行に届いているときに言う

カーソルが尽きておらず、**選択が読み込み済みの最後の行に届いている**ときだけ、値の横に `TriangleAlert` を出し、値と印の `title` に「読み込み済みの 1,000 行だけの合計です。まだ読み込んでいない行は含みません。」を添える。

issue の文面は「結果セットを読み切っていないとき」だが、条件を絞った。最後の行に届かない選択（1,000 行のうち 3〜10 行目など）は、利用者が選んだセルそのものであり、集計に欠けは無い。そこで印を出すと、分割取得の結果ではほぼ常に印が出て、印が本当に要る場面（`⌘A` や列選択で「全体」を選んだつもりのとき）を見分けられなくなる。[[0027-結果テーブルの検索]] が件数の隣に探した範囲を置いたのと同じく、**欠けが起きうる場所にだけ断りを置く。**

印は選択の位置で決まるため、`⌘A` の後にスクロールで続きの行を読むと、**選択は増えないまま印が消える**（選択の最後の行が、もう読み込み済みの最後の行ではなくなる）。このとき集計は選んだ範囲について正しく、欠けは無い。「全体を選んだつもり」は選び直すまで満たされないが、それは結果テーブルの選択そのものの挙動であり、許容する。

**件数には印を付けない。**件数は「選んだセルの数」であり、選択が最後の行に届いていても嘘にはならない。総行数が分からないことは結果ヘッダーの「1,000 行 読み込み済み」が既に言っている。**切り詰められた `CLOB`**（`Cell.truncated`）は文字列であり、どの集計にも入らないため扱いは要らない。

### 切り替えは「接続中」と同じ形のメニュー。保存しない

フッターには「件数 12　合計 ⌃ 1,234.5」と出す。「合計 ⌃」を押すと上へ開くメニューで 4 つから選ぶ。**メニューの項目には 4 つの値をすべて添える**（切り替えずに見比べられる）。`esc` で閉じる（`useEscapeKey`、[[0031-オーバーレイのescとdocumentのスクロール]]）。

ボタンとメニューは**押し下げで焦点を奪わない。**奪うと結果テーブルから焦点が抜け、選択が見えたまま `⌘C` が表へ届かなくなる。

値と件数の数字は `select-text` にして、なぞって写せるようにする。値の欄は幅を 180px に抑えて `…` で省く（メニューの項目の値も同じ）。`BINARY_DOUBLE` の 1e300 は Rust の `f64` の表示で 300 桁を超える 10 進で届き、`NUMBER` の 1e125 も 126 文字になる。そのまま出すと右の「接続中」を画面の外へ押し出す。全文は値の `title` で読め、省いた部分も DOM にあるため三度押しで選べば全文を写せる。コピーのボタンは置かない（issue の求めのとおり）。数値は整数部に 3 桁ごとの `,` を入れる（`formatStatValue`。`toLocaleString` は `number` へ通すため使わない）。

**選んだ種類は保存しない。**ウィンドウを閉じれば合計へ戻る。保存するなら `settings.toml` に項目を足すことになるが、表の表示の設定をまとめて扱う別の作業（3 桁区切りなど）の持ち場と重なる。一度切り替えれば済む操作のために書式を広げるほどの理由は無い。

## 却下した案

**選択を `ui` ストアへ出し、ステータスバーが集計する**: 選択が変わるたびに `ui` ストアの購読者がすべて描き直る。避けたかったことそのものである。

**結果テーブルの中で集計し、`useDeferredValue` で遅らせる**: 最初の実装だった。上に書いたとおり集計は細切れにならず、大きな選択で表が止まる。

**セル数に上限を設け、超えたら件数だけにする**: 止まらないが、列を丸ごと選んで合計を見たいという一番の用途が大きな結果で使えなくなる。

**`number`（倍精度）で足す**: 16 桁を超える `NUMBER` で黙って値が化ける。`0.1 + 0.2` も `0.30000000000000004` になる。

**カーソルが尽きていなければ常に印を出す**: 上に書いたとおり、ほぼ常に印が出て意味を失う。

**合計・平均・最小・最大を 4 つ並べる**: ステータスバーの幅が足りなくなり、接続の表示を押し出す。issue も切り替えを求めている。

**文字列の最小・最大も出す**: 照合順序が Oracle と一致しない。

## 結果

- 数値の書式は、結果テーブルに 3 桁区切りを足す作業と別に書いてある。あちらの設定ができたら `formatStatValue` をそれに揃える。
- `src/components/results/selectionStats.ts` に集計と書式、`src/stores/selectionStats.ts` にストア、`src/components/statusbar/useSelectionStats.ts` と `slicedStats.ts` に細切れの集計、`SelectionStatsView.tsx` に表示がある。
