# ADR 0037: キーバインドの VSCode 準拠と割り当て直し

- ステータス: 承認
- 日付: 2026-09-27

## 状況

小槌のキーは独自に決めてきた（`⌘T` で新しいタブ、`⌘K` でパレット、`⌘E` で実行計画）。利用者は VSCode に慣れており、手が VSCode のキーを先に打つ。困るのは「何も起きない」ことより「別のことが起きる」ことである。

- `⌥⌘C` は VSCode では「開いているファイルのパスをコピー」だが、小槌では**コミット**である。取り消せない。
- `⌥⌘R` は VSCode では「Finder で表示」だが、小槌では**ロールバック**である。
- `⇧⌘E` は VSCode では「エクスプローラーへ移る」だが、小槌では**文を実行する**実測付きの実行計画である（確認は出る）。
- `⌘E` は VSCode では「選択範囲を検索語にする」だが、小槌では `EXPLAIN PLAN` が `PLAN_TABLE` へ書き込み、未コミットの印が立ちうる。

加えて、全体設定から利用者がキーを割り当て直せるようにしたい。決めることは 6 つある。

1. 既定の割り当てをどう VSCode へ寄せるか。VSCode に無い操作をどこへ置くか
2. `⌘K` を前置キーとする 2 打鍵の和音（chord）を扱うか
3. どこまでを割り当て直せるようにするか
4. 保存の形と、既定へ戻す手段
5. 衝突の検出と見せ方
6. macOS で `⌥` が文字を変える問題（ADR 0024）と、打鍵を記録する欄の IME（ADR 0025）

## 決定

### 既定は 3 つの規則で決める

1. **VSCode に同じ操作があれば VSCode の mac 版のキーにする。**
2. **今のキーが VSCode では別の操作であり、小槌の操作が SQL を流すか取り消せないものなら、`⌃⌘` へ移す。**VSCode の mac 版の既定は `⌃⌘` + 英字をほとんど使わない（`⌃⌘F` の全画面だけ）。macOS が持つ `⌃⌘Q`（画面のロック）・`⌃⌘D`（辞書）・`⌃⌘Space`（絵文字）は避ける。
3. **それ以外（小槌の操作がダイアログを開くだけ）は今のキーを残す。**押し間違えても閉じれば済み、変えると今の手を崩すだけになる。

VSCode にあって小槌に無い操作（次のタブ `⇧⌘]` / 前のタブ `⇧⌘[`、ツリーへ移る `⇧⌘E` など）は**今回は足さない**。足すときは表に 1 行を足すだけで済む形にしておく。例外は「名前を付けて保存」1 つである（次節）。

### `⇧⌘S` は「名前を付けて保存」にし、保存済みクエリへの追加は `⌃⌘S` へ移す

草稿では `⇧⌘S` を保存済みクエリへの追加（ADR 0018）のまま残した（規則 3）。承認の際に、VSCode と同じ「名前を付けて保存」に合わせると決めた。`⇧⌘S` は VSCode の手にとって「別のファイルへ保存する」ことであり、名前を尋ねるダイアログが出るという見た目が似ているだけに、保存済みクエリへ積まれていたことに後で気付くことになる。

- 名前を付けて保存は新しい操作として表に 1 行を足し、裁定は `src/mediator/files.ts` の `saveActiveTabAs` に置く。**保存先が決まっていても尋ね、保存した後はそのタブの保存先を新しいファイルへ移す**（VSCode と同じ。以後の `⌘S` が元のファイルを書き換えない）。ダイアログの初期値は今の保存先、無ければタブの名前である。`⌘S`（`saveActiveTab`）とは「決まっている保存先を使うか」だけが違い、`selectActiveSqlTab` を通す関所（定義タブでは何もしない）と書き戻しは 1 つの関数を共有する。
- 保存済みクエリへの追加は `⌃⌘S` へ移す。VSCode の mac 版の既定は `⌃⌘S` を使わず、DB 固有の操作を `⌃⌘` に集める規則 2 と揃う。取り消せない操作ではないが、VSCode に対応する操作が無い DB 固有の操作という点で実行計画・コミット・ロールバックと同じ仲間であり、置き場所の規則を 1 つにしておくほうが覚えやすい。キーを外してパレットだけから引く案も考えたが、ADR 0018 がキーで保存できることを前提にしているため採らない。

### 2 打鍵の和音は扱わない。`⌘K` は空けておく

小槌の操作は、VSCode のキーを潰さずに 1 打鍵の組み合わせだけで置ききれる（上の表）。和音を扱うには、ウィンドウ・CodeMirror・部品の 3 か所にまたがって「前置キーを待っている」状態を持ち、記録の欄も 2 打鍵を受けるように作る必要があり、得るものに対して重い。

**`⌘K` には何も割り当てない。**VSCode の手で `⌘K ⌘C`（行コメント）などを打ったときに、1 打鍵めで小槌の操作が走らないようにするためである。後で和音を扱うときに `⌘K` を取り返す手間も無くなる。

### 割り当て直せるのはコマンドの表の行だけとし、表は CodeMirror の keymap も配る

割り当て直せるのは次の 2 つである。

- ウィンドウ全体のキー（今の `owner: 'window'` の行）
- エディタの中のキーのうち、パレットにも並ぶ 5 つ（実行 3 つ・中止・整形。今の `owner: 'editor'` の行）

`editor` の行は今は表記の文字列だけを持つが、**組み合わせを持つ形に改める。**CodeMirror の keymap はこの 5 つについて表から作り、`any` から打鍵を見て当てる（整形と同じ形。下記）。これで「キーとパレットの一覧が 1 つの表から作られる」（ADR 0035）がエディタの行にも及ぶ。どのキーがどこで振り分けられるか（ウィンドウか CodeMirror か）は変えない。

割り当て直せないもの（**固定のキー**）:

- エディタの検索（`⌘F` / `⌘G` / `⇧⌘G` / `⌥⌘F`）。VSCode と同じであり、CodeMirror の `searchKeymap` が持つ。
- 結果テーブル・スキーマツリー・タブ帯・ペインの区切りの中のキー。焦点のある場所でしか意味を持たず、どれも macOS か VSCode の慣習どおりである。割り当て直せるようにすると判定が 4 つの部品へ散り、`ResultTable.tsx` には並行する作業もある。
- 編集の基本（`⌘Z` / `⇧⌘Z` / `⌘X` / `⌘C` / `⌘V` / `⌘A`）と、macOS・メニューが持つもの（`⌘Q` / `⌘H` / `⌘M` / `⌘,`）。

固定のキーは表示と衝突の判定のために一覧（`FIXED_KEYS`）として持つ。記録の欄はこれらを受け付けず、設定画面には参考として並べる。

### 振り分けは修飾の完全一致にし、`⌥` の付いた英数字は `event.code` で読む

組み合わせは `⌘` / `⌃` / `⌥` / `⇧` の 4 つを明示して持つ。**押された修飾と書いた修飾が完全に一致したときだけ当てる。**ADR 0035 の補足にある「書いていない修飾が押されていても当たる（`⌃⌘S` が保存に当たる）」はやめる。利用者が組み合わせを自由に決められるようになると、緩い一致では `⌘S` の行が `⌃⌘S` を奪い、衝突の判定も「同じ組み合わせか」で決まらなくなる。修飾の数で勝ちを決める `specificity` も要らなくなる。

キーは `event.key` から読むが、**`⌥` が押されていて英字・数字が別の文字へ化けているときは `event.code`（`KeyF` → `f`）から読む。**ADR 0024 が整形の `⇧⌥F` だけに施した手当てを、全部の組み合わせへ広げる形である。`event.key` を先に見るのは、Dvorak のように物理の位置と文字がずれる配列で `⌘S` を `S` の文字の位置で効かせるためである。判定は 1 つの純粋な関数（`matchesChord`）に置き、ウィンドウの振り分けと CodeMirror の `any` の両方がこれを通す。`isFormatShortcut` はこれに置き換わる。

### `settings.toml` には既定との差分だけを持つ

```toml
[keybindings]
palette = "cmd+shift+p"
commit = ""            # 外した
```

- 鍵はコマンドの表の `id`、値は VSCode の `keybindings.json` と同じ書き方の文字列。空文字は「キーを外した」。
- **既定と同じ行は書かない。**既定を後の版で変えたとき、触っていない利用者には新しい既定が届く。
- 知らない `id` は読み捨てずにそのまま書き戻す（新しい版で足した行を古い版で開いて保存しても消えない）。
- Rust 側は中身を解釈しない（`AppearanceSettings` と同じ）。項目には `#[serde(default)]` を付け、**値が文字列でない行はその行だけ捨てる**（寛容な読み取り）。1 行の書き損じで表ごと読めなくなり、テーマまで既定へ戻ることを避ける。
- フロントエンドで読めなかった行（`cmd+shift+` のような書き損じ）は、その操作だけ既定のキーで動かし、設定画面に「読めなかった割り当て」として出す。**設定をどう読み損ねても、既定のキーで起動できる。**

### 既定へ戻す手段は 2 つ

行ごとの「既定に戻す」（差分からその行を消す）と、「すべて既定に戻す」（`[keybindings]` を空にする）。

### 衝突は記録の時点で断り、読み込みの時点では見せる

- **記録の時点**: 他の操作が持っている組み合わせ・固定のキー・修飾の無い打鍵（`F1`〜`F20` を除く）は受け付けず、欄の下に「〇〇 に割り当て済みです」と出す。黙って相手から外すことはしない。
- **読み込みの時点**: 手で書いた `settings.toml` や、後の版で既定が変わったことで、同じ組み合わせが 2 つの操作に付くことはある。このときは**利用者が付けたほうが勝ち**、同じ立場なら表の上の行が勝つ。負けた側はキーが無い扱いになり、設定画面の該当行に「△△ と重なっているため効きません」と `--warn` の色で出す。起動は止めない。

### 打鍵を記録する欄

記録の欄は `<button>` で、押すと記録の状態に入り、次の 1 打鍵を組み合わせとして受ける。

- **先頭で `isComposingKey` を見て、変換中なら何もしない**（ADR 0025）。監査の表に 1 行を足す。
- 修飾キーだけの打鍵（`Meta` / `Shift` など）は待ち続ける。
- 受けた打鍵は `preventDefault()` する。ウィンドウの振り分けは `event.defaultPrevented` を見て飛ばすので、記録中に `⌘W` を打ってもタブは閉じない。
- `esc` は記録の取り消しである。`preventDefault()` しておけば `useEscapeKey` は先頭で `defaultPrevented` を見て飛ばすため、設定画面ごと閉じることはない（ADR 0031 の順序のまま）。
- `⌘,` / `⌘Q` / `⌘H` はメニューと macOS が先に取るため、記録の欄まで届かない。

### ネイティブのメニューへの申し送り

並行する作業がメニューバーに「設定…」（`⌘,`）を足す。メニューのアクセラレータはウェブビューより先に打鍵を取るため、**メニューには表のキー（`⌘N` / `⌘W` など）をアクセラレータとして付けない。**付けると、割り当て直した後もメニューが古いキーを握り続ける。

### 操作の ID から今のキーの表記を引ける

`shortcutLabelFor(id, bindings)` を用意する。パレットの表記もこれを通す。後で右クリックのメニューにキーを添えるときもこれを使う。

## 理由

- **VSCode に寄せるのは、利用者の手がすでに VSCode のキーを覚えているからである。**小槌独自のキーは、覚えてもらう費用を利用者に払わせ続ける。
- **規則 2 で `⌃⌘` へ移すのは、押し間違えの害が操作によって違うからである。**VSCode の手が打ったキーで取り消せない操作が走ることは、何も起きないことよりはるかに悪い。
- **規則 3 で残すのは、ダイアログを開くだけの操作の押し間違えは閉じれば済み、変える費用のほうが大きいからである。**
- **割り当て直せる範囲を表の行に絞るのは、ADR 0035 の「1 つの表から配る」を崩さずに済む範囲だからである。**部品の中のキーまで広げると、判定と既定が部品ごとに散る。
- **差分だけを持つのは、既定の改善を利用者へ届けるためである。**全部を書き出すと、ある版の既定がその利用者のところで凍る。

## 却下した案

**`⌘K` を前置キーとする和音を扱う**: VSCode の `⌘K ⌘S` などと形が揃うが、前置キーを待つ状態がウィンドウ・CodeMirror・部品にまたがる。小槌の操作は 1 打鍵で置ききれるため、今は払う理由が無い。

**DB 固有の操作をファンクションキーへ置く（SQL Developer の `F5` スクリプト実行・`F10` 実行計画・`F11` コミット・`F12` ロールバック）**: DB クライアントの慣習としては通りがよいが、mac のノートでは `fn` を押さないと音量や明るさの操作になる。

**すべてのキー（部品の中のキーを含む）を割り当て直せるようにする**: 自由度は上がるが、焦点のある場所ごとに判定と既定を持つことになり、表が 1 つである利点が消える。部品の中のキーはすでに慣習どおりであり、変えたい理由が薄い。

**衝突した組み合わせを記録したら、相手から黙って外す**: 手数は減るが、気付かないうちに別の操作のキーが消える。

**`settings.toml` に全部の割り当てを書き出す**: 読めば全体が分かるが、既定を後の版で直しても届かなくなる。

## 実装の補足（2026-09-27）

- **置き場所**: 組み合わせの読み書きと照合は `src/keybindings/chord.ts`（`parseChord` / `serializeChord` / `formatChord` / `chordFromPress` / `matchesChord`）、既定と差分の解決・記録の判定・固定のキーは `src/keybindings/bindings.ts`（`resolveKeybindings` / `checkRecordedChord` / `withOverride` / `FIXED_KEYS` / `shortcutLabelFor`）に置いた。どちらも React にも仲介者にも依存しない。
- **表の行の形**: `key: { owner, chord | label }` を `scope: 'window' | 'editor'` と `defaultKey: Chord | null` に改めた。`editor` の行も組み合わせを持つ。エディタが振り分ける `id` の一覧は `src/components/editor/editorKeys.ts` の `EDITOR_ACTIONS` にあり、表の `editor` の行と一致することを `mediator/commands.test.ts` が見張る（部品は仲介者の値を import しないため、`id` の写しを持つ）。
- **解決は `App.tsx` で 1 度だけ行い、React の context（`src/keybindings/context.ts`）で配る。**解決にはコマンドの表（仲介者の値）が要り、部品は仲介者の値を import しないためである。ウィンドウの振り分け・パレット・エディタ・設定画面はどれもこの 1 つの結果を読む。
- **ボタンやメニューに添えたキーの表記も割り当てから引く**（`useShortcutLabel`）。実行ボタンのメニュー・ステータスバーのコミット / ロールバック・タイトルバーの検索欄・切断できない旨のダイアログの 4 か所に表記が手で書かれており、割り当て直すと食い違うためである。
- **表記の順**: 修飾は macOS のメニューと同じ `⌃⌥⇧⌘` の順に並べる。そのため整形は画面では `⌥⇧F` と出る（文書の `⇧⌥F` と同じキーである）。
- **設定画面**: `SettingsPanel` にキー割り当ての欄（`KeybindingSettings`）を足し、表は `commands` で受け取る。`⌘,` は表に無く、`FIXED_KEYS` に「設定を開く（メニュー）」として載るだけである。

## 結果

- 既定のキーが VSCode の mac 版に揃い、VSCode の手で打ったキーで取り消せない操作（コミット・ロールバック・文を実行する実行計画）が走らなくなった。
- 設定画面から、ウィンドウ全体とエディタの 22 の操作のキーを割り当て直せる。`settings.toml` には差分だけが残る。
- `⇧⌥F` の `event.code` の手当て（ADR 0024）が全部の組み合わせに及ぶ。
- ADR 0035 の補足にある緩い一致（書いていない修飾が押されていても当たる）と、修飾の数で勝ちを決める規則は廃した。
- ADR 0018 の `⌘K`（パレット）と `⇧⌘S`（保存済みクエリへの追加）は、それぞれ `⇧⌘P` と `⌃⌘S` へ移った。
