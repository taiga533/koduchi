# ADR 0042: 自動アップデート

- ステータス: 承認
- 日付: 2026-09-27
- [[0011-cicdとリリース配布]] の「自動アップデータは入れない」を置き換える

## 状況

小槌は GitHub の下書きリリースに dmg を添付し、人間が公開して配っている（[[0011-cicdとリリース配布]]）。新しい版を入れるには、利用者がリリースのページを見にいき、dmg を開いて入れ替えるしかない。利用者は、アプリの中で新しい版を知り、そのまま入れ替えたいと言っている。

[[0011-cicdとリリース配布]] は Tauri の updater を却下した。理由は 2 つである。

1. `latest.json` を「常に最新を指す URL」に置く必要があり、公開後に差し替えられないイミュータブルリリースと噛み合わない。
2. 未署名のアプリを自動で更新すると、Gatekeeper と相性が悪い。

2 つめは [[0028-配布物の署名と公証]] で解けた。配布物は Developer ID で署名し、公証してある。1 つめは、GitHub の `releases/latest/download/<アセット名>` を使えば解ける。この URL は**公開済みの最新のリリース**のアセットへ転送し、下書きは指さない。リリースごとに `latest.json` を添付すれば、どのリリースも差し替えずに済む。

決めることは次の 5 つである。

1. いつ新しい版を確かめるか
2. 見つかったときにどう入れ替えるか
3. 再起動と未コミットの変更をどう両立させるか
4. 更新用の成果物をどう公証するか
5. 署名の鍵をどう扱うか

## 決定

### 確認先は公開済みの最新リリースの latest.json とする

確認先は次の 1 つだけで、`tauri.conf.json` の `plugins.updater.endpoints` に書く。

```
https://github.com/taiga533/koduchi/releases/latest/download/latest.json
```

`latest.json` は `scripts/generate-latest-json.sh` がリリースの CI で組み立て、dmg と一緒に下書きへ添付する。人間が下書きを公開した時点で、既に入っている小槌がその版を見つける。**公開ボタンが配布の最後の関所である点は変わらない。**

対象は Apple Silicon の macOS だけなので、`platforms` は `darwin-aarch64` の 1 つである。リリースノートは `latest.json` に入れない。下書きの本文は公開の前に人間が書き直すため、入れると食い違う。ダイアログからは版ごとのリリースのページを開く。

### 起動時に確かめ、メニューとパレットからも確かめられる

確かめる契機は 2 つある。

| 契機 | 最新のとき | 失敗したとき |
| --- | --- | --- |
| 起動時 | 黙っている | 黙っている |
| 手で押したとき | 「最新の版です」 | 文言を出す |

起動時の確認は**最初のウィンドウ（ラベル `main`）でだけ**走らせる。接続ごとに開くウィンドウ（[[0009-ウィンドウモデルとタイトルバー]]）で毎回問い合わせると、同じ版を何度も勧めるためである。`tauri dev` では走らせない。動いているのは `.app` ではなく、入れ替える先が無い。判定は `src/mediator/update.ts` の `shouldCheckOnLaunch` にある。

手で押す入口は 2 つある。アプリメニューの「アップデートを確認…」（「〜について」の直後、[[0040-メニューバーからコマンドを走らせる]]）とコマンドパレットである。どちらもコマンドの表の `check-update` を通る。**繋がっていなくても押せる。**キーは割り当てない。

### 尋ねてから取得し、そのまま再起動する

新しい版が見つかったら、新旧の版を出して尋ねる。「ダウンロードして再起動」を押すと取得して入れ替え、続けて再起動に進む。承諾は 1 回だけで、入れ替えた後にもう一度は尋ねない。**取得を裏で勝手に始めない。**利用者の知らない間に `/Applications` の中身を書き換えないためである。

取得と再起動の最中はダイアログを閉じられない（`esc` も効かない）。閉じても止まらず、再起動は後から関所の確認として現れるためである。段階は `src/stores/update.ts` が持ち、遷移は `docs/state/update.d2` にある。ダイアログを出すかは段階と別の `dialogOpen` で持つ。起動時の確認は、段階は動いても新しい版が見つかるまで何も出さないためである。

### 再起動はアプリの終了と同じ関所を通す

`AppHandle::restart` を直に呼ばない。呼ぶと各ウィンドウの未コミットの関所（[[0012-トランザクション制御]]）を飛ばし、未コミットの変更が暗黙のロールバックで消える。

代わりに、再起動を**予約**してから各ウィンドウへ閉じる要求を送る（`restart_for_update`）。ここから先はメニューの「終了」と同じ道である。各ウィンドウが関所を通って閉じ、最後のウィンドウが閉じたときに `RunEvent::ExitRequested` が来る。予約があれば終了を止め、`request_restart` で起ち上げ直す。判断は `src-tauri/src/updater.rs` の `decide_exit` にある。

どこかのウィンドウで「やめる」を選ばれたら、そのウィンドウは予約を取り消す（`cancel_update_restart`）。取り消さないと、後で普通に終了したときに思いがけず起ち上がり直す。再起動を押したウィンドウは「新しい版を入れました」へ戻り、「再起動」を押し直せる。入れ替えは済んでいるので、再起動しなくても次に起動したときから新しい版になる。

関所の問いかけは閉じるときと同じ文言（`CLOSE_WORDING`）のままにする。再起動を押していないウィンドウは、自分が再起動のために閉じられているとは知らない。

### 更新用の .app は別に公証へ出さない

更新用の成果物は `.app` を固めた `tar.gz` である。これを別に公証へ出すと提出が 2 回になり、`.app` の公証待ちに 49 分かかった実測もある（[[0028-配布物の署名と公証]]）。出さずに済むのは、`tar.gz` の中の `.app` が dmg の中の `.app` と**同じ実行ファイル**だからである。notary は dmg を展開して中の `.app` の cdhash まで記録するため、同じ cdhash の `.app` にもその記録が当たる。

`tar.gz` の `.app` には staple が付かない。Gatekeeper はオンラインで記録を照合する。

同じ実行ファイルであることは前提なので、リリースの CI が cdhash の一致を確かめ、`spctl` を当ててから添付する。食い違えば赤にして下書きを作らない。

### 署名の鍵は minisign の組を 1 つ持つ

updater は Apple の署名とは別に、minisign の鍵で成果物を検証する。公開鍵は `tauri.conf.json` の `plugins.updater.pubkey` に書く。秘密鍵とそのパスワードは GitHub の secret にだけ置き、リポジトリには置かない。secret の名前は `TAURI_SIGNING_PRIVATE_KEY` と `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` である。

**秘密鍵を失うと、既に配った版は二度と自動で更新できない。**公開鍵は配った `.app` に焼き込まれており、新しい鍵の署名を受け付けないためである。秘密鍵は secret とは別に、利用者の手元にも控えておく。

公開鍵と秘密鍵が組でないと、配った版はどれも更新の検証に落ちる。気付くのは次の版を出したときである。そのためリリースの CI は、添付する前に `tar.gz` の署名を `tauri.conf.json` の公開鍵で確かめる。公開鍵が minisign の公開鍵として読めることは `src-tauri/tests/updater_config.rs` が見張る。

`bundle.createUpdaterArtifacts` は `tauri.conf.json` に書かず、リリースの CI が `--config` で足す。書くと、手元の `bun run tauri build` まで秘密鍵を要求するためである。

## 却下した案

**`tauri-apps/tauri-action` へ移る**: [[0011-cicdとリリース配布]] は updater を入れるときの移行を見込んでいた。移らないのは、今の `release.yml` の「署名だけしてビルド → dmg を 1 回公証 → 検査 → 添付」の順を崩すためである。`tauri-action` はビルドの直後に成果物を添付するため、公証と検査を添付の前に挟めない（[[0028-配布物の署名と公証]]）。足した手順は `tar.gz` の名付け・検査・`latest.json` の組み立て・添付の 4 つであり、YAML にそのまま並べて読める。

**`latest.json` を GitHub Pages や gist に置く**: 置き場所が 1 つ増え、公開ボタンとは別に更新する手順が要る。書き忘れると、公開したのに誰も更新しない。

**裏で取得し、終了時に入れ替える**: 利用者の知らない間に `.app` を書き換える。取得の途中で終了されたときの扱いも要る。

**知らせるだけにして dmg へ誘導する**: 今の手順と変わらず、要望に応えない。

**更新用の .app も別に公証して staple する**: 提出が 2 回になり、staple の後で `tar.gz` を作り直して minisign で署名し直す手順も要る。cdhash が一致する限り、得るものは「オフラインでも照合できる」ことだけである。

## 結果

- リリースに添付するものが 3 つになった（dmg・`koduchi_<版>_aarch64.app.tar.gz`・`latest.json`）。`release.yml` は `--bundles app,dmg` で作る。
- リリースの CI に secret が 2 つ増えた。1 つでも欠けるとビルドが落ちる。
- リリースの CI が Homebrew から minisign を入れる。版は固定していない。検証にしか使わないためである。
- `tauri-plugin-updater` は 2.12.0 を使う。2.13 は tauri 2.12 を要求するため、tauri を上げるときに併せて上げる。
- アプリメニューに「アップデートを確認…」が増えた。
- ウィンドウを閉じる関所は `src/mediator/update.ts` の `confirmWindowClose` を通るようになった。中身は `resolvePendingTransaction` に予約の取り消しを足したものである。
- 公開した版は、起動するたびに GitHub へ 1 回問い合わせる。送るのは版と対象の OS・CPU だけである。
