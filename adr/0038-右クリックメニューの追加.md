# ADR 0038: 右クリックメニューの追加

- ステータス: 草稿（承認待ち）
- 日付: 2026-09-27

## 状況

小槌の右クリックメニューは 2 か所にしかない。スキーマツリー（`SchemaTreeContextMenu.tsx`、ADR 0020・0022）と結果テーブル（`ResultContextMenu.tsx`）である。利用者は「右クリックしても何も出ない、あるいはウェブビューの既定のメニューが出る」場所が多いと感じている。

コードを見て確かめた事実は次のとおりである。

- **ウェブビューの既定のメニューを止めている箇所は 1 つも無い。**`contextmenu` を受けているのは上の 2 部品だけである。WKWebView は、文字の上では「調べる / 翻訳 / コピー / 貼り付け / スペル / サービス」を、何も無い場所では「再読み込み」を出す（開発ビルドでは「要素の詳細を表示」も）。**「再読み込み」を押すとウェブビューが読み直され、フロントエンドの状態（接続・タブ・結果・未コミットの表示）だけが消える。**Rust 側のプールとトランザクションは残るため、画面と実体が食い違う。
- 既存の 2 つのメニューは見た目も `MenuItem` も写しである。違いは結果テーブルの側だけが焦点を奪わないこと（issue #53）と、ツリーの側だけが見出しを持つことの 2 点。どちらも**画面端での位置の補正を持たない**（下端や右端で右クリックするとメニューがウィンドウの外へ切れる）。
- タブ帯には右クリックのメニューが無い。ADR 0032 は「名前を変える」をメニューに置く案を、「1 項目のためにメニューの仕組みを持ち込むと『閉じる』『他を閉じる』『右側を閉じる』が付いてくる。メニューを作るかどうかは別に決める」として退けている。この ADR がその「別に決める」にあたる。
- 裁定の側で、今あるもののうち右クリックから呼べるもの: `closeTabAndRelease(tabId)` / `putSqlIntoEditor(sql)` / `openSqlInNewTab(sql)` / `openDefinitionTab(target)` / `saveActiveTab()` / `saveActiveTabAs()`（どちらも選んでいるタブだけ）/ コマンドの表の各行（`runCommand`）。キーの表記は `useShortcutLabel(id)`（ADR 0037）で引ける。

## 提案

### 足す場所

**判断**の列: ◎ 足すことを勧める / ○ 足してよい / ✕ 足さない。

| # | 場所 | 今の右クリック | 足す項目 | 理由 | 既存の入口との関係 | 判断 |
|---|---|---|---|---|---|---|
| 1 | 画面全体（下の自前メニューの無い所） | ウェブビューの既定（何も無い所では「再読み込み」） | **既定のメニューを止める**。ただし入力欄・`<textarea>`・CodeMirror の本文・文字を選んでいる最中は止めない | 「再読み込み」は画面と実体を食い違わせる。止める条件を「編集できる要素か、選択があるか」に絞れば、コピー・貼り付け・調べる・スペルは失われない | 新しい入口は作らない | ◎ |
| 2 | タブ帯のタブ | 既定のメニュー | 閉じる（`⌘W`）/ 他のタブを閉じる / 右側のタブを閉じる / ─ / 名前を変更（`F2`、`canRenameTab` のときだけ）/ ─ / 保存（`⌘S`）/ 名前を付けて保存（`⇧⌘S`）（SQL タブだけ）/ ファイルのパスをコピー（`filePath` があるときだけ） | ADR 0032 が予告した一式。ブラウザと VSCode でタブの右クリックに期待されるものが揃う | 閉じるは 1 枚ずつ `closeTabAndRelease` を通す（関所は 1 つのまま。未保存があれば 1 枚ずつ尋ねる）。名前の変更は `F2` と同じ編集開始を呼ぶ。保存は `saveActiveTab` を**タブ ID を受ける形へ広げ**、`⌘S` はそれに今のタブを渡す | ◎ |
| 3 | 履歴の行 | 既定のメニュー | エディタへ入れる / 新しいタブで開く / SQL をコピー / ─ / 削除 | 1 行目しか見えない一覧から全文をコピーする道が無い。今のタブを上書きせずに開く道も無い | 入れるは行の単クリック（`putSqlIntoEditor`）、新しいタブは `openSqlInNewTab`、削除は `✕` と同じ `remove` | ◎ |
| 4 | 保存済みクエリの行 | 既定のメニュー | エディタへ入れる / 新しいタブで開く / SQL をコピー / ─ / 名前を変更 / 削除 | 履歴と同じ。作りを揃える（`SavedQueryList` は履歴に揃えると決めてある） | 名前の変更は鉛筆と同じ行内の編集を始める。削除は `✕` と同じ | ◎ |
| 5 | 結果テーブルの見出し | 既定のメニュー | 列名をコピー / この列をコピー / 列幅を内容に合わせる | 列名だけが欲しい場面は多く、今は見出しから取れない | 「この列をコピー」はセルのメニューと同じ組み立て、幅合わせは見出しのダブルクリックと同じ `autoFitWidth` | ◎ |
| 6 | 結果テーブルの行番号 | 既定のメニュー | セルと同じメニュー（右クリックした行が選択の外なら、先にその行全体を選ぶ） | 行番号の単クリックで行を選べるのに、その場でコピーへ進めない | セルのメニューそのもの | ○ |
| 7 | メッセージタブのログの 1 件 | 既定のメニュー（文字の上ならコピー、他は再読み込み） | SQL をコピー / 新しいタブで開く / エラーをコピー（エラーがあるときだけ）。**文字を選んでいる最中は既定のメニューに任せる**（#1 の条件） | スクリプト実行で失敗した 1 文を取り出して直す道が無い | エラーのコピーは `ErrorCopyButton` と同じ文字列を写す（手を加えない）。新しいタブは `openSqlInNewTab` | ○ |
| 8 | 定義タブの列・制約・索引の行 | 既定のメニュー | 名前をコピー / この行をコピー | 列名 1 つが欲しいのに、今は内訳を丸ごと写して削るしかない | 行の写し方は `definitionCopy.ts` と同じ規則（タブ区切り、コメントの欄は画面に出ているときだけ）。内訳まるごとのコピーは右上のボタンのまま | ○ |
| 9 | ソース検索の当たりの行 | 既定のメニュー | オブジェクト名をコピー / 当たった行をコピー | 見つけた処理の名前をエディタやチケットへ写す道が無い | 新しい裁定は無い | ○ |
| 10 | セッションとロックの行 | 既定のメニュー | `SID,SERIAL#` をコピー / 行をコピー | kill を DBA に頼むときに番号を写すことが多い | **kill はメニューに入れない**（下の「足さない場所」） | ○ |

### 足さない場所

| 場所 | 足さない理由 |
|---|---|
| エディタの本文（CodeMirror） | **既定のメニューを奪わない。**奪うと「調べる」「翻訳」「スペルと文法」「サービス」「作文ツール」を失い、貼り付けを作り直すにはクリップボードの読み取り権限まで要る。自前で出したい項目（実行・選択範囲を実行・整形）はどれもキーとパレットに既にあり、右クリックでしか届かない操作にはならない。なお macOS の再変換はメニューではなくキー（`⌃⇧R` / 英数・かなの 2 度押し）で行うため、どちらにしても失われない |
| DDL の内訳・セルの詳細パネル・入力欄 | 文字を選んで写す場所であり、既定のメニューがそのまま役に立つ（#1 の条件で残る） |
| タブ帯の何も無い所 | 「新しいタブ」「ファイルを開く」は `＋` とキーで足りる。#1 で既定のメニュー（再読み込み）だけは止まる |
| スキーマツリーの見出し行・種別の束 | 既存のメニューが既に出ている（ADR 0020）。項目は変えない |
| ステータスバー・タイトルバー・サイドバーの空き・分割線・設定画面・各ダイアログ・パレット | 並べる操作が無い。置けば押せる所が増えるだけで、左クリックの入口と二重になる |
| セッションの kill | 取り返しの付かない操作を「押したことが分かりにくい」右クリックへ置かない（ADR 0020 が `SELECT` の実行を右クリックに置かなかったのと同じ考え）。関所 3 つは行のボタンの先にだけある |
| ソース検索の「定義を開く」「エディタへ挿入」 | 当たりからの動線は ADR 0021 で決めていない。種別が `SourceKind`（本体を含む）で、`ObjectKind` の定義タブへそのまま繋がらない。求められたら別に決める |
| タブの「Finder で表示」 | 既存の操作ではない（`opener` の `reveal_item_in_dir` の権限を新たに足すことになる）。パスのコピーで代える |

### 共通の部品にする

`src/components/menu/ContextMenu.tsx` に 1 つ作り、既存の 2 つもこれへ寄せる。

- 項目は `{ label, icon, onSelect, shortcut? }` と区切り線の並びで受ける。**キーの表記は `useShortcutLabel(id)` で引いて右端に添える**（ADR 0037。手で書かない）。
- **焦点を奪わない作りを標準にする**（結果テーブルの `keepFocus`）。ツリーのメニューは今は奪うが、奪わないほうへ揃えても困らない（閉じた後も焦点がツリーの行に残り、`↑` / `↓` がそのまま効く）。**これはツリーの振る舞いの小さな変更**であり、嫌なら部品に切り替えの印を持たせて今のまま残す。
- `esc` は `useEscapeKey`（ADR 0031）。暗幕の押し下げと右クリックで閉じる。
- **画面端での位置の補正を足す。**位置の計算は純粋な関数（`placeMenu(point, menuSize, viewport)`）に置き、はみ出すときは左上ではなく右下を押した点へ合わせる。既存の 2 つにも効く（今は切れている）。
- 見出し（ツリーの対象名）は任意の欄として持つ。

### 既定のメニューを止める仕組み

`src/input/nativeContextMenu.ts` に「既定のメニューを残すか」の純粋な関数を置き、`window` の `contextmenu` で 1 度だけ張る。残すのは、押した要素が編集できる（`input` / `textarea` / `contenteditable`）か、文字を選んでいる最中のときだけ。自前のメニューを出す部品は今までどおり自分で `preventDefault` する。

### 仲介者

右クリックは**入口を足すだけ**で、裁定は既存のものを呼ぶ。例外は 2 つで、どちらも mediator-design の手順を踏んで `src/mediator/tabs.ts` / `files.ts` に置く。

- 「他のタブを閉じる」「右側のタブを閉じる」: 対象の ID の並びを純粋な関数で決め、1 枚ずつ `closeTabAndRelease` を `await` する。途中で「キャンセル」されたらそこで止める。
- 保存のタブ ID 化: `saveActiveTab` / `saveActiveTabAs` を `saveTab(tabId)` / `saveTabAs(tabId)` の薄い包みにする（コマンドの表の行は変えない）。

### 操作の表への追記

- `CLAUDE.md` のスキーマツリーの表: 変更なし。
- `ResultTable.tsx` 冒頭の表に「見出しを右クリック」と「行番号を右クリック」の 2 行を足す。
- タブ帯・履歴・保存済みクエリには操作の表が無い。`CLAUDE.md` の「タブ帯の並べ替えと閉じる」段落に右クリックの 1 文を足す。
