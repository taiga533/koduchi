# ADR 0039: 文末のセミコロンの扱い

- ステータス: 承認
- 日付: 2026-09-27

## 状況

セミコロンで終わる SQL を複数並べて実行すると `ORA-00933`（23ai では `ORA-03048`）になる（issue #55）。

経路ごとに調べると、Oracle へ渡る本文が経路によって違っていた。

| 経路                         | 渡っていた本文                         | 結果                                                     |
| ---------------------------- | -------------------------------------- | -------------------------------------------------------- |
| `⌘⏎`（カーソル位置の文）     | `splitStatements` の本文（`;` 抜き）   | SQL は通る                                               |
| `⌥⌘⏎`（スクリプト実行）      | 同上                                   | SQL は通る                                               |
| `⇧⌘⏎`（選択範囲）            | **選択した文字列そのまま**             | `;` と複数の文が届き、**issue #55 の正体**               |
| `⌘E` / `⇧⌘E`（選択があるとき） | **選択した文字列そのまま**           | 同上                                                     |

加えて、`splitStatements` は PL/SQL 単位からも `END;` のセミコロンを落としていた。Oracle で確かめると次のとおりである。

| 本文                                              | 結果                                                     |
| ------------------------------------------------- | -------------------------------------------------------- |
| `select 1 from dual;`                             | `ORA-03048`（古い版では `ORA-00911` / `ORA-00933`）      |
| `begin null; end`                                 | `PLS-00103`                                              |
| `create or replace procedure p is begin null; end` | **成功を返すが、`USER_ERRORS` に 1 件載った無効なオブジェクトができる** |
| `begin null; end;` / `... end;`                    | 通る                                                     |

最後の組み合わせが最も悪い。実行した時点では「完了しました」と出て、呼んだときに初めて壊れていると分かる。

## 決定

### Oracle へ渡す本文は `splitStatements` の `text` 1 つで決める

`SqlStatement.text` を「そのまま Oracle へ渡せる本文」と定める。**通常の SQL は末尾の `;` を落とし、PL/SQL 単位は `END;` の `;` まで含める。**`start` / `end` もそれに合わせる。

置き場所を文の切り出しにしたのは、**`;` が文の一部か区切りかを知っているのがここだけ**だからである。`BEGIN…END;` の入れ子を数えて「ここで切ってよい」と決めた瞬間に、その `;` が PL/SQL の構文か SQL*Plus 流の区切りかも分かっている。

退けた案は次の 2 つ。

- **実行の直前（仲介者）で `;` を落とす。**末尾の `;` を落とすだけなら書けるが、PL/SQL かどうかを見分けるには切り出しと同じ走査がもう 1 本要る。2 本あれば食い違う（ADR 0024 が `scan.ts` を 1 つにしたのと同じ理由）。
- **Rust 側で落とす。**同じ理由に加え、Rust は文を切らない（ADR README「SQL の実行単位」）。1 本の文字列に複数の文が入って届いたら、Rust は直しようがない。

ADR 0034 は「クライアント側で SQL を読んで種別を決めない」と決めている。ここはそれに当たらない。0034 は Oracle が種別を教えてくれるから読まないのであって、`;` の要否は Oracle が文を受け取る**前に**決めなければならない。そして PL/SQL の見分けは、文を切るために切り出しがもともと持っている。

### 選択範囲も同じ切り出しを通す

`⇧⌘⏎` は選択範囲を `splitStatements` に掛ける。

- 1 文なら、その本文を実行する。
- **複数の文なら、スクリプト実行（`⌥⌘⏎`）と同じく順に実行する。**Oracle は 1 度に 1 文しか受け取らないため、まとめて渡す道は無い。止まり方・履歴・バインド変数の尋ね方はスクリプト実行の決めごとをそのまま使う。
- 空白とコメントだけなら何もしない。

`⌘E` / `⇧⌘E` は 1 文にしか取れないため、選択に複数の文があれば**最初の 1 文**の実行計画を取る。

## 影響

- どの経路でも、渡す本文は `splitStatements` の `text` になった。PL/SQL の見立ての誤りは、どの経路でも同じ形で現れる。
- `CREATE [OR REPLACE] PACKAGE`（仕様）と `CREATE TYPE ... AS OBJECT` は `BEGIN` を持たないため、切り出しが文の終わりを見つけられない。この ADR より前からの制限であり、ここでは扱っていない。
- 統合テスト（`src-tauri/tests/oracle.rs`）は、切り出しの出す形がそのまま通ること、`;` 付きの SQL と `;` 抜きの PL/SQL が拒まれることを見張る。
