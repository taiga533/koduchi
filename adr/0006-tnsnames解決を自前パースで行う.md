# ADR 0006: tnsnames.ora の解決を自前パースで行う

- ステータス: 承認
- 日付: 2026-08-30

## 状況

Oracle の接続先指定には EZConnect（`host:port/service_name`）、TNS エイリアス、SID の 3 方式がある。TNS エイリアスに対応する場合、利用者に `tnsnames.ora` の置かれたディレクトリを Finder で選ばせ、そこからエイリアスをプルダウンで提示したい。

ここで `oracle` crate の API に制約がある。docs.rs で確認した事実:

- `InitParams::oracle_client_config_dir()` が `TNS_ADMIN` 相当の設定にあたる。
- `init()` は "only once per process" であり、2 回目以降の呼び出しでは "subsequent parameter values have no effect" と明記されている。
- `Connector` 側に接続ごとの `config_dir` / `TNS_ADMIN` 設定手段は**存在しない**。

つまり素直に実装すると「TNS_ADMIN はアプリ全体で 1 つ、変更にはアプリの再起動が必要」になる。1 接続 = 1 ウィンドウで、ウィンドウごとに別の `tnsnames.ora` を使いたい場合に破綻する。

## 決定

**`tnsnames.ora` を自前でパースし、得られた接続記述子をそのまま接続文字列として `oracle` crate に渡す。**

Oracle は次の形式を接続文字列として直接受け付けるため、ODPI-C の `TNS_ADMIN` に一切依存しなくなる。

```
(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=...)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=...)))
```

パーサの対応範囲:

- 括弧構文の再帰パース
- `#` コメント
- 複数エントリ
- エイリアスのカンマ区切り別名
- 複数 `ADDRESS`（フェイルオーバー構成）
- `DESCRIPTION_LIST`

**`IFILE` ディレクティブは非対応**とし、検出したら「一部のエントリを読み込めませんでした」と表示する。

接続フォームには、デザインの「名前」欄の下に接続方式のセグメントコントロール（EZConnect / TNS）を 1 行追加する。TNS を選ぶと、ホスト / ポート / データベースの 3 欄がエイリアスのプルダウン 1 欄に差し替わる。

## 理由

- プルダウン表示のためにどのみち `tnsnames.ora` はパースする。パース結果を接続にも使えば、プロセス 1 回きりという制約が丸ごと消え、ディレクトリを接続ごとに変えられ、再起動も不要になる。
- パーサは純粋関数であり、実ファイルを使った単体テストを厚く書ける。
- `IFILE` は大企業の共有設定でたまに使われる程度で、対応範囲を明示して警告を出せば実用上足りる。

## 却下した案

**TNS_ADMIN をアプリ全体の 1 設定とし、変更時に再起動を促す**: 1 接続 = 1 ウィンドウという設計（[[0009-ウィンドウモデルとタイトルバー]]）と噛み合わない。

**接続ごとに TNS_ADMIN を変えるため、接続を別プロセスに分離する**: IPC が二重になり、[[0002-接続ごとのアクタースレッドと中止]] のアクター方式を作り直すことになる。

**エイリアス名だけを正規表現で拾い、実際の接続は ODPI-C に任せる**: 本決定では記述子そのものが必要なので成立しない。

**「データベース」欄に TNS エイリアスも書けることにし、`host:port/service` 形式かどうかで自動判別する**: UI 変更は不要だが挙動が暗黙的になり、「なぜ繋がらないのか分からない」型の事故を生む。

## 結果

- Instant Client 自体は依然として必要である（[[0001-oracle接続方式]]）。本決定が取り除くのは `TNS_ADMIN` の制約だけである。
- パーサが対応しない構文の `tnsnames.ora` では、該当エントリだけがプルダウンに現れない。警告でその旨を伝える。
