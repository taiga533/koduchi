# ADR 0001: Oracle 接続方式

- ステータス: 承認
- 日付: 2026-08-30

## 状況

小槌は Oracle と PostgreSQL に対応する GUI データベースクライアントで、Oracle から先に実装する。

Rust には純 Rust 実装の Oracle ドライバが存在しない。利用可能なのは `oracle` crate のみで、これは Oracle が提供する C ライブラリ ODPI-C へのバインディングである。ODPI-C は動作時に Oracle Instant Client を必要とする。

Instant Client はアプリケーションに同梱することもできるが、その場合はバイナリサイズが数百 MB 増加し、Oracle の再配布ライセンス条項の確認も必要になる。

## 決定

`oracle` crate を使用し、**Oracle Instant Client は利用者が別途インストールする**前提とする。アプリには同梱しない。

未検出時の扱いは次のとおり。

1. アプリ起動時に `oracle::InitParams::init()` を試行する。
2. 失敗した場合は専用の案内画面を表示する。案内画面には `brew install instantclient-basic` の手順と、ライブラリのディレクトリを Finder で指定する入力欄を置く。
3. 指定されたパスは `InitParams::oracle_client_lib_dir()` に渡し、`connections.toml` とは別の設定ファイルに保存する。
4. `init()` はプロセスにつき 1 回しか効かないため、パス指定後はアプリの再起動を促す。

対象プラットフォームは macOS のみとする。コードはクロスプラットフォームを崩さないが、動作確認とビルドは macOS だけを対象にする。

## 理由

- 個人利用のデータベースクライアントにおいて、Instant Client の事前インストールを求めるのは現実的な要求である。README に手順を記載すれば足りる。
- 同梱方式は配布サイズとライセンス確認のコストが、得られる利便性に見合わない。
- 起動直後に判定できるため、案内はデータベースへ接続する前に出せる。接続を試みて初めて意味不明なエラーで落ちる、という事態を避けられる。
- `oracle_client_lib_dir()` が存在するため、Homebrew 以外の場所に置いた利用者にも対応できる。

## 却下した案

**Instant Client をアプリにバンドルする**: バイナリが数百 MB 膨らみ、再配布条項の確認が必要になる。個人プロジェクトの規模に対して負担が大きい。

**Oracle 対応を将来課題とし、接続種別の枠だけ用意する**: Oracle を先に実装するという方針と矛盾する。

## 結果

- Instant Client が無い環境では、アプリは起動するが Oracle へ接続できない。この状態を案内画面で明示する。
- `init()` がプロセス 1 回きりであることは、[[0006-tnsnames解決を自前パースで行う]] でも制約として現れる。
- PostgreSQL 対応時は、この制約を持たない `tokio-postgres` を [[0002-接続ごとのアクタースレッドと中止]] の Driver trait 実装として追加する。
