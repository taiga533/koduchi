# ADR 0008: デザイントークンとテーマの実装方式

- ステータス: 承認
- 日付: 2026-08-30

## 状況

Claude Design のデザインファイル（`DB Client.dc.html`）は、すべての色を CSS 変数として定義している。`--bg` / `--panel` / `--panel2` / `--fill` / `--fill2` / `--line` / `--line2` / `--fg` 〜 `--fg6`、SQL ハイライト用の `--kw` / `--str` / `--num` / `--fn` / `--cmt` / `--err`、差分表示用の `--dmb` / `--dmf` / `--dpb` / `--dpf`、アクセントの `--ac` / `--acfg` / `--acdiv`、および罫線の `--gl` と行パディングの `--rp`。

これらはライト / ダークで別の値を取り、アクセント色は実行時に計算される（ダーク時は明度を 1.62 倍にスケールし、`--acfg` は輝度 0.62 を境に白か黒を選ぶ）。

フロントエンドは UnoCSS を使う。

## 決定

**CSS 変数を `:root` と `[data-theme="dark"]` に定義し、UnoCSS の `theme` からそれを参照する。**

```ts
// uno.config.ts
theme: { colors: { panel: 'var(--panel)', fg: 'var(--fg)', /* ... */ } }
```

テーマ切替はルート要素の `data-theme` 属性 1 つで行う。

- 既定は**システム追従**（`prefers-color-scheme`）。
- 設定画面で「システム / ライト / ダーク」の 3 択に上書きできる。

**アクセント色はオリーブ `#6d7a35` に固定する。** デザインは 4 色（`#6d7a35` / `#c9a227` / `#b1743a` / `#3a5fa8`）の切り替えを持つが、切り替え機能は実装しない。ダーク時のアクセントは設計側の計算どおり明度 1.62 倍で導出した値を、CSS 変数の定数として持つ。

罫線の有無（`--gl`）と行の高さ（`--rp`）は、デザインが `showGridLines` / `compactRows` プロパティとして定義しているとおり、設定画面から切り替えられるようにする。

## 理由

- ダーク時のアクセントが計算値である以上、値を 1 箇所で切り替えられる CSS 変数が唯一の現実的な選択肢である。
- UnoCSS の `dark:` バリアントで書き分けると、すべての要素に色指定を二重に書くことになる。デザインの変数は 25 個以上あり、破綻する。
- `data-theme` 属性 1 つで切り替わるため、システム追従と手動上書きの 3 択がそのまま実装できる。
- アクセント 4 色の切り替えは、色の計算ロジックを実行時に持つ必要が生じる。機能としての価値に対してコストが見合わない。

## 却下した案

**UnoCSS の theme に色を直接書き、ダークは `dark:` バリアントで書き分ける**: 前述のとおり全要素で二重記述になる。

**素の CSS Modules を使い、UnoCSS はレイアウトユーティリティのみに使う**: UnoCSS を採用する意味が薄れる。

**アクセント 4 色の切り替えを実装する**: 実行時の色計算が必要になり、得られる価値に見合わない。

**ライトのみ対応**: デザインが全トークンのダーク値を定義しており、使わないのはもったいない。

## 結果

- SQL のシンタックスハイライト色（`--kw` / `--str` / `--num` / `--fn` / `--cmt`）は CodeMirror のテーマとして同じ CSS 変数を参照させる。テーマ切替が自動的にエディタにも効く。
- 差分表示用の `--dmb` / `--dmf` / `--dpb` / `--dpf` は Ask AI 機能のためのもので、Ask AI は実装しないため未使用になる。将来のために変数定義だけは残す。
- デザインには NULL の表示指定が無い。結果テーブルの NULL は `--fg5` の淡色・斜体で `NULL` と表示し、空文字列と区別する。
