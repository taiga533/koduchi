# ADR 0035: 仲介者の切り出しとコマンドの表

- ステータス: 承認
- 日付: 2026-09-27

## 状況

`App.tsx` が 1525 行ある。中身は 4 種類が同居している。

| 中身                           | 例                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| 裁定の関数（30 個ほど）        | `disconnectAndReset` / `closeTabAndRelease` / `resolvePendingTransaction` / `startCsvExport` |
| キーの振り分け                 | `keydown` の `useEffect`（約 85 行）                                                       |
| コマンドパレットの一覧         | `paletteCommands`                                                                          |
| 確認ダイアログの表示フラグ・小さな部品 | `disconnectBlocked` などの state、`RunControls` / `BindPrompt` / `Shell` / `SessionSaver` |

裁定の関数は小槌の**仲介者**である。ストア同士を結合させず、「後片付けは `App.tsx` が順に呼ぶ」（ADR README「接続の切断と切り替え」）と決めた結果、複数のストアにまたがる動きはすべてここに集まった。この決定は正しく、覆さない。困っているのは置き場所である。

- **裁定を試すには `App` を描くしかない。**関数のほとんどは `useXStore.getState()` を呼ぶだけで React の機能を使っていないが、`useCallback` の中にあるため外から呼べない。
- **同じ操作が 2 か所に書かれている。**`keydown` の振り分けとパレットの一覧は、どちらも「このキー / この項目でこの裁定を呼ぶ」を別々に書いている。片方にだけ足す・片方だけ条件を変える、が起きうる。
- **裁定の流れが途中で切れる。**確認ダイアログを state のフラグで出すと、「尋ねる」と「答えを受けて続ける」が別の関数へ分かれる。未コミットの確認（`transaction/pendingChanges.ts`）とタブを閉じる確認（`setCloseTabDialog`）は既に `await` で答えを待つ形であり、形が 2 通りある。

## 決定

### 裁定は `src/mediator/` の普通の関数にする

`App.tsx` の裁定の関数を、React に依存しない関数として `src/mediator/` へ移す。ファイルは**裁定の領域**で分ける（接続の一生・実行・タブとファイル・CSV など）。画面の部品や描画の単位では分けない。

- ストアは `useXStore.getState()` で直に触ってよい。仲介者はストアの上に立つ層であり、ストアを差し替えずに単体テストできる（ストアの先の `src/api/` 層は ADR 0010 のとおり差し替える）。
- 画面にしか無いもの（エディタのハンドル、確認の尋ね方）は**引数で受け取る**。仲介者は `SqlEditorHandle` や React の state を import しない。
- `App.tsx` は、仲介者の関数を部品の callback と Tauri のイベントへ**配線するだけ**になる。
- ストアの中から別のストアを呼ばない、という既存の決定はそのまま守る。仲介者を切り出しても、裁定の持ち主は仲介者だけである。

### 操作は 1 つの**コマンドの表**から配る

`App.tsx` の `keydown` とコマンドパレットの両方に現れる操作を、1 行 1 コマンドの表にする。1 行が持つのは、識別子・名前・キー（無ければ無し）・実行する裁定・今使えるかの判定である。

- `App.tsx` の `keydown` の振り分けと、パレットのコマンドの一覧は、**どちらもこの表から作る**。パレットに出すキーの表記も表から取る。
- `event.defaultPrevented` を見てエディタが処理したものを二重に扱わないこと、修飾の重なる `⌘S` / `⇧⌘S` / `⌥⌘S` を絞りの強い枝から見ること（ADR README「キーバインド」）は、表から振り分けを作る関数が守る。
- **表に入れるのは `App.tsx` の `keydown` に置いていたキーだけである。**CodeMirror の keymap・`ResultTable`・`SchemaTree`・`TabBar` の中でしか効かないキーは、今の置き場所のまま動かさない（ADR README「キーバインド」の置き場所の決定は変えない）。

### 確認は **`await` で答えを待つ**形に揃える

仲介者が利用者に尋ねるときは、答えを `Promise` で受け取る。ネイティブのダイアログは `pendingChanges.ts` と同じく差し替えられる形で、画面の中に描く確認（切断できない旨など）は、仲介者が「尋ね事」を出し、`App.tsx` がそれを描き、押されたら `Promise` を解く。

表示フラグを `App.tsx` の state に 1 つずつ持つ形はやめる。

### 小さな部品は別のファイルへ出す

`RunControls` / `BindPrompt` / `Shell` / `SessionSaver` など、`App.tsx` の末尾にある部品はそれぞれの持ち場の `src/components/` の下へ移す。

## 理由

- **仲介者を普通の関数にするのは、裁定のテストを描画から切り離すためである。**関所の抜けは裁定の中で起きる（未コミットの確認を飛ばす経路、切断の後片付けの順序）。それを試すたびに `App` を丸ごと描くのは重く、描画の都合でテストが壊れる。
- **領域で分けるのは、裁定が画面の境界をまたぐからである。**「切断」はステータスバーからもメニューからも起き、片付けはタブ・実行・スキーマ・セッション・定義のすべてに及ぶ。部品の単位で分けると、1 つの裁定が複数のファイルに散る。
- **コマンドの表は、入口が増えても裁定が 1 つであることを構造で保つ。**同じ操作の条件を 2 か所で揃え続けるのは注意力に頼る作りであり、いつか食い違う。
- **確認を `await` に揃えるのは、裁定を上から下へ 1 本で読めるようにするためである。**既に 2 つの確認がこの形であり、残りを揃えると形が 1 通りになる。

## 却下した案

**全部品を Passive View にし、イベントを Chain of Responsibility で親へ上げ、1 つのステートマシンの仲介者に裁定させる**: 設計としては一貫するが、小槌には打鍵やポインタの頻度で変わる状態（結果テーブルの選択、タブのドラッグ）と、自分で状態を持つ部品（CodeMirror）が多い。前者は上へ報告するたびにアプリ全体が描き直り、後者は受け身の描画に作り替えられない。接続・トランザクション・タブ・実行は互いに独立に進むため、1 つの機械にすると状態の組み合わせが爆発する。並行する状態に分ければ扱えるが、分けた姿は今の機能別のストアとほぼ同じになる。**段階を持つストアが自分で遷移を拒むこと（関所）と、複数のストアにまたがる裁定を仲介者に集めることだけを採る。**

**仲介者をストアとして持つ（zustand の 11 個めのストア）**: 描画と切り離せる点は同じだが、仲介者は自分の状態をほとんど持たず、他のストアを呼ぶだけである。ストアにすると「ストアの中から別のストアを呼ばない」という決定の例外を作ることになる。

**裁定を `src/connection/` や `src/transaction/` のような既存の領域の置き場所へ散らす**: 置き場所の規則は増えないが、どのファイルが仲介者でどのファイルが純粋な判定なのかが名前から分からなくなる。仲介者であることを置き場所で示す。

**`App.tsx` を部品に分けるだけに留める**: 行数は減るが、裁定は依然として描画の中にあり、テストの重さも入口の二重化も残る。

## 実装の補足（2026-09-27）

決定の読み方が分かれうる所を、実装でどう決めたかを残す。

- **置き場所**: `src/mediator/` の `connection.ts`（切断・繋ぎ直し・接続断の配り）/ `transaction.ts`（コミット・ロールバック・未コミットの関所）/ `execution.ts`（実行・実行計画・バインド変数）/ `tabs.ts`（タブを閉じる・定義タブ・SQL をタブへ入れる）/ `files.ts`（`.sql` の保存と読み込み）/ `savedQuery.ts` / `csv.ts` / `schema.ts`（ツリーで示す・取り直す）/ `session.ts`（セッションの復元）/ `commands.ts`（コマンドの表）/ `ask.ts`（尋ね事）。
- **コマンドの表の `editor` の行**: パレットには CodeMirror の keymap が持つキー（`⌘⏎` / `⇧⌘⏎` / `⌥⌘⏎` / `⌘.` / `⇧⌥F`）の操作も並ぶ。これらは表に**表記だけ**を持つ行（`owner: 'editor'`）として置き、表は振り分けない。キーの置き場所は動かしていない。逆に `⌘W` と `⌘K` は `keydown` にだけあった操作であり、表には置くがパレットには並べない（`inPalette: false`）。
- **振り分けの規則**: 表の組み合わせに書いた修飾は「押されていなければならない」ものであり、書いていない修飾が押されていても当たる（`⌃⌘S` が保存に当たるのは以前の `keydown` と同じ）。当たる行が複数あるときは求める修飾の多い行が勝ち、同じ数なら表の上の行が勝つ（`⌥⇧⌘S` は以前どおり CSV に当たる）。
- **使えるかの判定（`available`）**: 以前から関数の中で弾いていたもの（繋がっていなければパレットを開かない・スキーマを取り直さない）だけを表へ出した。判定が偽のキーは実行しないが、既定の動作は止める（以前の `keydown` と同じ）。パレットには並べない。
- **尋ね事の受け渡し口**: `ask.ts` の `createAskChannel` は React に依存しない小さな購読の口であり、`App.tsx` が `useSyncExternalStore` で読む。種類ごとに高々 1 つを持ち、違う種類は同時に出ていてよい（以前の表示フラグが種類ごとに独立していたのと同じ）。同じ種類を重ねて出したら前のものは「何もしない」答えで解く。答えの来ない `Promise` を残さないためである。
- **尋ね事にしなかったもの**: CSV の保存ダイアログとコマンドパレットは「尋ねて答えを待つ」確認ではなく、開いている間に利用者が操作を続けるパネルである。開閉は `App.tsx` の state のまま残し、CSV の進み具合と中止の印はダイアログの包み（`components/csv/CsvExportDialog.tsx`）に閉じ込めた。
- **ネイティブのダイアログ**: 保存先・開くファイルの選択と、実測付きの実行計画の確認は `src/api/dialog.ts` の窓口越しに呼ぶ。未コミットの確認とタブを閉じる確認は、既存の専用の差し替え口（`pendingChanges.ts` / `closing.ts`）のままにした。
