# ADR 0015: 接続の色分けとグループ分け

- ステータス: 承認
- 日付: 2026-09-08

## 状況

1 接続 = 1 ウィンドウである（[[0009-ウィンドウモデルとタイトルバー]]）。本番と開発を並べて見られるのが利点であり、実際そう使う。ところが**並べたウィンドウを見分ける手掛かりが接続名の文字しか無い。**

- タイトルバーには `--ac` 固定の 13px の角丸と接続名がある。どのウィンドウも同じ色である。
- ステータスバーの「接続中」も接続によらず同じ緑である。
- 接続を選ぶ画面は保存された順に並ぶ 1 本の一覧であり、接続が 20 件になれば目的の 1 件を探すだけで一仕事になる。

読み取り専用フラグ（[[0004-認証情報と接続設定の保存先]]）はあるが、これは「何ができるか」であって「どこに繋いでいるか」ではない。本番へ書き込みの権限で繋ぐ場面はあり、そのときこそ見分けが要る。**間違ったウィンドウで `DELETE` を撃つのは、[[0012-トランザクション制御]] が塞いだ「消えたはずのデータが消えない」より重い事故である。**

## 決定

### 色は決め打ちの 7 色 + 色なし。カラーピッカーは置かない

`none` / `red` / `orange` / `yellow` / `green` / `blue` / `purple` / `gray` の 8 択とし、既定は `none`。値は `tokens.css` の `--cn-red` などのトークンと 1 対 1 で対応させ、ライト / ダークで別々の値を持つ（[[0008-デザイントークンとテーマ実装方式]]）。明度はテーマごとに揃えてあり、どの色も同じ強さに見える。黄だけはアクセントのオリーブと紛れるため明度を上げてある。

コンポーネントは色の値を持たない。`connectionColorVar()` が `var(--cn-red)` という**トークンの参照**を返し、それを `style` に渡す。接続の色は接続ごとに動くため UnoCSS のクラス名では書けないが、値そのものはトークン側にしか無い状態を保つ。`uno.config.ts` の `theme.colors` にはこの 7 色を足さない。クラス名として書けない色を足しても使われないためである。

### 色は「面積のある帯」で出す。主役はウィンドウ上端

3 箇所に出すが、役割は同じではない。

| 場所                       | 形                        | 役割 |
| -------------------------- | ------------------------- | ---- |
| タイトルバーの上端         | ウィンドウ全幅・3px の帯  | 主役 |
| タイトルバーの接続名の左   | 13px の角丸（既存の置換） | 補助 |
| ステータスバーの「接続中」 | 7px の角丸                | 補助 |
| 接続を選ぶ画面の行の左端   | 行の高さいっぱい・3px の縦帯 | 一覧の見分け |

**主役をウィンドウ上端の全幅の帯にした。** 作業中に見ているのはエディタと結果テーブルであり、視線は画面の中ほどにある。上端の帯は、そこから目を上げなくても周辺視野に入る唯一の場所である。点で出すと、色を付けたことにはなるが「気づかせる」という目的をほとんど果たさない。事故を防ぐための機能なのだから、視界の端に置けなければ意味が無い。

3px という高さは信号機との兼ね合いで決まる。[[0009-ウィンドウモデルとタイトルバー]] の導出により、ボタンの中心はウィンドウ上端から `y − 2` = 13px、直径は 14px であるから、ボタンの上端は 6px の位置に来る。3px の帯はここに掛からない。

接続を選ぶ画面の縦帯は、色が無くても場所だけ空ける。色の有無で行の頭が揃わなくなると、名前を目で追いにくくなるためである。

### 読み取り専用は形で、接続の別は色で示す

読み取り専用はこれまでどおり鍵のアイコンと「読み取り専用」の文言（形と文字）で示し、色は使わない。接続を選ぶ画面の行にも鍵を足した。**色は「どの接続か」、形は「何ができるか」という別々の軸を表す。**同じ手掛かりに 2 つの意味を載せると、赤が「本番」なのか「危険」なのか読み分けられなくなる。同じ理由で、色を選ぶ見本の「選ばれている」印にも色を使わず、アクセントの縁で示す。

### グループは 1 段だけ。未指定は見出しを付けず先頭に置く

`SavedConnection` にグループ名を 1 つ持たせる。**入れ子は構造として作れない。**接続が持つ名前が 1 つである以上、束ねた結果は必ず 1 段になる。`本番/東京` のような区切り文字での擬似的な入れ子も解釈しない。

接続を選ぶ画面での並びは次のとおり。

- グループ未指定の接続を、**見出しの無い 1 組として先頭に置く**。「その他」のような見出しを機械的に付けると、グループを使っていない利用者にまで不要な見出しが出る。グループを使わない限り、画面はこれまでと同じに見える。
- グループは `connections.toml` の並びで**最初に現れた順**に置く。名前で並べ替えない。
- グループ名は前後の空白を落として比べる。`本番` と `本番 ` が別の組に割れないようにするためである。空白だけの名前は未指定として扱う。

接続を作る画面のグループ欄は自由入力だが、既に使われている名前を `datalist` の候補として出す。同じ意味のグループが綴り違いで割れるのを防ぐ。

並びの決まりごとは `src/components/connection/grouping.ts` の純粋な関数に寄せてある。

### 保存先は `connections.toml`

[[0004-認証情報と接続設定の保存先]] のとおり。`color` と `group` を `#[serde(default)]` で足し、項目を持たない古いファイルは色なし・グループ未指定として読める。どちらも単純な値であるため、TOML の表（`schema_filter` など）より前に置く。表の後ろに単純な値を並べると書き出せない。

グループ未指定は `Option<String>` の `None` であり、書き出したときに行そのものが出ない。

## 理由

- **色を決め打ちにした**のは、任意の色を入れさせるとテーマとの整合が取れなくなるためである。利用者が選んだ `#ffff00` はダークで白飛びし、`#333333` はライトで背景に沈む。[[0008-デザイントークンとテーマ実装方式]] が全トークンにライト / ダークの値を持たせている前提そのものが崩れる。7 色あれば「本番・検証・開発・手元」の区別には足りる。
- **色をアクセント色の切り替え（[[0008-デザイントークンとテーマ実装方式]] で却下）と混同しない。**あちらはアプリ全体の意匠の話で、実行時の色計算が要るために却下した。こちらは接続ごとの識別の話であり、必要なのは静的なトークンが 7 つだけである。同じ「色を増やす」でも、払うコストが違う。
- **グループを 1 段に限った**のは、深い階層を作れるようにすると畳んだ / 開いたの状態を持つ必要が生じ、接続を選ぶ画面が「探す」画面から「操作する」画面に変わってしまうためである。日常の起動でここに用があるのは数秒間である。
- **グループを名前で並べ替えない**のは、日本語の名前で並びが読み手の予想と合わないためである。`localeCompare` は漢字を読みでは並べられず、`検証` が `本番` の前に来るか後に来るかを利用者は予測できない。ファイルの並びなら、利用者が `connections.toml` を直に編集して決められる。

## 却下した案

**カラーピッカーで任意の色を選ばせる**: 前述のとおりテーマとの整合が取れなくなる。「ライトでは読めるがダークでは見えない色」を利用者が選べてしまう。

**色を点（ドット）だけで出す**: 実装は最小で済むが、視線が画面中央にあるときに気づけない。本番と開発を見分けるという目的を果たさない。既存の 13px の角丸を接続の色にするだけでは、色を付けた甲斐がほとんど無い。

**ウィンドウ全体の背景色を接続の色で染める**: 最も気づきやすいが、`--bg` から `--panel` までの面の階調（[[0008-デザイントークンとテーマ実装方式]]）が全部やり直しになる。結果テーブルの読みやすさを、7 色それぞれについて作り直すだけの値打ちは無い。

**読み取り専用も色で示す（例: 読み取り専用は必ず青）**: 色の意味が 2 つになり、赤が「本番」なのか「危険」なのか読み分けられなくなる。接続の色と読み取り専用は独立に付くため、両方を色で表すと組み合わせが破綻する。

**グループを入れ子にできるようにする**: 畳んだ / 開いたの状態を持つことになり、[[0005-クエリ履歴とセッション復元のsqlite]] の保存先にもう 1 項目増える。接続の数が数十件で頭打ちになるアプリで、その複雑さは見合わない。

**グループを選択式（プルダウン）にする**: グループを作る操作と接続を作る操作が分かれ、手数が増える。自由入力に候補を添えるほうが、最初の 1 件を作るときに躓かない。

**グループを名前で並べ替える**: 前述のとおり日本語の名前で予想と合わない並びになる。

**接続の色をアプリ設定（`settings.toml`）に置く**: 接続そのものの属性であり、接続と一緒に消えるべきである。接続を削除したときに孤児の設定が残る（[[0004-認証情報と接続設定の保存先]] がキーチェーンについて避けたのと同じ問題）。

## 結果

- `ActiveConnection` が `color` と `group` を持つ。どちらも Rust へは渡さない値であり、[[0013-補完の候補生成と識別子の出力スタイル]] の `completion` と同じ扱いになる。3 つとも接続した時点で決まり、繋いだ後は変わらない。
- `connect()` の引数が増え続けるのを避けるため、Rust へ渡さないこれらの値を `ConnectionProfile` という 1 つの型にまとめた。今後この種の項目が増えても、ストアの呼び出し口の形は変わらない。
- グループを持つ接続はタイトルバーに `本番 / 本番東京` の形で出る。ウィンドウを並べたときに、色と文字の両方で見分けられる。
- 色を増やすときは `tokens.css` の 3 箇所（ライト・システム追従のダーク・ダーク固定）すべてに足すこと。`connectionColors.test.ts` が 3 箇所揃っているかを見張る。
- `settings.toml` は触っていない。接続の色はアプリ全体の見た目ではなく、接続 1 件の属性である。
