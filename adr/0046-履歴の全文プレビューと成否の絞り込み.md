# ADR 0046: 履歴の全文プレビューと成否の絞り込み

- ステータス: 承認
- 日付: 2026-09-28

## 状況

履歴の一覧は SQL の 1 行目しか出さない（[[0005-クエリ履歴とセッション復元のsqlite]]）。行の高さを揃えて多くを並べるためである。全文を見る道は、エディタへ入れるか右クリックの「SQL をコピー」（[[0038-右クリックメニューの追加]]）しかなかった。

利用者は issue #76 で次の 2 つを求めている。

1. 履歴の SQL の全文プレビュー。ただし**フォーカスした行についてだけ**出す。
2. 成功のみ・失敗のみで一覧を絞る。

一覧は Rust 側の問い合わせで新しい順に最大 200 件（`HISTORY_LIMIT`）を取る。接続名と検索語の絞り込みも問い合わせに載っている。

決めることは 4 つある。

1. 「フォーカスした」を何で判定するか
2. プレビューをどこに出すか
3. 成否の絞り込みを問い合わせで行うか、取得済みを手元で絞るか
4. 絞り込みを保存するか

## 決定

### 「フォーカスした」はキーボードの焦点とホバーの 2 つ

行の本体（押すとエディタへ入るボタン）に**キーボードの焦点が当たったとき**と、**ポインタを行に置き続けたとき**（350 ms）に出す。どちらでもない行には出さない。

焦点だけにしないのは、WKWebView ではボタンを押しても焦点が移らない（macOS の作法）ためである。焦点だけを入口にすると、マウスで使う人には開く道が無い。一方で、行を押す操作は「エディタへ入れる」のままにする（既存の動きを変えない）。

2 つは閉じる条件が違う。

- 焦点で開いたものは焦点が抜けたら閉じる。ポインタが離れても閉じない。
- ホバーで開いたものは、ポインタが行にもプレビューにも居なくなってから 150 ms で閉じる。猶予は行からプレビューへ移る途中にサイドバーの縁を通るためである。

ほかに `esc`（[[0031-オーバーレイのescとdocumentのスクロール]] の `useEscapeKey`）と、右クリックのメニューを開いたときに閉じる。

**プレビューは常に対象の行の横に居なければならない。**別の行の横に残ると、見えている全文がどの行のものかを偽る。行が動く場面は 2 つあり、それぞれ次のように扱う。

- **プレビューの外がスクロールしたとき**: ホバーで開いたものは閉じる（行がポインタの下から去った）。焦点で開いたものは行を測り直して付いていく。`↓` で見えていない行へ送ると器がスクロールするが、焦点はその行に残るので、閉じると開き直す道が無い。
- **一覧が変わったとき**（実行のたびの読み直しで先頭に行が入る、別の行を消す）: 塗る前に行を測り直す。行が一覧から消えていれば閉じる。

焦点を行から行へ送りやすいよう、一覧に `↑` / `↓` を足した。行ごとに `✕` があるため `Tab` では 2 打鍵に 1 行しか進まない。変換中の打鍵は `isComposingKey` で捨てる（[[0025-入力欄における変換中の打鍵]]）。焦点は `preventScroll` で当て、見せる分だけ `scrollIntoView({ block: 'nearest' })` で送る。`focus()` に任せると焦点が当たった後でスクロールが起き、`onFocus` で測った位置が古くなる。端の行でも矢印の既定の動き（器のスクロール）は止める。

### プレビューはサイドバーの右隣に重ねて出す

行の横、エディタの上に `position: fixed` の浮き板として出す。幅は 480px、高さは画面の 60% までで、それを超える SQL は中でスクロールする。**全文を切り詰めない。**失敗した履歴はエラーメッセージも添える。

- 一覧の中で行を広げる案は採らない。ホバーで開くと下の行が押し下げられ、ポインタの下の行が入れ替わって開き直しが連鎖する。
- サイドバーの下部に枠を設ける案も採らない。長い SQL をスクロールしに枠へ向かう途中で別の行を通り、中身が入れ替わる。右隣なら、行から右へ動かすだけで他の行をまたがずにプレビューへ入れる。

**焦点は奪わない**（焦点で開いたものが焦点を取ると、行から焦点が抜けてその場で閉じる）。行の本体は `aria-describedby` でプレビューを指す。位置の計算は `src/components/sidebar/previewPlacement.ts` の純粋な関数に置く。右クリックのメニュー（`placeMenu`）と違い、はみ出しても反対側へは開かず端へ寄せる。行の横に並んでいることが「どの行の全文か」の手掛かりだからである。

**構文の色分けはしない。**字句の走査（`src/sql/tokens.ts`）は空白を落とすため元の書式へ戻せない。CodeMirror をホバーのたびに起こすのは重い。

### 成否の絞り込みは問い合わせに載せる

`HistoryQuery` に `succeeded: Option<bool>` を足し、`where` に `(?4 is null or succeeded = ?4)` を加える。画面は「すべて / 成功 / 失敗」の 3 つのボタンで、スコープ切替の右に並べる。

手元で絞らないのは、件数の上限より先に効かせるためである。手元で絞ると、新しい成功が 200 件を埋めたとき古い失敗が 1 件も出ない。`#[serde(default)]` を付けてあるため、この項目を送らない呼び出し（コマンドパレット）もそのまま動く。索引は足さない。成否は 2 値しかなく選択性が低い。新しい順に `started_at` の索引を読みながら篩に掛ければ足りる。

### 絞り込みは保存しない

スコープ（この接続のみ / 全接続）と同じく、開いたときは「すべて」に戻す。絞ったまま次に開くと、履歴が消えたように見えるためである。同じ理由で、絞り込んだ結果が空のときは「失敗した実行はありません」のように絞り込みを言う一言を出す。

## 却下した案

**押した行を「選択」にし、選択した行にプレビューを出す**: 行を押すとエディタへ入る今の動きを、ダブルクリックへ移すことになる。使い慣れた動きを変える割に得るものが無い。

**ホバーだけで出す**: キーボードで辿る人に開く道が無い。

**一覧の中で行を広げる / サイドバーの下部に枠を置く**: 上に書いたとおり、ホバーと組み合わせると中身が入れ替わる。

**取得済みの 200 件を手元で絞る**: 上に書いたとおり、古い失敗が見えなくなる。

**絞り込みを `session_state` へ保存する**: 絞ったことを忘れた再起動の後に、履歴が消えたと読まれる。

## 結果

- `HistoryQuery` に `succeeded` が増えた。フロントエンドの `HistoryQuery` 型でも必須の項目にしたため、呼ぶ側は成否を問わないとき `null` を渡す。
- 履歴のストアに `outcome` と `setOutcome` が増えた。問い合わせへの写しは `outcomeToSucceeded`。
- 履歴のストアの読み出しに世代番号を付けた（スキーマのストアと同じ形）。絞り込みを続けて切り替えると読み出しが重なり、遅れて返った古い条件の結果が今の条件の結果を上書きするためである。
- 保存済みクエリの一覧（`SavedQueryList`）には全文プレビューを足していない。issue #76 の対象は履歴であり、保存済みクエリには名前という見出しがある。要れば同じ部品を使える。
