# ADR 0030: 接続が切れていることの気付き方と繋ぎ直し

- ステータス: 承認
- 日付: 2026-09-11

## 状況

[[0026-接続断の検出と回復]] で `DbErrorKind::ConnectionLost` と「接続が切れました / 再接続」を入れたが、実際に使うと利用者から 2 つの不満が出た。実装を読んで数えたところ、原因は 3 つあった。

**1 つめ。切れても画面は「接続中」の緑のままである。**Wi-Fi が落ちる、VPN が切れる、DBA がデータベースを落とす。小槌は何も言わない。次にクエリを走らせて初めて `ORA-03113` が返り、そこで初めて表示が変わる。その間に利用者は SQL を書き、「さっきコミットしたはずだ」と思い、切れているとは知らずに画面を読む。

ADR 0026 はこれを織り込んでいた。「気づくのは往復したときだけ。定期的な生存確認はしない」と決め、理由も書いた——`select 1 from dual` を定期的に投げると**その問い合わせ自体がアイドル時間をリセットし**、DBA が設定した `IDLE_TIME` を骨抜きにする。この理由は今も正しい。

しかしそこで決めたのは**「往復を伴う生存確認をしない」**であって、**「気付けないことを黙っている」**ではなかった。緑を出し続けるのは「今この瞬間も繋がっている」という主張であり、小槌はその主張を裏付けるものを何も持っていない。**確かめていないことを確かめたように見せている。**

**2 つめ。「再接続」を押したときの挙動が怪しい。**報告はそれだけだったので、実装を読んで実体を数えた。

| 見つけたもの                                                                                         | 起きること                                                                                        |
| ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `reconnect` が古い接続の `disconnect` を**待ってから**段階を `connecting` にしていた                   | 待っている間ボタンは「再接続」のまま押せる。押した回数だけ接続が張られ、最後に返った 1 つ以外は Rust 側の接続表に残り続ける（1 つにつき Oracle のセッション 4 本） |
| 切れている接続の後片付け（ODPI-C のログオフ）は**往復を試みる**                                        | 回線が落ちている相手では TCP が諦めるまで返らない。押してから数十秒、画面が動かない                |
| 繋ぎ直すと `connection.id` が変わるが、スキーマツリーは `load` が `status !== 'idle'` で素通りしていた | スキーマの読み込み中に切れると、ツリーは空（または失敗表示）のまま二度と埋まらない                |
| `pool.release` と `pool.cancel` が `見張る` を通っていなかった                                         | その 2 つの経路だけが断に気付けない（ADR 0026 の「接続を要る操作はすべて通る」が守られていない）   |

**3 つめ。そして、これが根っこだった。**ADR 0026 は `DbError::execute` を直に作らず `map_execute_error` を通すと決め、`errors.rs` の doc コメントにも「**この関数を通さずに `DbError::execute` を直に作ると、その経路だけが接続断に気付けなくなる**」と書いた。数えたところ、**通っていたのは `oracle/mod.rs`（SQL の実行）だけだった。**

| ファイル        | 直に作っていた件数 |
| --------------- | ------------------ |
| `schema.rs`     | 10                 |
| `definition.rs` | 10                 |
| `plan.rs`       | 8                  |
| `convert.rs`    | 4                  |
| `source.rs`     | 3                  |
| `sessions.rs`   | 2                  |

つまり、**スキーマツリーを開いても、定義タブを開いても、実行計画を取っても、セッション一覧を出しても、ソース検索をしても、切れたことに気付かなかった。**断は `Execute` の普通のエラーとして結果ペインに出るだけで、`src/connection/lost.ts` の見張り（`kind === 'connectionLost'` を見る）には何も届かない。ステータスバーは緑のまま。

**フロントエンド側で気付く場所を 1 箇所に寄せても、Rust 側が断を断として返さなければ意味が無い。**片肺だった。issue の「クエリを再実行しないと接続が切れたことがわからない」は、ほぼそのままこれの説明である。

## 決定

### Oracle のエラーは、例外なく写し替えを通す

`src/db/oracle/` の中で `DbError::execute` を直に作っていた 37 箇所を `errors::map_execute_error` へ通した。**文言は 1 文字も変えていない。**`map_execute_error(context, error)` が作るのは `"{context}: {text}"` であり、文脈を持たない箇所には空文字列を渡して従来どおりの文言にしてある。

既に `map_oracle_error` / `map_permission_error` を通していた箇所は触っていない。どちらも内部で `classify` を通り、**接続断を権限より先に見る**（ADR 0026）。

**`bind.rs` の 1 箇所だけは直に作ったまま残した。**バインド変数へ与えられた値が読めないという失敗であり、**データベースへは行っていない。**接続断ではありえないものを断の写し替えへ通すと、写し替えの意味のほうが薄まる。

この掃除の結果、6 つのファイルから `DbError` の import そのものが消えた。**そのファイルが作るエラーはすべて写し替えを経由する**ようになったということである。

### 抜けは、経路ごとのテストではなく数え上げで塞ぐ

「スキーマ取得で `ORA-03113` が来たら `connectionLost` になる」と 1 経路ずつ書くテストは、**次に経路を足した人がまた抜かす。**現にそうなった。

そこで `src-tauri/tests/oracle_errors.rs` が `src/db/oracle/` を読み、`DbError::execute(` が現れる場所と件数を数える。許すのは `errors.rs`（写し替えそのもの）と `bind.rs`（データベースへ行っていない失敗）だけで、**件数まで決め打ちする。**許した場所の中で 1 件増えたときにも落ちる。落ちた人は「この 1 件は本当にデータベースへ行っていない失敗か」を考えることになる。

泥臭い。しかし、**足した経路だけが気付けない、を構造として塞ぐ形**が他に見つからなかった。型で縛るには `DbError::execute` を `errors.rs` の中だけから呼べるようにする必要があり、Rust の可視性では同じクレートの中でそこまで絞れない。

### 往復を起こさない覗きを入れる。`select 1 from dual` は投げない

`oracle` crate（ODPI-C）の `Connection::status()` は、**サーバへパケットを 1 つも送らずに** OCI がクライアント側に持っている `OCI_ATTR_SERVER_STATUS` を読む。Instant Client 12.2 以降は、この値を読むときに TCP ソケットが相手から閉じられていないかを見る（`ping()` が「往復する」と明記されているのと対になっている）。

**アイドル時間は戻らない。**送るものが無いのだから、サーバ側から見れば何も起きていない。ADR 0026 が却下したのは「問い合わせを投げる生存確認」であり、その却下の理由——`IDLE_TIME` の骨抜き——はここには当たらない。**DBA の設定はこれまでどおり効く。**

見えるものと見えないものを、はっきり分けて型にした。

```
pub enum Liveness {
    Disconnected,  // サーバ側から切られていることが分かった
    Unknown,       // 切られたとは分からなかった。生きている証明ではない
}
```

- **見える**: データベースの停止、インスタンスの再起動、`ALTER SYSTEM KILL SESSION`（[[0017-セッションとロックの確認]]）——相手が FIN / RST を送ってくる断。
- **見えない**: VPN の切断、回線障害、サーバ機の異常停止——パケットが 1 つも届かない断。`IDLE_TIME` の超過も、サーバ側の専用プロセスが残るためここでは見えないことがある。

**`Unknown` を「生きている」と読み替えない。**区分を 2 つに留めたのは、言えないことを型の上で言わせないためである。`Alive` という名前を持たせれば、それを返した瞬間から表示が嘘をつき始める。

覗き手（`Prober`）は中止（`Canceller`）と同じ形にした。`oracle::Connection` は `Send + Sync` であり `Arc` で複製を持てるため、**アクタースレッドを介さずに呼べる**（[[0002-接続ごとのアクタースレッドと中止]]）。命令のチャネルに載せると長い問い合わせの後ろに並び、「今どうなっているか」を知りたいときにこそ答えが返らない。

覗きは 30 秒ごとにフロントエンドから `connection_health` で行う。**このコマンドはデータベースへ往復しない。**1 本でも切られていると分かればプールごと切れたものとして印を立て（[[0026-接続断の検出と回復]] の「1 本の断はプールごとの断」）、フロントエンドは例外の経路と同じ `onConnectionLost` の見張りへ配る。**報せを数えないのは受け手の仕事**であり、`markLost` の戻り値で 2 度目以降を落とす形は変えていない。

### 見えない断は、見えないことを正直に出す

覗きで拾えない断が残る以上、緑だけを出し続けるわけにはいかない。そこで**最後にデータベースと往復できた時刻**をプールが持ち、5 分を過ぎたらステータスバーに「最終応答 12 分前」を添える。

- **「接続中」は取り下げない。**切れたと分かったわけではない。分かったのは「ここまでは確かだった」だけであり、それをそのまま言う。
- **時刻を進めるのは `見張る` が成功したときだけである。**往復しなかった操作（割り当ての無いタブを手放す、など）で進めると、表示が実際より新しくなる。**嘘は楽観の方向にだけ出る**ため、進める場所は 1 箇所に絞った。
- **猶予の内なら何も言わない。**言わないのが正しい場面で何かを言うと、注記そのものが読まれなくなる。5 分にしたのは、実務の `IDLE_TIME` が 15〜60 分（ADR 0026）であるのに対し、切られる前に気付ける余地を残しつつ、少し目を離しただけでは出てこない幅としてである。
- 判定は `src/connection/freshness.ts` の純粋な関数に寄せ、時計は呼び出し側から渡す。

### 繋ぎ直しは、古い接続の後片付けを待たない

**押した瞬間に段階を `connecting` へ動かす。**待ってから動かすと、その間ボタンが押せるまま残る。

古い接続は投げっぱなしで手放す。Rust 側の `disconnect` は**接続表から外してからプールを捨てる**ため、表から外れるのは呼んだ時点である。待たされるのは後片付けのほうであり、利用者が待っているのは新しい接続であって古い接続の後始末ではない。

同じ理由で、**切断（接続を選ぶ画面へ戻る）と接続の切り替えも待たない。**切れている相手の後片付けを待つと、袋小路を避けるために残した 2 つめの道（ADR 0026）そのものが数十秒固まる。

繋ぎに行っている最中の `reconnect` は何もしない。段階を先に動かすことでボタンは消えるが、**押しどころが消えたことと押せないことは別である。**キーの取りこぼしや素早い連打で 2 度目が入っても、接続が増えないようにしておく。

### 繋ぎ直せたら、スキーマツリーだけを取り直す

ADR 0026 は「繋ぎ直した接続は別のセッションである」と言った。では何をどこまで戻すのか。

| もの                      | 繋ぎ直したとき      | なぜ                                                                                            |
| ------------------------- | ------------------- | ----------------------------------------------------------------------------------------------- |
| スキーマツリー            | **自動で取り直す**  | 接続の識別子で引くため、新しい接続では取り直さないと繋がらない。断が読み込み中に起きていれば空のまま残る |
| 結果セット                | 戻さない            | カーソルはサーバ側にもう無い。断の時点で破棄済みにしてある（ADR 0026）                          |
| 未コミットの表示          | 戻さない            | サーバ側でロールバック済みであり、戻すものが無い（ADR 0026）                                    |
| エディタのタブと本文      | そのまま残す        | 接続に属さない                                                                                  |
| 定義タブの中身            | そのまま残す        | 同じデータベースの同じオブジェクトである。取り直しても同じものが返る                            |
| グローバル一時表・`ALTER SESSION` の設定 | 戻さない | 小槌は覚えていないため復元できない（ADR 0026）                                                  |

**取り直すのはツリーだけである。**利用者が押したのは「繋ぎ直す」であって「さっきの続きをやり直す」ではない。実行し直すかどうかは利用者が決める——[[0003-結果セットのカーソル保持と接続プール]] の「結果は破棄されました。再実行してください」と同じ線引きである。

取り直しは繋ぎ直しが返った直後に**同期的に**始める。そうすると、接続が変わったことで走る取得（`load`）は読み込み中を見て素通りし、往復が 2 度走らない。

### `release` と `cancel` も `見張る` を通す

ADR 0026 は「接続を要る操作はすべて `見張る` を通る」と決めたが、`pool.release` と `pool.cancel` が通っていなかった。通す。ただし**往復する場合だけ**である——割り当てが無ければどちらも往復せずに戻るため、その手前で返す。「往復した時刻」を往復していない操作で進めないためである。

## 理由

- **写し替えを全部通す**のは、断が**経路に依存しない事象**だからである（ADR 0026 の「窓口を丸ごと包む」と同じ理由）。権限（[[0017-セッションとロックの確認]]）は「何を引いたか」に依存するため経路ごとの判断でよいが、断はどの往復でも同じ顔で来る。経路ごとに気付くかどうかが違うのは、**利用者から見れば「触る場所によって切れていたりいなかったりする」**という読めない状態になる。
- **覗きを入れる**のは、ADR 0026 が却下した理由（`IDLE_TIME` の骨抜き）が、往復しない手段には当たらないからである。決定は理由とともに読む。理由が当たらない手段まで一緒に封じる必要は無い。
- **`Unknown` を残す**のは、見えない断が確実に残るからである。全部見えるふりをすると、見えなかった 1 件で信用がまとめて失われる。
- **時刻を添える**のは、**黙って緑を出し続けるのがいちばん悪い**からである。[[0004-認証情報と接続設定の保存先]] が読み取り専用をデータベース側に保証させ、[[0012-トランザクション制御]] が未コミットをデータベースへ聞き、ADR 0026 がロールバックを黙って隠さなかったのと同じ姿勢である。**表示を嘘にしない。**
- **後片付けを待たない**のは、待っているものが利用者の求めたものではないからである。押した結果がすぐ画面に出ないと、利用者は押せていないと考えてもう一度押す。挙動が怪しいという報告の実体はここにあった。
- **ツリーだけ取り直す**のは、それだけが「取り直さないと壊れたまま」だからである。他は放っておいても正しいか、もともと無い。

## 却下した案

**写し替えの漏れを、経路ごとのテストで 1 つずつ塞ぐ**: 何が起きるかを読んで分かるテストになる。しかし**テストが守るのは書いた経路だけ**であり、次に足される経路は守られない。漏れの正体は「書き忘れ」であって「書き間違い」ではないため、書いたものを確かめるテストでは塞げない。

**`DbError::execute` を `pub(super)` などで絞り、`errors.rs` の外から呼べなくする**: 型と可視性で縛れれば、テストは要らなくなる。しかし `DbError` は `db/error.rs` にあり、`db/oracle/` 以外（`csv`・`commands`）からも組み立てられる。`oracle` モジュールの中だけで禁じる可視性は Rust には無い。

**`Connection::ping()` を定期的に呼ぶ**: 断を確実に見つけられる。しかしこれは明示的に往復する API であり、アイドル時間をリセットする。ADR 0026 が却下した `select 1 from dual` と同じものに別の名前を付けただけである。

**ウィンドウが前面に戻ったとき・スリープから復帰したときに往復して確かめる**: 「定期的」ではないため、文面上は ADR 0026 に触れない。しかし利用者が画面を行き来するたびにアイドル時間が戻るのは同じことであり、他の作業をしながら 5 分おきにウィンドウを覗く人のセッションは永久に切られなくなる。**抜け道であることに変わりはない。**

**`navigator.onLine` の `offline` で断と決める**: 回線が落ちたことを往復なしで知れる。しかし WKWebView のこの値は「ループバック以外の経路があるか」程度のものであり、データベースが同じ機械に居る場合や、経路が一瞬切り替わっただけの場合に嘘をつく。**断と言い切れないものを断と言わない。**

**覗きの結果が `Unknown` のときも「接続中（未確認）」のように常に添える**: いつも正直ではある。しかし注記が常時出ていれば注記ではなくなる。**古くなったときにだけ出る**から目に入る。

**最後の往復の時刻をフロントエンドで数える**: Rust 側に何も足さずに済む。しかしフロントエンドには「その呼び出しが本当にデータベースへ行ったか」が分からない。割り当ての無いタブを手放したときのように往復しない経路があり、そこで時刻を進めると**表示が実際より新しくなる。**往復の定義を持っているのは `見張る` であり（ADR 0026）、時刻もそこが持つのが正しい。

**繋ぎ直しの間ボタンを `disabled` にして押せなくする**: 二度押しは防げる。しかし段階を先に動かせば表示そのものが「接続中…」に変わり、押しどころは消える。ボタンを残したまま押せなくするのは、押せるように見えるものが反応しない状態を作ることになる。

**古い接続の後片付けが終わるまで待ち、その間くるくる回す**: 正直ではある。しかし待っている対象は利用者が要求したものではない。**終わるのを見せる値打ちが無い作業を、待たせる形で見せない。**

**切れたプールを Rust 側で使い回して繋ぎ直す**: 識別子が変わらないため、スキーマツリーも定義タブも指し先を失わない。しかし手綱を差し替えるには `handles` を `Mutex` に入れることになり、あらゆる操作にロックが 1 つ増える。ADR 0026 が既に却下している。

**繋ぎ直したら、直前に開いていた結果セットも実行し直す**: 画面が切れる前へ戻る。しかし再実行は副作用を伴いうる（`update` を含むスクリプトの途中だったかもしれない）。ADR 0003 が「再実行してください」と利用者に委ねた線を、こちらの都合で越えない。

**繋ぎ直しに成功したことをメッセージタブへ 1 行残す**: 押した結果が残る。しかし成功はステータスバーが「接続中」へ戻ることで見えており、失敗だけが見えない（ADR 0026 で `noteReconnectFailure` を別の入口にしたのはそのためである）。**見えているものを二重に言わない。**

## 結果

- `src/db/oracle/` の 6 ファイルが、Oracle のエラーをすべて `errors.rs` の写し替えへ通すようになった。**`DbError::execute` を直に作らないこと。**`src-tauri/tests/oracle_errors.rs` が数え上げで見張っている。データベースへ行っていない失敗をどうしても直に作るなら、そのテストの `直に作ってよい場所` に 1 行を足し、なぜ断ではありえないのかを書くこと。
- `Driver` に `prober()` が加わった。既定は `UnknownProber`（何も答えられない覗き手）である。**往復なしで断を見分ける術はクライアントライブラリに依る**ため、持たないドライバは「分からない」と答え続けるのが正しい。PostgreSQL を足すとき（[[0002-接続ごとのアクタースレッドと中止]]）は、`PQstatus` が同じ役目を果たせるか確かめること。
- `ConnectionPool` が `last_round_trip` を持つようになった。**進めるのは `見張る` が成功したときだけ**である。往復しない経路から進めないこと。
- `ConnectionPool::probe()` は `見張る` を通さない。往復しないため通してはならない（通すと時刻が進んで嘘になる）。
- `connection_health` コマンドが加わった。**このコマンドはデータベースへ往復しない。**往復する処理をここへ足さないこと。
- `pool.release` と `pool.cancel` が `見張る` を通るようになった。プールへメソッドを足すときの決まりは ADR 0026 のままである。
- `src/connection/lost.ts` に `reportConnectionLost` が加わった。例外を経由しない断の入口である。**2 度目を数えないのは受け手の仕事**であり、ここは届いた事実をそのまま配る。
- 接続の様子を覗くのは `useConnectionHealth` であり、ステータスバーが呼ぶ。**ステータスバーは常に描かれている**ため、覗きが止まる場面が無い。描画の条件を足すときは、覗きも一緒に止まることに気を付けること。
- `connect` / `reconnect` / `disconnect` のどれも、古い接続の後片付けを待たなくなった。**待つ形へ戻さないこと。**切れている相手のログオフは往復を試みる。
