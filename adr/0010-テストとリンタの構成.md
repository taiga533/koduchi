# ADR 0010: テストとリンタの構成

- ステータス: 承認
- 日付: 2026-08-30

## 状況

プロジェクトの方針として「すべての実装にテストを記述する」「mock の利用は最小限に留める」が定められている。一方、リポジトリは `create-tauri-app` のテンプレート状態でリンタもテストランナーも導入されていない。

Oracle を先に実装するため、統合テストには実際の Oracle が必要になる。`gvenzl/oracle-free` イメージは利用可能だが、起動に数十秒から数分かかる。

## 決定

### Rust

- `docker-compose.yml` に `gvenzl/oracle-free:23.9-slim`（バージョン固定）と初期スキーマ投入 SQL を用意する。コンテナは `docker compose up -d` で開発者が手動起動する。
- 統合テストは環境変数 `KODUCHI_TEST_ORACLE_URL` が設定されているときだけ実行し、未設定ならスキップして緑にする。Docker が動いていない環境でも `cargo test` が通る。
- 純ロジックは Docker 不要の単体テストにする。対象は SQL 文の分割、`tnsnames.ora` パーサ（[[0006-tnsnames解決を自前パースで行う]]）、データベース値から表示文字列への変換、CSV の書き出し。
- 整形とリントは `cargo fmt` と `cargo clippy`。

### フロントエンド

- `vitest` + `@testing-library/react` + `jsdom`。
- `src/api/` 層（Tauri の `invoke` ラッパ）を差し替えることで、zustand ストアとコンポーネントのテストをデータベースから切り離す。ストアが直接 `invoke` を呼ばないのはこのためである。
- リンタは `oxlint`、フォーマッタは `Prettier`。

### 共通

- 依存関係はすべてバージョンを指定してインストールする。
- テストは Arrange - Act - Assert の順で書き、テストケース名は日本語で「何をテストしているか」を明示する。
- `CLAUDE.md` の「リンタ・テストランナーは未導入」という記述を更新する。

## 理由

- CI の無い個人プロジェクトでは、コンテナの寿命を開発者が握れるほうが反復が速い。テストのたびに Oracle が起動するのは待ち時間が支配的になる。
- 環境変数によるゲートにより、Docker の有無で `cargo test` の結果が割れない。
- ロジックの大半（文の分割、パース、型変換、CSV）は純粋関数として書けるため、mock を使わずに厚くテストできる。これは「mock を最小限に」という方針とそのまま噛み合う。
- `src/api/` を境界に置くことで、フロントエンドのテストでも mock ではなく実装の差し替えで済む。
- `oxlint` はリンタ専用でフォーマッタを持たない（`oxfmt` は実験段階）ため、整形は実績のある Prettier に任せる。

## 却下した案

**`testcontainers` crate で `gvenzl/oracle-free` を毎回起動する**: 技術的には可能だが、テストごとのコンテナ起動が重い。

**`testcontainers` でコンテナを全テストで 1 回だけ共有する（`OnceLock`）**: 起動回数は減るが、Docker が無い環境で `cargo test` が失敗する問題は残る。

**Rust 側は純ロジックの単体テストのみとし、実データベースのテストは手動確認にする**: ドライバ層の回帰を検出できない。

**モックでドライバ層を差し替える**: 「mock は最小限」という方針に反し、ODPI-C の実挙動（`NUMBER` の精度、`break_execution` のタイミング）を検証できない。

**`Biome` を使う**: リンタとフォーマッタが 1 つに収まる利点はあるが、`oxlint` を使う方針が決まっている。

**`oxlint` + `oxfmt`**: `oxfmt` はまだ実験段階である。

## 結果

- 統合テストを走らせるには、開発者が `docker compose up -d` を実行し `KODUCHI_TEST_ORACLE_URL` を設定する必要がある。この手順は README に記載する。
- Oracle Free コンテナの初回起動は数分かかる。2 回目以降はボリュームを再利用する。
- `oxlint` と `Prettier` の責務が重ならないよう、Prettier 側で整形に関するルールを持たせ、`oxlint` は整形系ルールを無効にする。
