# ADR 0031: オーバーレイの `esc` と document のスクロール

- ステータス: 承認
- 日付: 2026-09-11

## 状況

見た目の不具合が 2 件挙がった（issue #36・#37）。どちらも「触っていると気持ちが悪い」類だが、原因は別の場所にあり、どちらも**同じ穴を次の人がもう一度開けられる形**で残っている。1 本の ADR にまとめるのは、2 件がともに「アプリの器の決めごとが 1 箇所に無い」ことに帰着するためである。

### issue #36 — コマンドパレットが `esc` で閉じないことがある

> コマンドパレットが最前面に来てるときに、画面上のいずれの要素にもフォーカスが当たってない状態で ESC を押してもコマンドパレットを閉じれない

`CommandPalette` は `esc` を**器の `onKeyDown`** で受けていた。React の合成 event は DOM の伝播に乗るため、焦点が器の中にあるあいだしか届かない。

焦点が抜ける道は塞いだつもりでも残る。実際に起きているのはこれである。

1. パレットの暗幕（`absolute inset-0` の `div`）を押す。
2. `div` は焦点を持てないため、押し下げで入力欄の焦点が外れ、`document.activeElement` が `<body>` に戻る。
3. 暗幕には「押したら閉じる」も無いため、パレットは開いたまま残る。
4. 以後 `esc` も `↑` `↓` も `⏎` も届かない。**閉じる道が無くなる。**

同じ形のオーバーレイを数え上げたところ、`esc` の扱いは 3 通りに割れていた。

| 受け方 | 部品 | 焦点が外れたとき |
| --- | --- | --- |
| 器の `onKeyDown` | `CommandPalette` / `BindValuesDialog` / `SaveQueryDialog` | **閉じない** |
| `window` の `keydown` を自前で張る | `SessionsPanel` / `SourceSearchPanel` / `CellDetailPanel` | 閉じる |
| 何も無い | `SettingsPanel` / `CsvSaveDialog` / `DisconnectBlockedDialog` / `SchemaTreeContextMenu` / `ResultContextMenu` | **そもそも `esc` が効かない** |

2 番目の作り（`window` に自前で張る）にも別の穴がある。**開いているオーバーレイ全部に同じ 1 打鍵が届く。**セルの詳細パネルの上にコマンドパレットが重なっているとき、`esc` 1 回で両方が消えるのは「1 つ戻る」ではない。

### issue #37 — スクロールすると下部に謎の余白が出る

> 画面をスクロールすると下部に謎の余白が出る
> 上にスクロールすると画面が下に降りようとする挙動もする

まず**どの要素がスクロールしているのか**を測った。`bun run dev` を立て、開発者ツールから各段の高さを読んだ（1100 × 700 の窓）。

| 要素 | `clientHeight` | `scrollHeight` | `overflow-y` | `overscroll-behavior-y` |
| --- | --- | --- | --- | --- |
| `html` | 700 | 700 | `visible` | `auto` |
| `body` | 700 | 700 | `visible` | `auto` |
| `#root` | 700 | 700 | `visible` | `auto` |
| `Shell` の器 | 700 | 700 | `visible` | `auto` |

**`scrollHeight` と `clientHeight` が等しい。はみ出しは 0px である。**`window.innerHeight` も 700 で一致する。900 × 320 まで縮めて本体が溢れる状態を作っても `documentElement.scrollHeight` は 320 のままであり、溢れは `CenteredPanel` の `overflow-auto` が引き受けていた。**つまり「謎の余白」は部品の寸法ではない。**タイトルバーの 42px でもステータスバーの 26px でも、`100vh` と実際の窓の高さの差でもない（`100vh` は src のどこにも使っていない）。

残るのは 1 つで、WKWebView が主フレームを弾ませる**ラバーバンド**である。「上にスクロールすると画面が下に降りようとする」はその弾みそのものであり、下端で弾めば地の色（`--bg`）の帯が現れる。これが「下部の謎の余白」である。**その高さは指の勢いで決まり、定数では説明できない。**器の中のスクロール（結果テーブル・スキーマツリー）が端に達したところから document へ伝播するため、「スクロールすると出る」という現れ方になる。

`html` / `body` はどちらも `overflow: visible` のままで、`overscroll-behavior` は既定の `auto` であった。**デスクトップアプリで document がスクロールできる状態になっているのは、それ自体が誤りである。**

## 決定

### 1. `esc` は器ではなく `window` で受け、受け手を積みで 1 つに絞る

**オーバーレイの器に `onKeyDown` を付けない。**`src/input/useEscapeKey.ts` の `useEscapeKey(onClose)` 1 つを通す。

- 打鍵は `window` の `keydown` で受ける。焦点が `<body>` に戻っていても届く。これが**閉じる道の保証**である。
- 受け手は `src/input/escapeStack.ts` の積みに入れ、**いちばん後に開いたものだけ**を走らせる。重なったオーバーレイが 1 打鍵でまとめて消えない。
- `window` の listener は受け手が 1 つ以上あるあいだだけ張る。

見る順は 3 つで、どれも飛ばさない。

1. **`event.defaultPrevented`** — より近い所（入力欄・CodeMirror・結果テーブルの検索欄）が既に処理した `esc` は二重に扱わない。`App.tsx` の `keydown` と同じ作法である。
2. **`isComposingKey`**（[[0025-入力欄における変換中の打鍵]]） — 変換中の `esc` は変換の取り消しであって「閉じる」ではない。`window` で受ける以上、この関所はここにも要る。
3. **積みの末尾** — 手前の 1 つだけが閉じる。

渡された関数は描画のたびに別物になりうるが、**積みに入る受け手の同一性は `useRef` で保つ。**描画のたびに積み直すと、後ろに居たはずのオーバーレイが手前へ繰り上がってしまう。

**上の表に挙げた 11 個すべてをこの 1 つへ寄せた。**`esc` を持っていなかった 5 個（設定・CSV 保存・切断できない知らせ・ツリーの右クリックメニュー・結果の右クリックメニュー）にも付く。オーバーレイを足す人が `useEscapeKey` を呼べば済み、`window` に自分で張る形はもう要らない。

`SessionsPanel` と `SourceSearchPanel` の「まず中の状態だけを解き、次に閉じる」2 段の動きはそのまま残す（渡す関数の中で分岐する）。

#### 焦点が抜ける道そのものも塞ぐ（ただし保証にはしない）

`CommandPalette` の暗幕は、自分自身が押されたときだけ `mousedown` の既定動作を止める。押しても入力欄の焦点が外れないため、`↑` `↓` `⏎` も効いたままになる。**これは原因の側の手当てであって、閉じる道の保証ではない。**焦点が抜ける道は塞いだつもりでも残る（メニューの外を押す、ネイティブのダイアログから戻る、ウィンドウの外から戻る）。だから保証は `useEscapeKey` が別に持つ。

#### 退けた案

- **焦点の罠を張る（外れたら入力欄へ引き戻す）。** 引き戻す先が 1 つに決まらない。`SessionsPanel` のように入力欄が複数ある部品では、利用者が選んだ欄を奪い返すことになる。`CellDetailPanel` のように「焦点を奪わないこと」が持ち味の部品もある。
- **器に `tabIndex={-1}` を持たせて器で拾う。** 器自身に焦点を当てる誰かが要る。当て損ねればまた同じ穴であり、`autoFocus` の付いた入力欄と焦点を取り合う。
- **`App.tsx` に `esc` の枝を 1 本足す。** どのオーバーレイが開いているかを `App.tsx` が全部知ることになる。オーバーレイを足すたびに `App.tsx` へ 1 行足す形は、まさに今 3 通りに割れた原因である。

### 2. document はスクロールさせない

`src/app.css` の `html` と `body` に 2 つ足す。

```css
html,
body {
  overflow: hidden;
  overscroll-behavior: none;
}
```

- **`overscroll-behavior: none`** が弾み（ラバーバンド）を止め、器の中から document へのスクロールの伝播も断つ。**器の中のスクロールそのものには影響しない。**仮想スクロール（結果テーブル・スキーマツリー）はそれぞれの器が持つスクロールであり、この宣言はビューポートにしか効かない。
- **`overflow: hidden`** は、将来どこかが溢れても document をスクロールさせない。溢れを引き受けるのは常にその場の器である。

**`html` と `body` の両方へ書く。**ビューポートのスクロールの持ち主は実装によって `html` にも `body` にもなる。

高さの出どころは既にある `height: 100%` の連なり 1 本のままにし、**`100vh` にも `100dvh` にも替えない。**測ったとおり `height: 100%` の連なりはウィンドウの高さとぴったり一致しており（700 = 700 = 700）、替える理由が無い。`100vh` は macOS のウィンドウの実際の高さと必ずしも一致せず、差がそのままはみ出しになる。

[[0009-ウィンドウモデルとタイトルバー]] の `trafficLightPosition` と `src/components/titlebar/geometry.ts` には**手を触れていない。**余白はタイトルバーの寸法とは無関係であった。

## 帰結

- オーバーレイを足す人は `useEscapeKey(onClose)` を呼ぶだけでよい。**`window` に自分で `keydown` を張らない。器に `onKeyDown` を付けない。**
- `esc` が効くオーバーレイが 6 個から 11 個へ増えた。設定画面と CSV 保存ダイアログと 2 つの右クリックメニューは、これまで `esc` で閉じられなかった。
- 重なったオーバーレイは 1 打鍵で 1 つずつ閉じる。これまでは `window` に張っていた 3 つが同時に消えていた。
- document は二度とスクロールしない。仮想スクロールは器の中のままである。
- **確かめ方。** `esc` の側は jsdom で確かめられる（焦点を `<body>` へ落として `window` へ `esc` を送る）。document のスクロールの側は jsdom がレイアウトを持たないため確かめられないので、**実機で測った**うえで、決めた宣言が消えていないことを `src/app.css.test.ts` が見張る。読み取りは `src/theme/cssRules.ts` の純粋な関数である。
