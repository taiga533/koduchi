## ADR に切り出していない決定

単独で覆す対象になりにくい、あるいは他の ADR に従属する決定をここにまとめる。

### 機能スコープ

|        | 内容                                                                                                      |
| ------ | --------------------------------------------------------------------------------------------------------- |
| 作る   | SQL 実行 / シンタックスハイライト / 結果テーブル / 実行計画 / クエリ履歴 / スキーマツリー / CSV 保存      |
| 器だけ | 保存済みクエリ（空状態を表示）・`⌘K` コマンドパレット（表示のみ操作不可）・テーブル定義ビュー（開かない） |
| 対象外 | Ask AI / SSH トンネル / エラーの候補提示「近い名前・修正して再実行」                                      |
| 順序   | Oracle を先に全機能。PostgreSQL は `tokio-postgres` で Driver trait の別実装として後から追加              |

エラー表示はメッセージタブのテキストのみとする。デザイン状態 5b の波線・行番号の赤ドット・候補提示・「修正して再実行」ボタンは実装しない。

### SQL の実行単位

`⌘⏎` はカーソル位置の文、`⇧⌘⏎` は選択範囲を実行する。文の切り出しは、文字列リテラル・コメント・Oracle の `q'[...]'` 引用符リテラル・`BEGIN…END;` ブロックを考慮した自前パーサで行う。デザインのメニュー 2 項目がそのままこの意味になる。

### 値の受け渡し

各セルは `{ text: string, kind: "number"|"text"|"datetime"|"bool"|"binary"|"null" }` として送る。

- Oracle の `NUMBER` は最大 38 桁の 10 進数であり、`f64` に入れると精度が壊れる。**文字列のまま保持する。**
- `kind` は結果テーブルの右寄せ判定に使う。
- `CLOB` は先頭 64KB まで、`BLOB` / `RAW` は `[BLOB 1.2 KB]` と表示する。
- `NULL` は `--fg5` の淡色・斜体で `NULL` と表示し、空文字列と区別する（デザインに指定が無いための追加）。

### 実行計画

- `⌘E` = `EXPLAIN PLAN FOR <sql>` → `DBMS_XPLAN.DISPLAY`（実行しない見積り）
- `⇧⌘E` = SQL に `/*+ GATHER_PLAN_STATISTICS */` を注入して実際に実行 → `DBMS_XPLAN.DISPLAY_CURSOR(format => 'ALLSTATS LAST')`（E-Rows と A-Rows の乖離が見える）

`⇧⌘E` は SQL を書き換えて実行するため、`SELECT` 以外に対しては事前に確認ダイアログを出す。計画の表示はテキストのままで、ツリー UI へのパースは行わない（`DBMS_XPLAN` の出力は既に整形済みである）。

### メッセージタブ

実行ログを時系列で追記する。実行時刻・SQL 全文・所要時間・影響行数に加え、データベースからの通知（Oracle は `DBMS_OUTPUT.GET_LINES`、PostgreSQL は `NOTICE`）を出す。`DBMS_OUTPUT` が無いと無名 PL/SQL ブロックを実行しても何も見えない。

### エディタとタブ

- CodeMirror 6 + `@codemirror/lang-sql`。接続種別で方言を切り替え、取得済みスキーマ（[0007](0007-スキーマ取得の段階的ロード.md)）を渡してテーブル名・列名の補完を効かせる。
- タブは `.sql` ファイルの開く/保存に対応する。未保存バッファも SQLite に保存し、再起動でタブ構成ごと復元する。新規タブ名は `無題-1.sql`。

### 結果テーブル

TanStack Virtual による仮想スクロール。スクロールが下端に近づくたびに 1,000 行ずつ追加取得する（[0003](0003-結果セットのカーソル保持と接続プール.md)）。

### CSV の書式

保存ダイアログで次を選ばせ、選択内容は次回のために保存する。

- 区切り文字: **カンマ**（既定） / タブ / セミコロン
- 文字コード: **UTF-8 (BOM 付き)**（既定、Excel 対策） / UTF-8 (BOM なし) / Shift_JIS
- NULL の表現: **空欄**（既定） / `NULL` / `\N`

固定: ヘッダー行あり、`"` 囲みの RFC 4180 エスケープ、改行は CRLF。

### キーバインド

| キー        | 動作                             |
| ----------- | -------------------------------- |
| `⌘⏎`        | 実行（カーソル位置の文）         |
| `⇧⌘⏎`       | 選択範囲のみ実行                 |
| `⌘E`        | 実行計画を生成                   |
| `⇧⌘E`       | 実測付きで生成                   |
| `⌥⌘S`       | 結果を CSV で保存                |
| `⌘.`        | 実行を中止                       |
| `⌘S` / `⌘O` | 保存 / 開く                      |
| `⌘T` / `⌘W` | 新しいタブ / タブを閉じる        |
| `⌃⌘N`       | 別の接続を新しいウィンドウで開く |

`⌘K`（コマンドパレット）と `⌘I`（Ask AI）は**割り当てない**。将来のために予約する。

### 設定画面（ステータスバー右の ⚙︎）

テーマ 3 択 / Oracle Instant Client のパス（未検出時のみ表示）/ 履歴の一括削除 / 罫線の有無（`--gl`）/ 行の高さ（`--rp`）。

### 状態管理

zustand を機能別に 6 ストアへ分割する（`connection` / `tab` / `execution` / `history` / `schema` / `ui`）。ストアは Tauri の `invoke` を直接呼ばず、`src/api/` 層越しに呼ぶ。これによりストアの単体テストをデータベースから切り離せる（[0010](0010-テストとリンタの構成.md)）。

### ディレクトリ構成

```
src/
  api/            Tauri invoke のラッパ（テスト時に差し替える境界）
  stores/         zustand ストア6種
  components/
    titlebar/  sidebar/  editor/  results/  connection/  settings/
  theme/          CSSトークン定義（:root / [data-theme="dark"]）
  types/          Rust と共有する型定義
src-tauri/src/
  lib.rs          commands 登録のみ
  commands/       Tauri コマンド（薄い層）
  db/
    driver.rs     Driver trait
    oracle/       接続・実行・スキーマ取得・実行計画・DBMS_OUTPUT
    actor.rs      接続ごとのスレッドとチャネル
  tnsnames/       tnsnames.ora パーサ
  config/         connections.toml の読み書き
  keychain/       keyring ラッパ
  history/        SQLite（履歴・タブ復元）
  csv/            CSV 書き出し
```

## デザインからの意図的な変更

出典は Claude Design プロジェクト <https://claude.ai/design/p/11b6f2ab-681b-437c-a5f0-1ddf7e59fbbe?file=DB+Client.dc.html> の `DB Client.dc.html`（3a が本体レイアウト、5a〜5g が状態パターン）。同梱の `support.js` はキャンバスの実行時ランタイムであり、アプリ実装とは無関係。

1. **実行計画タブを追加** — デザインにメニュー項目（`⌘E` / `⇧⌘E`）はあるが表示先が無かった。
2. **NULL の表示を定義** — デザインに指定が無かった。
3. **接続フォームに方式セグメントを追加** — TNS 対応のため（[0006](0006-tnsnames解決を自前パースで行う.md)）。
4. **結果ペインのタブを動的に** — 固定 3 タブ（結果 / メッセージ / 履歴）から、履歴をサイドバーへ移し、必要時のみ出現する方式へ（[0005](0005-クエリ履歴とセッション復元のsqlite.md)、[0009](0009-ウィンドウモデルとタイトルバー.md)）。
