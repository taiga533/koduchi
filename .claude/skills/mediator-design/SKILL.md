# 仲介者と関所で設計する

小槌の動きは 3 つの持ち場に分ける。

| 持ち場 | 担うこと                                                                 | 置き場所                                                                                                                                                                                              |
| ------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 部品   | 描く。利用者の意図を `on〇〇` の callback で上へ**報告**する             | `src/components/`                                                                                                                                                                                     |
| 仲介者 | 報告を受け、どのストアへ何をどの順で配るかを**裁定**する                 | `src/mediator/`（`tabs.ts` の `closeTabAndRelease` / `transaction.ts` の `resolvePendingTransaction` / `connection.ts` の `disconnectAndReset` と接続断の配り）。`App.tsx` は配線するだけ（ADR 0035） |
| ストア | 自分の段階と遷移を持ち、今の段階で起こせない遷移を自分で拒む（**関所**） | `src/stores/`。遷移表は `docs/state/*.d2`                                                                                                                                                             |

ストアを**読む**のは部品のどこからでもよい。持ち場の線を引くのは**書き**である。

## 手順

### 1. 報告の行き先を決める

足す操作ごとに、書き換えるストアを数える。

- **1 つ**なら、部品がそのストアの action を直に呼んでよい（例: `SchemaReloadButton` → `schema`）。
- **2 つ以上**なら仲介者を通す。部品は callback を受け取って報告するだけにし、順序と後片付けは仲介者の関数 1 つに書く。ストアの中から別のストアを呼ぶ形は取らない（ADR README「後片付けは仲介者が順に呼ぶ」）。
- 同じ裁定に入口が 2 つ以上ある（ボタンとキーとコマンドパレットなど）なら、どれも同じ仲介者の関数を通す。`✕` と `⌘W` が `closeTabAndRelease` 1 つを通るのが手本である。ウィンドウ全体のキーとパレットの項目は `src/mediator/commands.ts` のコマンドの表に 1 行で足す（片方にだけ足さない）。

完了の目安: 足す操作すべてについて「報告する部品・裁定する関数・書き換えるストア」の 3 つ組が言える。

### 2. 関所をストアに置く

段階を持つストアでは、どの段階でどの action を受け付けるかをストア自身が判定する。ボタンを隠す・押せなくするのは見た目の手当てであり、関所はその下にもう 1 枚ストアに置く。

`await` を挟む action は、待ちの後で**自分がまだ有効か**を確かめてから書き戻す。確かめる材料は、その試行の識別子が今も最新か、書き戻す先の項目がまだあるか、のどちらかである。無効になっていたら書き戻さず、待ちの間に作った資源（Rust 側のプールなど）を手放す。

完了の目安: 各 action について「どの段階で受け付け、どの段階で拒むか」と「待ちの後に何を確かめるか」がテスト名になっている。

### 3. 遷移表を直す

段階や遷移を足す・変えたら `docs/state/` の D2 を同じ変更で直す。1 本の矢印に 1 つのテストを対応させ、拒む遷移もテストに書く。描画の確認は `d2 fmt --check` と `d2 <file> <out>.png`（mise で入れた `d2` は PATH に無いことがある。`mise which d2` で引く）。

完了の目安: D2 の矢印とストアのテストが 1 対 1 で対応し、赤の破線（`class: unguarded`）が残っていない。

### 4. 仲介者を書く

裁定は `src/mediator/` に、React に依存しない普通の関数として書く（ADR 0035）。`App.tsx` の `useCallback` の中に書かない。

- **ファイルは裁定の領域で選ぶ**（接続の一生は `connection.ts`、実行は `execution.ts`、タブは `tabs.ts` など）。画面の部品や描画の単位では分けない。どこにも当てはまらない領域なら、ファイルを 1 つ足す。
- 部品は `src/mediator/` の値を import しない（型は許す）。部品は callback で報告し、`App.tsx` がそれを仲介者の関数へ繋ぐ。
- ストアは `useXStore.getState()` で直に触ってよい。**画面にしか無いもの**（エディタのカーソルやハンドル、確認の尋ね方）は引数で受け取る。`SqlEditorHandle` も React の state も import しない。
- **利用者に尋ねるときは答えを `await` する。**画面の中に描く確認は `ask.ts` の `AskRequest` に種類を 1 つ足し、`App.tsx` で受け渡し口（`createAskChannel`）から描く。表示フラグを `App.tsx` の state に足さない。ネイティブのダイアログは `src/api/dialog.ts` 越しに呼ぶ。
- 単体テストは `App` を描かずに書く。`src/test/activeConnection.ts` で接続済みにし、`src/api/` 層を差し替える。`App.test.tsx` には配線を確かめるテストだけを足す。

完了の目安: 足した裁定が `src/mediator/` の関数 1 つにあり、`App.tsx` の差分が配線だけで、その関数の単体テストがある。

## 仲介者を通さないもの

次のどれかに当たる状態は、持ち主の部品の中に閉じたままにする。

- **打鍵やポインタの動きの頻度で変わる。**上へ報告すると、そのたびにアプリ全体が描き直る。
- **寿命が 1 つの部品と同じ。**部品が消えたら一緒に捨ててよく、他の持ち場が知る必要が無い。
- **外から持ち込んだ部品が自分で持っている。**エディタの中身のように、受け身の描画に作り替えられない。

判断の中身そのもの（並べ替えの位置、範囲の判定など）は純粋な関数に寄せ、部品・仲介者・ストアのどこからでもそれを呼ぶ。
