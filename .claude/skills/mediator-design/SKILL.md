# 仲介者と関所で設計する

小槌の動きは 3 つの持ち場に分ける。

| 持ち場 | 担うこと                                                                 | 置き場所                                                                                              |
| ------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 部品   | 描く。利用者の意図を `on〇〇` の callback で上へ**報告**する             | `src/components/`                                                                                     |
| 仲介者 | 報告を受け、どのストアへ何をどの順で配るかを**裁定**する                 | `App.tsx`（`closeTabAndRelease` / `resolvePendingTransaction` / `disconnectAndReset` / 接続断の配り） |
| ストア | 自分の段階と遷移を持ち、今の段階で起こせない遷移を自分で拒む（**関所**） | `src/stores/`。遷移表は `docs/state/*.d2`                                                             |

ストアを**読む**のは部品のどこからでもよい。持ち場の線を引くのは**書き**である。

## 手順

### 1. 報告の行き先を決める

足す操作ごとに、書き換えるストアを数える。

- **1 つ**なら、部品がそのストアの action を直に呼んでよい（例: `SchemaReloadButton` → `schema`）。
- **2 つ以上**なら仲介者を通す。部品は callback を受け取って報告するだけにし、順序と後片付けは仲介者の関数 1 つに書く。ストアの中から別のストアを呼ぶ形は取らない（ADR README「後片付けは `App.tsx` が順に呼ぶ」）。
- 同じ裁定に入口が 2 つ以上ある（ボタンとキーとコマンドパレットなど）なら、どれも同じ仲介者の関数を通す。`✕` と `⌘W` が `closeTabAndRelease` 1 つを通るのが手本である。

完了の目安: 足す操作すべてについて「報告する部品・裁定する関数・書き換えるストア」の 3 つ組が言える。

### 2. 関所をストアに置く

段階を持つストアでは、どの段階でどの action を受け付けるかをストア自身が判定する。ボタンを隠す・押せなくするのは見た目の手当てであり、関所はその下にもう 1 枚ストアに置く。

`await` を挟む action は、待ちの後で**自分がまだ有効か**を確かめてから書き戻す。確かめる材料は、その試行の識別子が今も最新か、書き戻す先の項目がまだあるか、のどちらかである。無効になっていたら書き戻さず、待ちの間に作った資源（Rust 側のプールなど）を手放す。

完了の目安: 各 action について「どの段階で受け付け、どの段階で拒むか」と「待ちの後に何を確かめるか」がテスト名になっている。

### 3. 遷移表を直す

段階や遷移を足す・変えたら `docs/state/` の D2 を同じ変更で直す。1 本の矢印に 1 つのテストを対応させ、拒む遷移もテストに書く。描画の確認は `d2 fmt --check` と `d2 <file> <out>.png`（mise で入れた `d2` は PATH に無いことがある。`mise which d2` で引く）。

完了の目安: D2 の矢印とストアのテストが 1 対 1 で対応し、赤の破線（`class: unguarded`）が残っていない。

### 4. 仲介者の肥大を見る

`App.tsx` は既に長い。新しい裁定を足して描画のコードと同居させ続けるか、裁定の関数を別のモジュールへ切り出すかは未決である。切り出しが要りそうなら、置き場所を決める前に利用者へ確認する（CLAUDE.md「ADR で決まっていない判断は利用者に確認する」）。

## 仲介者を通さないもの

次のどれかに当たる状態は、持ち主の部品の中に閉じたままにする。

- **打鍵やポインタの動きの頻度で変わる。**上へ報告すると、そのたびにアプリ全体が描き直る。
- **寿命が 1 つの部品と同じ。**部品が消えたら一緒に捨ててよく、他の持ち場が知る必要が無い。
- **外から持ち込んだ部品が自分で持っている。**エディタの中身のように、受け身の描画に作り替えられない。

判断の中身そのもの（並べ替えの位置、範囲の判定など）は純粋な関数に寄せ、部品・仲介者・ストアのどこからでもそれを呼ぶ。
